# 一木记账解析规则

> 本规则依据 `demo/data/一木记账` 中导出的 CSV 核对；XLSX 与 CSV 表头和业务行一致，解析语义相同。XLS 不是支持的输入格式，需先在一木记账中另存为 CSV 或 XLSX。

账单、转账、债务文件可以单独上传或任意组合上传。

## 1. 文件模板

### 1.1 账单文件

账单文件包含普通收入、普通支出、退款、报销垫付及一木自动生成的结果行。

- 核心字段：`日期`、`收支类型`、`金额`、`类别`、`二级分类`、`账户`、`退款`、`备注`、`报销账户`、`报销金额`、`报销明细`、`其他`。
- `日期` 是交易时间；来源提供 `入账时间` 时使用其作为入账时间，否则入账时间等于交易时间。
- `退款` 是同一支出上的退款金额。
- `报销明细` 按每行 `YYYY/MM/DD账户到账金额` 解析，按行顺序生成报销到账；最后一行是结束报销。
- `其他` 中的 `不计入收支`、`不计入预算` 分别映射为统计、预算排除标记。
- `账本`、`优惠`、`标签`、多币种、地址、创建用户、附件等字段，暂时忽略。

### 1.2 转账文件

转账文件包含资金账户之间的转账，以及对负债账户的还款。文件类型本身不携带该负债是信用、应付还是借款的画像。

- 核心字段：`日期`、`类型`、`转出账户`、`转入账户`、`金额`、`手续费`、`备注`。
- `类型=转账` 的手续费属于该转账；不得再导入账单中自动生成的“转账手续费”支出行。
- `类型=还款` 的手续费：正数是利息，负数是还款优惠，零或空表示无附加金额。

### 1.3 债务文件

债务文件包含普通应收、普通应付和借款性质负债的借出、收回、借入、还款及其期初余额。

- 核心字段：`日期`、`类型`、`转出账户`、`转入账户`、`金额`、`手续费`、`备注`。
- 虽然列名固定为“转出账户 / 转入账户”，对 `收款` 而言前者是实际收款的资金账户；必须按下文的业务类型解释，不能机械按列名推断资金流向。
- 债务文件没有“这是普通应付还是贷款”的画像字段；其负债账户新建默认是应付账户，已有映射可明确选择借款账户。

## 2. 名称映射与账户识别

### 2.1 SmartFlow 目标账户

来源账户映射到以下完整的“账户类型 + 子类型 + 账户画像”组合：

| 导入目标 | 账户类型 / 子类型 | 账户画像 |
| --- | --- | --- |
| 资金账户 | `asset / fund` | `ledger.fund` |
| 报销账户 | `asset / receivable` | `ledger.reimbursement` |
| 应收账户 | `asset / receivable` | `ledger.receivable` |
| 应付账户 | `liability / payable` | `ledger.payable` |
| 信用账户 | `liability / payable` | `credit.credit` |
| 借款账户 | `liability / loan` | `credit.loan` |

账户画像用于导入审阅和建户入口，账务角色由账户类型和子类型决定。报销账户与普通应收账户共享 `asset / receivable`，但不能互相替代；应付账户与信用账户共享 `liability / payable`，也不能因为子类型相同而互相替代。

### 2.2 来源账户键与约束合并

- 对非空且非 `无账户` 的账户名，按规范化后的名称创建同一个来源账户实体；同名在账单、转账、债务三类文件中只映射一次。
- 每次出现为该实体附加“允许的目标画像”约束。彼此不兼容的强约束形成阻塞冲突，不能静默新建错误类型账户。
- 已有来源映射或名称完全匹配只有同时满足全部角色和画像约束时才可自动采用；不做模糊名称匹配。用户可在审阅中选择另一个兼容目标或新建目标。
- 来源明确为 `无账户` 时不创建来源账户实体，也不保存来源映射。普通账单收支的无账户使用幽灵账户；债务期初按第 3.3 节处理，不使用幽灵账户。

### 2.3 账户角色识别矩阵

| 来源文件 | 业务类型 | 来源字段        | 允许/首选目标 | 新建默认 |
| --- | -- |-------------| --- | --- |
| 账单文件 | 普通收入、普通支出、退款。报销垫付付款方、报销到账方 | 账户、报销明细到账账户 | 结算账户；可为资金或非借款负债账户 | 资金账户 |
| 账单文件 | 报销垫付及其到账、结束报销 | 报销账户      | 仅报销账户 | 报销账户 |
| 转账文件 | 转账 | 转出、转入账户     | 仅资金账户 | 资金账户 |
| 转账文件 | 还款 | 转出账户 / 转入账户 | 资金账户 / 应付、信用或借款账户 | 资金账户 / 信用账户 |
| 债务文件 | 借出、收款 | 转出账户 / 转入账户 | 资金账户 / 仅应收账户 | 资金账户 / 应收账户 |
| 债务文件 | 借入、还款 | 转出账户 / 转入账户 | 资金账户 / 应付账户或借款账户 | 资金账户 / 应付账户 |

债务文件最后一行的“应付账户或借款账户”是刻意保留的兼容范围：一木债务导出没有足以自动判定 `payable` 与 `loan` 的信息。新建时选择应付账户；只有用户已有映射或在审阅中明确选择时才使用借款账户。转账文件的还款目标同样不能仅凭文件类型定型；为保持既有导入体验，新建默认信用账户，但已有应付/借款映射仍是兼容目标。

### 2.4 分类提取

- 账单收入从 `类别`、`二级分类` 提取收入分类；账单支出以同样方式提取支出分类。
- 有二级分类时使用完整路径 `一级 / 二级`，没有二级分类时使用一级。新建分类保留父子关系，公共父分类只创建一次，来源映射指向叶子；一级直接记账不是“未分类”。
- 转账和债务文件不提取用户分类。
- 结束报销金额大于原支出时，差额收入使用系统分类 `其他 / 报销差额收入`；小于原支出时，差额支出复用原垫付的支出分类。

## 3. 文件解析

以下示例均为脱敏的虚拟数据；

### 3.1 账单文件

1. **普通支出和退款**

   示例：`日期=2026-04-04 12:55，收支类型=支出，金额=-68.00，类别=餐饮，二级分类=生鲜，账户=资金账户A，退款=2.00`。

   解析结果：创建普通支出 `70.00`，并在同一交易组创建退款 `2.00`。`账户` 是结算账户，不因该行单独出现就假定为资金账户；若没有其它强角色，建户默认资金账户。

2. **普通收入**

   示例：`日期=2026-03-11 10:19，收支类型=收入，金额=1500.00，类别=收入，二级分类=工资，账户=资金账户A，备注=工资入账`。

   解析结果：创建一条普通收入，并保留收入分类、结算账户和备注。

3. **报销垫付与结束报销**

   示例：`收支类型=支出，金额=-18.00，类别=食品餐饮，二级分类=请客吃饭，账户=资金账户A，报销账户=报销账户A，报销金额=17.00，报销明细=2026/08/21资金账户B到账10.00\n2026/08/21资金账户B到账7.00`。

   解析结果：创建一条报销垫付；第一笔明细创建报销到账，最后一笔创建结束报销。报销账户必须映射为 `ledger.reimbursement`，付款和到账账户按结算账户处理。明细合计必须等于报销金额，否则该交易组阻塞。

4. **报销垫付含退款**

   示例：`收支类型=支出，金额=-18.00，类别=食品餐饮，二级分类=请客吃饭，账户=资金账户A，退款=2.00，报销账户=报销账户A，报销金额=17.00，报销明细=2026/08/21资金账户B到账10.00\n2026/08/21资金账户B到账7.00`。

   解析结果：创建报销垫付 `20.00`，并按顺序创建退款 `2.00`、报销到账 `10.00`、结束报销 `7.00`。退款与报销到账都核销该垫付产生的报销应收，报销明细合计仍必须等于报销金额 `17.00`。

5. **统计和预算标记**

   示例：`收支类型=支出，金额=-480.00，类别=居家生活，二级分类=房租，账户=资金账户A，其他=不计入预算`。

   解析结果：正常导入，并写入预算排除标记；`不计入收支、不计入预算` 同时写入两个标记。

6. **过滤：报销差额结果行**

   判定：备注以 `报销差额` 开头，例如 `报销差额`、`报销差额：说明文本`。

   解析结果：过滤。差额已由对应报销垫付的结束报销自动生成，单独导入会重复记账。

7. **过滤：还款利息和还款优惠结果行**

   判定：备注包含 `还款利息` 或 `还款优惠`。

   解析结果：过滤。它们分别由转账或债务文件的还款手续费正数、负数表达；不得与还款记录重复导入。

8. **过滤：转账手续费结果行**

   判定：账单支出备注符合一木自动生成的 `… 转账手续费` 文案，例如 `资金账户B 转账手续费`。

   解析结果：过滤。该行是一木为转账手续费自动生成的结果行，不单独导入为普通支出；不依赖资料包中是否同时上传了对应转账文件。

### 3.2 转账文件

1. **普通转账**

   示例：`日期=2026-03-03 21:43，类型=转账，转出账户=资金账户A，转入账户=资金账户B，金额=200.00，手续费=3.00`。

   解析结果：创建一条转账，转账金额 `200.00`、手续费 `3.00`；两个账户均只能映射为资金账户。

2. **还款（本资料包为信用账户）**

   示例：`日期=2026-08-21 20:16，类型=还款，转出账户=资金账户A，转入账户=信用账户A，金额=20.00，手续费=0.00`。

   解析结果：创建一条还款，本金 `20.00`。付款方是资金账户；目标是负债账户。本资料包的 `信用账户A` 已由建户事实和账单结算角色映射为 `liability / payable + credit.credit`。对其它来源名称，转账还款本身只约束为可还款负债，不能据此排除应付或借款账户。

3. **含利息、仅利息与优惠**

   - `金额=800.00，手续费=30.00`：创建还款，本金 `800.00`、利息 `30.00`。
   - `金额=0，手续费=120.00`：创建利息支出 `120.00`。
   - `金额=5020.33，手续费=-0.05`：创建还款，本金 `5020.33`、优惠 `0.05`，实际支付 `5020.28`。

### 3.3 债务文件

1. **借出（增加普通应收）**

   示例：`类型=借出，转出账户=资金账户A，转入账户=应收账户A，金额=50.00，手续费=0`。

   解析结果：创建借出：资金账户减少 `50.00`，普通应收账户增加 `50.00`。不得导入其可能生成的账单支出行。

2. **收款（收回普通应收）**

   示例：`类型=收款，转出账户=资金账户A，转入账户=应收账户A，金额=50.00，手续费=0`。

   解析结果：创建收回：资金账户增加 `50.00`，普通应收账户减少 `50.00`。尽管来源列名为“转出账户”，此处它是收款资金账户；不按列名反向建账。

3. **借入（增加普通应付或借款）**

   示例：`类型=借入，转出账户=资金账户A，转入账户=应付账户A，金额=30.00，手续费=0`。

   解析结果：创建借入：资金账户增加 `30.00`，应付账户增加 `30.00`。新建负债目标默认应付账户；已有映射明确为借款账户时可创建借款账户。不得导入其可能生成的 `收入 / 借入` 账单行。

4. **还款（减少普通应付或借款）**

   示例：`类型=还款，转出账户=资金账户B，转入账户=应付账户A，金额=50.00，手续费=0`。

   解析结果：创建还款，本金 `50.00`；付款方为资金账户，负债目标按第 2.3 节映射为应付账户或已明确的借款账户。手续费的利息/优惠规则与第 3.2 节相同。

5. **往来期初余额**

   示例：`类型=借出，转出账户=无账户，转入账户=应收账户A，金额=200.00`；`类型=借入，转出账户=无账户，转入账户=应付账户A，金额=100.00`。

   解析结果：分别创建应收账户、应付/借款账户的期初余额，另一侧记系统期初余额。`无账户` 或空的资金侧不是一笔新的借出/借入，也不映射到幽灵账户。只有 `借出`、`借入` 可以按此规则解释；收款、还款缺少资金账户是阻塞问题。

## 4. 校验与处理原则

- 金额必须为正数（账单支出可用负号表达）；退款、报销明细和手续费按其对应业务规则校验。
- 报销明细的日期、到账账户、金额任一缺失或无法解析时，该报销交易组阻塞；明细总额与报销金额不一致也阻塞。
- 普通账单收支中空账户或 `无账户` 可导入到幽灵账户；必须承担资金或往来角色的账户为空时阻塞，期初余额的明确例外见第 3.3 节。
- 过滤来源记录已被识别但不生成交易组，不是解析失败，也不计入用户跳过数量。
- 解析不通过账户名猜测类型，不根据导入数据库状态改变来源事实；账户映射、默认建户和最终账户兼容性在导入审阅/提交阶段处理。
