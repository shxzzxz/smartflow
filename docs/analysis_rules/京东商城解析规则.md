# 京东商城解析规则

> 样例文件：[京东商城交易流水(示例2025-01-01至2025-12-31).csv](<../../demo/data/京东/京东商城交易流水(示例2025-01-01至2025-12-31).csv>)
>
> 本规则依据该脱敏样例和京东商城交易流水 CSV 确定。样例保留原文件的前导说明区、分隔位置、表头位置和 11 列列顺序，只抽取覆盖不同解析场景的代表记录，并替换账号、时间、商户、交易说明、金额、支付方式、交易订单号、商家订单号和备注等敏感值。

本次规则范围是单个京东商城交易流水 CSV 文件。首版只把 `收/支` 为 `支出` 或 `收入` 的行解释为普通支出或普通收入；其他方向不推断为转账、退款、还款或投资交易。京东商城可与其他导入来源并存，但仍遵循“一个来源一个跨批次作用域”的导入域规则。

## 1. 文件模板

### 1.1 编码与结构

- 示例文件使用 UTF-8 BOM 和逗号分隔，遵循 CSV 引号规则。
- 文件带有前导说明区。示例中的数据表头位于第 22 行，前 21 行包含导出信息、汇总统计、特别提示和空行。
- 解析时通过必需表头定位交易区，不能假设表头固定在第 22 行。
- 表头为 11 列：`交易时间`、`商户名称`、`交易说明`、`金额`、`收/付款方式`、`交易状态`、`收/支`、`交易分类`、`交易订单号`、`商家订单号`、`备注`。
- 一个导入资料包只接受一个京东商城交易流水文件；文件名只作辅助识别，前导说明区中的账号、申请时间和汇总统计不参与交易解析、去重或映射。

### 1.2 核心字段

| 字段 | 必填 | 用途 |
| --- | --- | --- |
| `交易时间` | 是 | 交易发生时间；来源未提供独立入账时间，入账时间等于交易时间 |
| `商户名称` | 否 | 忽略，不写入备注、映射或去重身份 |
| `交易说明` | 否 | 去除首尾空白后写入交易备注；为空时不生成备注 |
| `金额` | 是 | 正数金额，单位为人民币元；方向不由金额正负决定 |
| `收/付款方式` | 否 | 来源结算账户；空值时使用幽灵账户 |
| `交易状态` | 否 | 不参与方向判断，也不写入交易备注 |
| `收/支` | 是 | 唯一的业务方向来源 |
| `交易分类` | 是 | 收入或支出的来源分类 |
| `交易订单号` | 否 | 与 `商家订单号` 共同组成来源操作键 |
| `商家订单号` | 否 | 与 `交易订单号` 共同组成来源操作键 |
| `备注` | 否 | 忽略；交易备注只取 `交易说明` |

### 1.3 忽略内容

- 前导说明区中的京东账号名、申请时间和导出统计不进入解析结果。
- `商户名称`、`交易状态` 和来源 `备注` 不写入交易备注，也不用于分类或业务方向判断。
- 交易订单号和商家订单号属于内部去重身份，不写入交易备注。
- 表头中无法识别的附加列忽略；缺少必需列时该文件不可用。

## 2. 导入判定

### 2.1 方向

去除首尾空白后，只按 `收/支` 判断：

- `支出`：生成普通支出候选；
- `收入`：生成普通收入候选；
- `不计收支`：过滤，不生成交易组；
- 空值或其它未知值：过滤并记录行级警告，不猜方向。

`交易状态`、`交易分类`、`交易说明`、金额正负和付款方式都不能覆盖这张方向判定表。样例中 `支出` 方向的 `交易成功`、`自动扣款成功`、`买入成功`，以及 `收入` 方向的 `交易成功`、`赎回成功`，都只产生当前方向对应的普通收入或普通支出。

京东流水中的投资理财买入和赎回、小金库转入转出、全额退款和个人资金互转，不会仅凭分类或状态自动转换成 SmartFlow 的转账、退款、还款或投资交易。方向为 `不计收支` 的行统一过滤；方向为 `支出` 或 `收入` 的行仍按普通收支导入。

### 2.2 金额与时间

- `金额` 按人民币元解析为两位小数，再转换为 SmartFlow `Money` 最小货币单位。
- 只有方向为 `支出` 或 `收入` 的行才解析金额。`不计收支` 行先按方向过滤，因此金额文本不作为候选金额校验。
- 候选方向金额为零时过滤并记录 `jd_amount_zero`；金额为负数或无法解析时使该交易组阻塞。
- 样例中的 `9.99(已全额退款)` 只出现在 `不计收支` 行，方向过滤后不会进入金额解析，也不视为格式错误。
- `交易时间` 使用 `yyyy-MM-dd HH:mm:ss` 本地时间语义，`occurredAt` 与 `postedAt` 相同。
- 来源没有币种列，不能据此表达多币种交易。

### 2.3 备注

交易备注只取 `交易说明`：

- 去除首尾空白后作为备注；
- 不添加 `商户名称`、`交易状态`、交易订单号或商家订单号；
- `交易说明` 为空时不生成备注；
- 用户可以在导入审阅中修改备注。

`交易分类` 只用于分类映射，不并入备注。

## 3. 名称映射

### 3.1 分类

- `收/支=支出` 时，把 `交易分类` 提取为支出分类；
- `收/支=收入` 时，把 `交易分类` 提取为收入分类；
- `交易分类` 去除首尾空白后保留完整原值。来源没有明确说明空格是层级分隔符，因此首版不按空格拆分或推断父子层级，每个完整值作为单层来源分类路径；
- 分类来源键必须同时包含方向，避免收入 `其他`、支出 `其他` 或不同方向的同名分类互相复用；
- 分类为空或无法规范化时，该交易组阻塞并生成缺失分类审阅项。

`投资理财`、`小金库` 等分类仍只是普通收入或支出分类，不用于改变业务行为。相同分类出现在不同方向时，分别形成收入分类和支出分类。

### 3.2 结算账户

`收/付款方式` 作为来源结算账户：

| 来源值特征 | 目标约束 | 新建默认 |
| --- | --- | --- |
| 包含 `京东小金库`、`余额`、`数字人民币` 或 `储蓄卡` | 资金账户 | 资金账户 |
| 其它非空银行账户名称 | 资金账户 | 资金账户 |
| 包含 `先享后付` | 应付账户 | 应付账户 |
| 其它非空未知方式 | 由用户确认 | 资金账户 |
| 空值 | 缺失结算账户，当前导入使用幽灵账户 | 不新建来源账户 |

账户名称会去除首尾空白；银行卡或钱包尾号属于来源账户身份，必须保留以区分同名账户。样例使用虚拟银行、虚拟尾号和虚拟数字人民币钱包，不包含真实账户信息。

`收/付款方式` 为空时不创建持久的来源账户实体或默认映射，交易组按缺失结算账户处理，并在当前导入中使用幽灵账户；不能根据商户、交易说明、交易分类或前导区账号猜测账户。

### 3.3 来源身份与去重

- `交易订单号` 不能单独作为来源操作键。原始样例共 123 行，交易订单号只有 110 个不同值，存在 13 组重复；
- 同时存在非空 `交易订单号` 和 `商家订单号` 时，两者去除首尾空白后组成复合 `sourceOperationKey`。原始样例的复合键在 123 行中全部唯一；
- 任一订单号为空时不伪造标识，也不使用行号或文件名替代；保留缺失操作键并记录警告，仅使用交易组指纹发现疑似重复；
- 交易组指纹包含方向、交易时间、金额、结算账户来源键、分类来源键和规范化备注，并带独立的指纹版本；不包含映射后的 SmartFlow 账户或分类 ID；
- 同一文件内重复的复合操作键由导入计划装配阶段判定为冲突，不能静默合并。

样例中有两条支出使用相同的交易订单号和不同的商家订单号，用于确认复合键不会把同一父订单下的两笔交易误判为重复。

## 4. 文件解析

以下示例均来自脱敏样例，不代表真实交易。

### 4.1 普通支出

示例：

```text
交易说明=虚构家居用品订单
金额=13.03
收/付款方式=示例银行储蓄卡(0001)
收/支=支出
交易分类=家居家装
交易状态=交易成功
```

解析结果：生成一条普通支出 `13.03`，付款账户为 `示例银行储蓄卡(0001)` 来源实体，支出分类为 `家居家装`，备注为 `虚构家居用品订单`。

### 4.2 普通收入

示例：

```text
交易说明=虚构小金库收益
金额=0.01
收/付款方式=京东小金库
收/支=收入
交易分类=小金库
交易状态=交易成功
```

解析结果：生成一条普通收入 `0.01`，收款账户为 `京东小金库`，收入分类为 `小金库`。该行不会因为分类是“小金库”而转换成内部转账。

### 4.3 状态不覆盖方向

示例：

```text
金额=32.22
收/支=支出
交易分类=投资理财
交易状态=买入成功
```

```text
金额=199.99
收/支=收入
交易分类=投资理财
交易状态=赎回成功
```

解析结果：分别生成普通支出和普通收入，分类路径分别为支出 `投资理财` 和收入 `投资理财`。`买入成功`、`赎回成功` 只作为来源状态保留在文件中，不改变普通收支行为。

### 4.4 不计收支

示例：

```text
金额=66.66
收/支=不计收支
交易分类=小金库
交易状态=转出到账
```

解析结果：过滤，不生成候选交易组。虽然金额非零且分类为 `小金库`，方向列明确表示该行不计入收支，因此不能从分类或状态推断为收入。

### 4.5 全额退款后缀

示例：

```text
金额=9.99(已全额退款)
收/支=不计收支
交易分类=其他
交易状态=交易成功
```

解析结果：按方向过滤，不生成候选交易组；不尝试从带后缀的金额文本推断原支出或退款收入。

### 4.6 同一交易订单号的多笔交易

示例：

```text
交易订单号=JD-TXN-2025-0036
商家订单号=JD-MERCHANT-2025-0036
```

```text
交易订单号=JD-TXN-2025-0036
商家订单号=JD-MERCHANT-2025-0037
```

解析结果：两条记录保留为不同交易组，复合来源操作键不同。

## 5. 校验与处理原则

- 解码失败、找不到完整表头或没有任何数据行属于文件问题。
- 对方向为 `支出` 或 `收入` 的候选行，`交易时间`、`金额`、`交易分类` 缺失或无法解析时使该交易组阻塞；`交易说明` 为空时仍可形成无备注交易。
- `收/支=不计收支` 是过滤记录，不是解析失败，也不计入用户主动跳过数。
- `收/支` 为空或未知时过滤并记录警告，不根据交易状态、分类或金额反推方向。
- 候选金额为零时作为过滤记录处理；候选金额为负数或无法解析时阻塞。
- `收/付款方式` 为空时按缺失结算账户处理并使用幽灵账户。
- 所有过滤后没有候选交易组时不创建空批次。
- 解析器只解释来源事实，不读取数据库、来源映射或账务历史，也不直接构造账务命令。

## 6. 脱敏样例覆盖

[京东商城交易流水(示例2025-01-01至2025-12-31).csv](<../../demo/data/京东/京东商城交易流水(示例2025-01-01至2025-12-31).csv>) 保留原始文件前 21 行说明区、第 22 行表头和 11 列列顺序，并保存为 UTF-8 BOM。数据区按 `收/支 + 交易分类 + 交易状态 + 收/付款方式` 分组抽取代表记录，共 44 条虚构记录。

按本规则应得到 30 个候选交易组和 14 条过滤记录：

| 规则 | 对应样例场景 |
| --- | --- |
| 方向判定 | 27 条普通支出、3 条普通收入、14 条 `不计收支` |
| 分类提取 | 覆盖样例中的全部 20 个交易分类值，包括多段空格文本和跨方向同名分类 |
| 交易状态 | 覆盖 `交易成功`、`自动扣款成功`、`买入成功`、`转出到账`、`赎回成功` |
| 结算账户映射 | 覆盖候选行中的京东小金库、余额、银行储蓄卡、普通银行名称和数字人民币钱包；原始样例中的先享后付均出现在过滤行，其应付账户映射由解析器测试保护 |
| 金额文本 | 覆盖两位小数金额、零金额、正数金额和带 `(已全额退款)` 后缀的过滤金额 |
| 来源身份 | 覆盖复合交易订单号与商家订单号，并包含同一交易订单号配两个商家订单号的记录 |
| 文件结构 | 保留前导说明区、空行、第 22 行表头、11 列以及 UTF-8 BOM |

样例中的账号、商户、交易说明、时间、金额、支付方式、订单号和备注均为虚构值，不保留可识别的真实个人、交易或账户信息。
