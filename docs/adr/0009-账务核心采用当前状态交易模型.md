# 账务核心采用当前状态交易模型

SmartFlow 的交易表达当前有效业务事实，修改交易直接以新事实取代原事实，删除直接移除交易及其交易分项和分录，不维护冲销、补偿或交易历史版本。个人财务场景对历史审计链的收益不足以抵消版本聚合、父子迁移、查询折叠和状态校验的复杂度；交易修改与受影响子交易的修改必须作为同一账务操作保持原子性。

## Considered Options

- 冲销旧版本并追加正确版本：拒绝，因为它要求长期维护更正链、补偿记录、当前版本折叠和父子版本关系。
- 软删除交易：拒绝，因为当前产品不要求恢复已删除交易或保留删除审计记录。

## Consequences

- 交易、交易分项与分录是可修改的当前状态；修改交易不产生额外交易记录。
- 交易修改保持原交易身份不变，只有新的业务事件才创建新的交易身份。
- 不保留 `root_transaction_id`；交易组由稳定的顶层交易身份和 `parent_transaction_id` 表达，且只支持一层父子关系。
- 删除顶层交易时直接删除整个交易组，删除子交易时只删除该子交易；交易分项和分录随交易删除，并同步修正受影响账户余额。
- 父交易修改若影响子交易的业务合法性或账务表达，必须在写入前拒绝，或在同一事务中同步修改受影响子交易。
- 父交易修改后若无法继续容纳已有退款、报销到账等子交易，必须拒绝修改；系统不隐式缩减、删除或重新分配子交易金额。
- 父交易修改可以同步重算子交易中由父交易派生的账务表达，但不得修改子交易自身的金额、时间、账户选择、备注或账务行为；需要改变子交易账务行为时必须拒绝父交易修改。
- 顶层交易只允许普通支出与报销垫付双向转换；其它账务行为只能在原类型内修改，子交易和系统账务行为不参与类型转换。
- 普通支出与报销垫付互转时可以保留已有退款，并按目标父交易重算退款的抵减账户；已有报销到账或结束报销时，不允许将报销垫付转换为普通支出。
- `is_excluded_from_stats` 与 `is_excluded_from_budget` 是交易组级配置，统一同步到父子交易。普通支出转为报销垫付时两项配置重置为 `false`，之后转回普通支出时显示并沿用该状态。
- 交易组级排除配置在父子交易行上冗余保存，创建和修改子交易时必须与顶层交易同步；统计与预算查询直接读取当前交易行，不为此 self join 顶层交易。
- 结束报销存在时，不允许修改或删除交易组中更早的退款与报销到账；必须先删除结束报销，使交易组重新开放。
- 结束报销存在时，任何会改变其剩余应收或差额金额的父交易修改也必须拒绝；基础信息、付款账户、支出分类和报销应收账户仍可修改，账户变化需要同步重建子交易的父派生分录。
- 账务核心删除交易时不校验 `owner_*`；带业务归属交易的跨域清理由 application 调用路径负责，绕过所属业务域直接删除属于调用方错误。
- 迁移旧更正链时，顶层交易使用旧 `root_transaction_id` 作为稳定交易身份，并归并当前父版本的内容；当前子交易保留自身 id，`parent_transaction_id` 统一改为顶层稳定 id，其余版本记录删除。
- 日常修改通过移除旧分录影响并应用新分录影响来差量更新账户余额，日常删除只移除被删分录影响；旧更正链迁移的被删记录净影响为零，因此迁移不修改或重算账户余额。
- 修改交易的账务表达时，按受影响交易整组删除并重建 `transaction_details` 与 `entries`，不对聚合内部行执行逐行 diff 或 upsert；只改基础信息时不重建分项和分录。
- 任何可能影响父子语义、累计金额、结束报销锁或子交易派生分录的写入都必须加载完整交易组并通过统一的重写计划；纯基础信息和业务归属修改可以只加载单笔交易。
- `parent_transaction_id` 在子交易创建后不可修改；录错父交易时必须删除并重新创建子交易。账务核心不使用数据库外键，但写入时必须校验父交易存在、属于顶层交易且账务行为兼容。
- 本次调整不新增交易分项或分录金额必须为正数的约束；金额符号能力留待独立需求处理，不与移除历史版本模型绑定。
- 数据库与代码一次性切换到当前状态模型：迁移在单个事务中归并当前数据、更新引用、删除历史版本并重建 schema；不双写、不保留旧模型 fallback，也不支持降级回旧 schema，迁移失败则整体回滚。
