# 押金复用应收增加原语

押金是一种可能收回、也可能被扣减的已付款项。它没有独立于应收余额和普通支出的事实，因此不为押金增加账务行为、编排实例或状态机。

## Decision

- 借出和支付押金统一使用“应收增加”：减少付款资金账户，同时增加应收账户余额。
- 押金使用普通应收账户承载余额。新建交易的“往来”场景负责借出与押金的录入文案，场景不写入交易，也不改变过账规则。
- 押金收入、扣除和退款均按普通账务事实记录。剩余押金使用应收收回；被扣除部分记录为日常支出，并把对应应收账户作为支出账户。
- 日常支出允许应收账户作为支出账户。该能力只扩大日常支出的账户角色，不允许应收账户因此进入收入、转账或其它结算场景。
- 押金不进入交易编排域。没有押金编排实例、逐笔核销关系、关闭状态或跨交易归属。

## Consequences

- 押金沿用应收账户的余额、编辑、删除、统计排除和预算排除能力，不增加持久化模型。
- 押金扣除会形成真实支出，并直接减少应收余额；后续收回金额以扣减后的实际应收余额为准。
- 借出和押金在交易流水中统一显示为“应收增加”，应收账户详情中的创建入口显示为“记应收”。
- 交易编排域继续只承载需要额外场景事实、跨交易关系或状态机的复杂能力，普通押金不扩大该域职责。
