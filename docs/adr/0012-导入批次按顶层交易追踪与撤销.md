# 导入批次按顶层交易追踪与撤销

SmartFlow 的导入批次在导入域内为每个成功导入交易组只记录顶层交易 ID，并通过物理删除这些顶层交易撤销批次；账务核心不保存批次 ID，也不改变当前状态交易模型。顶层交易是账务交易组现有的稳定身份和删除边界，因此这种设计既能删除导入后新增的子交易，也避免导入域追踪不断变化的子交易集合。

## Considered Options

- 在每条账务交易上保存导入批次 ID：拒绝，因为批次身份不是账务事实，会让账务核心依赖导入域。
- 在批次详情中保存顶层与全部子交易 ID：拒绝，因为子交易可以在导入后增删，保存导入时快照不能表达撤销时的当前交易组。
- 用冲销交易或软删除撤销：拒绝，因为 SmartFlow 按 ADR-0009 使用当前状态交易模型，导入不应建立另一套删除语义。

## Consequences

- 批次只处于 `imported` 或 `reverted` 状态；撤销保留批次和详情，但解除后续导入的重复限制。
- 批次撤销在一个事务中删除仍存在的全部顶层交易并更新批次状态；失败时整体回滚，重复撤销幂等。
- 已被手动删除的顶层交易在撤销时忽略；已修改的顶层交易和导入后新增的子交易仍随当前交易组删除。
- 导入创建的交易当前不得带业务归属；未来若允许其它业务域事后关联导入交易，必须重新设计撤销时的跨域清理规则。
- 批次详情不使用数据库外键，不保存子交易 ID、交易快照、文件或来源记录关系。
