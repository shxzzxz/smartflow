# 标签作为交易的正交描述维度

SmartFlow 引入标签时将其定位为交易上正交于分类的描述性维度，表达一笔业务事件同时属于哪些事或视角（旅行、装修、某个项目），而不是分类层级的延伸或账务语义的载体。分类回答"记在什么科目上"，标签回答"属于哪件事"；标签不进入账务真相——不产生分录、不影响余额、不参与过账规则，因此删除标签只解除全部交易引用，不镜像分类"存在引用禁止删除"的账务约束。

## Considered Options

- 标签作为第三层分类细目：拒绝。分类语言已刻意锁定两层（「未细分」词条明确拒绝第三层分类），用标签绕过该决策会污染分类语言。
- 标签以统计口径为动机（如固定/变动支出划分）：拒绝。按标签重分组是正交定位的自然结果而非动机；只为重分组时应做自定义报表。
- 单标签：拒绝。单标签等价于第二个分类，无法表达"旅行 + 报销"的组合，不构成正交维度。
- 层级标签或标签分组：拒绝。层级语义由分类拥有；标签分组是词表膨胀后的治理手段，属过早抽象。
- 子交易独立持有标签或创建时复制继承：拒绝。前者使退款漏打标导致标签统计虚高，后者在父交易改标签后产生陈旧继承；标签描述的是业务事件整体。

## Consequences

- 所有账务行为的交易都可携带零个或多个标签；转账、借入、还款等无分类交易同样可打标签，标签不继承分类的适用范围。
- 标签挂在顶层交易上，子交易不单独持有标签，查询与统计读取时继承所属交易组的标签；退款在同一标签桶内自然抵减，与导入域按交易组草稿组织数据的结构对齐。
- 标签词表扁平、由用户管理：录入交易时可即时新建（经同一词表查重），管理页负责重命名、合并、排序与删除；删除展示使用数量并解除全部引用。
- 标签是交易筛选的第四个独立维度，与分类、结算账户、时间取交集；维度内多选为任一命中（OR），并提供与具体标签互斥的「未打标签」选项。
- 标签统计与收支统计同口径：仅收入/支出交易、按交易时间归属、退款抵减、`is_excluded_from_stats` 的交易组排除。转账不进入标签统计——取现等转账不构成消费，计入会与后续消费重复计算；转账标签只服务查询。
- 统计页的标签构成展示「未打标签」条目，表达未携带任何标签的交易净额；它只是统计展示项，不是持久化实体，地位类似分类统计中的「未细分」。
- 多标签统计接受重复计数：每个标签桶的口径是"命中该标签的交易净额"，按标签分组合计大于收支总额是预期行为，不做分摊或主标签归一。
- 预算不按标签设置（预算保持月 × 支出分类；多标签下预算口径无法定义）；数据清理条件不引入标签维度；导入不为标签做映射或预留代码（现有来源无标签字段，未来来源经来源映射机制扩展）；标签只挂交易，不为账户、预算等实体打标签。
