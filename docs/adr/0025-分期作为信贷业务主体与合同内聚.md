# 分期作为信贷业务主体与合同内聚

用户实际办理的是一项分期，而不是创建一份合同。信贷域将“分期”定义为一等业务主体；分期合同不再独立存在，其条款、还款计划、重定价和期次状态作为分期的内部配置与子数据。一个分期只有一份合同配置，两者共用一个身份和生命周期。

## Decision

- 顶层领域主体统一为 `Installment`。`id` 是用户在信贷域中识别该笔分期的稳定身份，也是账单明细、还款目标和账务业务归属使用的分期 ID。
- 分期类型只有三种：放款分期、账单分期、消费分期。放款分期覆盖此前的贷款分期与现金分期；挂载贷款账户或信用账户只影响账单生成，不产生新的分期类型，也不再使用“贷款分期”或“现金分期”作为独立展示类型。
- 不再保留独立的来源类型。`installment_type` 决定来源事实的语义：
  - 放款分期指向借入交易；记录型放款允许没有来源引用。
  - 账单分期指向创建该分期的分期还款记录。
  - 消费分期指向购买交易。
- 分期保存一个可空 `source_ref_id`。来源事实同时保存分期引用，形成双向链接。来源事实一侧是权威关系，分期上的 `source_ref_id` 是聚合索引；两者必须在同一 application 事务中维护，不允许各自独立变化。
- 一项来源事实最多对应一项分期。账单分期和消费分期的 `source_ref_id` 必须非空；只有放款分期允许为空。账单还款记录上的 `generated_installment_id` 与来源身份具有唯一约束。
- 删除 `disbursement_account_id`。放款入账账户属于借入交易，不属于分期；`liability_account_id` 才是分期挂载的负债账户。
- 分期整体状态 `ACTIVE / SETTLED` 属于 `Installment`；期次自身的 `PENDING / PARTIALLY_PAID / PAID / SKIPPED` 继续属于还款计划。整体状态由计划和实际还款事实投影得到。
- 放款交易和购买交易通过账务 `owner_type = credit.installment`、`owner_id = installment.id` 归属分期。合同不再占用跨域业务归属身份。
- application 按用户实际行为和还款目标划分：
  - 放款分期与消费分期分别组织自己的交易、分期和计划创建；消费分期退款属于消费分期行为。
  - 账单分期是一种账单还款 implementation，与普通账单还款共同位于账单还款 module，共享账单分配、核销和状态刷新。
  - 分期提前还款以分期为目标，账户还款以信用账户为目标并创建统一还款记录；三者共享 settlement implementation。
- 普通应付账户还款属于账务能力，直接使用账务的交易创建与编辑 interface。信贷域删除 `createLiabilityRepayment`、`editLiabilityRepayment` 和 `loadLiabilityRepaymentEditView`，不再提供绕过信贷还款事实、只修改负债余额的旁路。

## Considered Options

- **继续由合同同时表达能力类型、来源和合同配置**：拒绝。实体用“类型 + 多个互斥可空引用”表达隐式联合类型，允许大量非法状态；调用方还必须把“创建合同”翻译成用户实际执行的分期行为。
- **新增一个分期实体，与合同一对一关联**：拒绝。分期的合同始终一一对应、同生共死，没有独立创建、删除或替换合同的业务需求。拆成两个主体只会增加同步与不一致风险。
- **保留贷款分期和现金分期两个类型**：拒绝。两者共享借入来源与合同计划规则，账户类型已经决定账单生成差异，没有独立生命周期或业务不变量。
- **建立通用来源实体或通用来源类型**：拒绝。分期类型已经决定来源结构；新增来源类型会形成第二个一一对应维度，并重新引入与分期类型不一致的可能。
- **将账单分期作为独立顶层 module**：拒绝。账单分期的目标是核销账单，与普通账单还款共享分配和状态投影；创建分期只是该还款行为的内部实现。
- **把普通负债还款包装在信贷还款 module 中**：拒绝。它不创建信贷还款记录，也不参与账单、分期或未归属欠款，属于账务交易能力。

## Consequences

- 物理主表由 `installment_contracts` 改为 `installments`，合同配置、计划、重定价、利息调整和退款还本等子表统一使用 `installment_id` 逻辑引用；不使用数据库外键。
- `bill_items.contract_id` 改为 `installment_id`，还款目标从合同改为分期；既有 `RepaymentType.installment` 改为账单分期语义，避免与分期主体重名。
- 来源映射需要从原有 `source_type` 与四个引用字段迁移为 `installment_type` 与单个 `source_ref_id`，并为来源关系补齐唯一约束和一致性校验。
- 计划引擎与利率计算不感知分期类型；类型只决定来源事实、账单归集和 application 编排。
- 查询模型、备份恢复、状态修复和账务 owner 解析统一使用分期身份，不再同时暴露合同身份与分期身份。
- 本决策保留 [ADR-0005](0005-账单为中心的信贷还款模型.md) 的账单中心还款模型，并保留 [ADR-0024](0024-消费分期作为购买与融资一体的信贷场景.md) 的消费分期业务边界；仅调整信贷业务主体与合同的组织方式。
