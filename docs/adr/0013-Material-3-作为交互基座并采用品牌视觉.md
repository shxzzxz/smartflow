# Material 3 作为交互基座并采用品牌视觉

SmartFlow 保留 Flutter Material 3 作为控件行为、交互状态、无障碍和平台集成的技术基座，但不把默认 Material 外观视为产品视觉上限。通用控件通过设计 token 和 `ThemeData` 组件主题统一映射为 SmartFlow 品牌视觉，领域组件继续通过财务语义消费主题；仅在组件主题无法稳定表达目标结构或交互时新增自有基础组件。

组件示例页使用 `AppSurface` 卡片承载单个组件族。卡片是示例文档的信息分组容器，而不是要求所有业务页面都采用卡片布局；业务页面仍根据内容关系选择表面、留白和列表结构。

## Considered Options

- 直接使用默认 Material 3 外观：拒绝，因为会把框架默认样式误当成产品品牌，难以形成稳定且有辨识度的财务工具体验。
- 全面自研控件并脱离 Material：拒绝，因为会重复承担焦点、状态、点击反馈、键盘和无障碍等底层行为，维护成本与回归风险过高。
- 使用 Cupertino 控件复刻参考视觉：拒绝，因为平台中性的卡片、圆角和阴影不要求引入 iOS 专属控件与交互隐喻。

## Consequences

- `useMaterial3` 保持启用，Material 组件负责行为，SmartFlow 的 token、主题和组件负责最终视觉。
- 按钮、输入、搜索、页签、选择控件、反馈、弹层和导航的稳定外观优先收口在主题层，页面不得重复配置同类视觉值。
- Android 系统栏、返回、窗口、安全区、键盘、焦点、48dp 触控目标和无障碍语义继续遵循平台约束。
- 品牌视觉变更会影响多个业务页面，主题级调整必须同时验证亮色、暗色、关键业务页面和既有 widget tests。
- 示例页允许统一卡片化，但卡片组件示例需要提供可辨认的预览层级，避免同色表面嵌套。
