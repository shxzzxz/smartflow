# 字段编辑三态协议

SmartFlow 跨层 partial update 统一使用 `Patch<T>?` 表达“不修改、设值、清空”三种语义。这个决策避免 nullable 字段在 service、repository、infrastructure 之间被压扁成二态协议后产生语义错位。

## Considered Options

- 每个允许清除的字段配一个 `clearXxx: bool`：拒绝，因为扩展成本随字段数量线性增长，且容易把“不改”误判成“清除”。
- 在层与层之间做 `Patch<T>?` 到 `clearXxx + value` 的翻译：拒绝，因为三态信号会在边界被压扁又还原。
- 提供 nullable 到三态的便捷工厂：拒绝，因为 `null` 在不同上下文可能表示不知道、不改、清除或占位。
- 给所有 nullable 字段都套 `Patch<T>?`：拒绝，因为 `Patch<T>?` 只服务于业务允许清除的字段。

## Consequences

- 只有“DB 可为 null”且“业务允许从有值清除为无值”的字段使用 `Patch<T>?`。
- service command、domain repository 接口和 infrastructure 实现使用同一套三态语义。
- Drift 层通过统一适配把 `Patch<T>?` 转成 `Value<T?>`。
- 调用方在 nullable 进入三态协议时必须显式选择 set 或 clear。
