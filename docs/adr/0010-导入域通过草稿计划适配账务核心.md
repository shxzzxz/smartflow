# 导入域通过草稿计划适配账务核心

SmartFlow 将导入作为独立业务域，负责导入来源、来源映射、来源记录与操作身份、导入交易计划、批次结果和撤销编排；账务核心继续只负责账户、交易、分录与过账规则。每种导入来源只有一个跨批次作用域，用于选择解析器并归属来源映射与重复判断。各来源解析器产出导入域自己的强类型交易组草稿，每组由一条顶层交易草稿和零到多条子交易草稿组成，不直接构造账务核心命令；映射与确认完成后，导入域通过其定义的账务端口将草稿转换为账务 application 命令，基础设施适配器遵循 ADR-0001 调用账务 facade。

## Considered Options

- 解析器直接返回账务创建命令：拒绝，因为来源解析会依赖 SmartFlow 内部账户身份和账务 API，映射、歧义确认及命令演进都会扩散到每个解析器。
- 把来源、映射和批次追踪放入账务核心：拒绝，因为这些信息表达导入来源与执行历史，不是账务事实。

## Consequences

- 新增来源格式通常只需新增解析器；新增账务行为才需要扩展导入草稿类型和账务适配转换。
- 用户先选择导入来源并提供一组文件；具体来源解析器负责自动识别和校验文件角色，通用导入流程不提供手动角色配置。
- 解析器可以识别并过滤由其它来源事实完整表达的冗余记录；过滤数量和原因只在当前解析结果中展示，不进入批次跳过数量，也不持久化。
- 导入交易组草稿是整体校验、选择、去重和提交的最小单位，不使用跨交易组依赖；多条来源记录可以共同推导一个交易组。
- 提交交易组时先创建顶层交易，再按解析器给出的顺序创建子交易；解析器必须产出账务语义上有效的子交易顺序，不使用通用依赖图。
- 只为导入交易组的顶层草稿生成来源操作键与指纹，子交易不单独去重；顶层交易仍存在时整组视为已导入，顶层交易被删除后整组可以重新导入。
- 重复判断只比较同一导入来源的历史成功导入交易组；手工交易、自动创建的交易和其它导入来源不参与匹配。
- 导入创建的顶层与子交易统一标记为 `SourceKind.import`；批次追踪和撤销边界见 [ADR-0012](0012-导入批次按顶层交易追踪与撤销.md)。
- 导入开始时直接采用仍可用且角色兼容的既有来源映射；名称规范化后的唯一兼容匹配也直接填入当前配置，不再提供“应用建议”操作。
- 无法匹配的实体只生成 `ImportMappingCreation` 计划。计划在成功提交导入时、与账务交易和批次写入处于同一个外层事务中执行；取消或提交失败不会留下新账户或类别。
- 用户选择“保存映射配置”后，默认映射在同一成功事务中写入；只用于当前导入的临时覆盖不持久化。
- 来源映射在使用时验证目标账户或类别是否仍可用；目标被归档后必须重新映射，账户归档操作不需要通知或清理导入域。
