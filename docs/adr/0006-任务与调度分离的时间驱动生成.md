# 任务与调度分离的时间驱动生成

App 无服务端、无可靠后台执行（Android 后台受 Doze / 被杀 / 厂商省电限制），但多个业务域需要"到点生成"能力：信贷账单生成、预设域周期记账、周期账单到期等。需要统一机制，且调度策略未来可能更换（如引入 WorkManager），不应让各域绑死某种调度方式。

## Decision

把"任务"与"调度"拆开：

- **Task（由需要定时能力的业务域定义并实现）**：`run(now)` 完成"截至 `now` 应发生而未发生"的全部可自动处理工作，返回本次执行的 `completed` 或 `retryLater`。等待人工确认属于正常完成，缺少外部数据或部分执行失败请求重试；不通过 Task 上的可变字段传递结果。**Task 实现方负责保证幂等与并发安全**；具体实现机制由实现方决定，本 ADR 不规定。
- **调度器（通用能力，application 跨域层）**：持有已注册的 Task，决定**何时 / 如何**调用。**调度策略可整体替换或叠加**，不影响 Task。

**调度契约（核心）**：调度器**不保证准时、不保证只调用一次、不保证一定被调用**（App 不打开就不跑），也**不做单飞 / 加锁**。因此 Task **必须自身幂等且并发安全**、容忍迟到与重复、能一次补齐多个错过的周期。

- **调度策略可插拔**：当前采用**拉取式**，在 App 冷启动与从后台恢复时触发，并按 Task + 自然日水位避免当日重复空跑；异步执行不挡 UI。进入相关页或相关写入前不额外触发。后台定时器（WorkManager 等）是未来可接入的策略之一，因 Task 不依赖调度方式，可随时替换或叠加。
- **重试由调度策略限频**：`retryLater` 和普通 `Exception` 不推进完成水位，默认从执行结束起冷却 15 分钟，连续失败间隔翻倍，上限 6 小时；成功后清除退避。冷却跨自然日延续，结束后仍等待下次触发，不创建定时器或在一次触发中循环重试。策略可注入，显式 `force` 绕过冷却和当天完成水位。执行记录和冷却均为进程内状态，冷启动重新扫描；并发执行仍被允许，但较早执行的迟到结果不得覆盖较新执行的调度状态。`Error` 继续向全局边界传播。
- **不编排跨 Task 顺序**：Task 间相互独立；跨域时序依赖由域自身补齐 / 回填逻辑消化，调度器不负责排序。

## Considered Options

- **生成逻辑与触发都写进各域、各搞一套**：拒绝。重复，且无法统一替换调度策略。
- **调度器保证准时 / exactly-once**：拒绝。本地无服务端无法保证，强行保证会把复杂度堆给调度器且仍不可靠；改为"弱保证 + Task 自幂等并发安全"更稳、更易演进。
- **由本 ADR 规定 Task 的幂等 / 并发实现机制**：拒绝。机制属域实现细节，统一规定会限制实现方；ADR 只定契约。

> 后台定时器（WorkManager / push）**不在拒绝之列**——它只是本次未采用的一种调度策略，未来可作为调度器实现接入，不影响 Task。

## Consequences

- 通用调度器不依赖任何域；域实现 Task 并注册（守 [ADR-0001](0001-业务域划分与账务核心独立性.md)）。
- `application/shared/task/` 分别存放 Task 定义、拉取调度器与重试策略；具体 Task 放在 `application/<domain>/task/`，调用域内用例，不把定时触发职责混入业务用例文件。
- 调度策略（触发点、频率、是否引入 WorkManager 等）可独立演进或叠加，Task 不动。
- Task 实现方自行保证幂等与并发安全；机制（如数据层唯一约束）属域实现，不在本 ADR 约束。
- 信贷账单生成是第一个 Task；其幂等 / 并发实现见信贷域文档。预设域周期记账后续注册。
- 现仅搭"Task 抽象 + 注册 + 一种拉取式调度策略"的薄缝，不预造调度引擎。
- 提醒类的准时性由 OS 本地通知单独承担，不依赖本调度器。
