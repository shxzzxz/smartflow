# 任务与调度分离的时间驱动生成

> 周期记账的领域归属由 [ADR-0036](0036-录入域统一记账输入与执行能力.md) 确定为录入域；本文的任务与调度契约继续适用。

App 无服务端、无可靠后台执行（Android 后台受 Doze / 被杀 / 厂商省电限制），但多个业务域需要"到点生成"能力：信贷账单生成、预设域周期记账、周期账单到期等。需要统一机制，且调度策略未来可能更换（如引入 WorkManager），不应让各域绑死某种调度方式。

## Decision

把"任务"与"调度"拆开：

- **Task（由需要定时能力的业务域定义并实现）**：提供稳定 `key` 与不可变 `runPolicy`；`run(now)` 完成"截至 `now` 应发生而未发生"的全部可自动处理工作，返回不可变的本次执行结果，包含 `completed` 或 `retryLater`，以及可选的下一次期望检查时间 `nextCheckAt`。时间提示仅申请额外触发机会，不阻止周期检查，也不绕过执行策略。等待人工确认属于正常完成，缺少外部数据或部分执行失败请求重试；不通过 Task 上的可变字段传递结果。**Task 实现方负责保证幂等与并发安全**；具体实现机制由实现方决定，本 ADR 不规定。
- **调度器（通用能力，application 跨域层）**：持有已注册的 Task，决定**何时 / 如何**调用。**调度策略可整体替换或叠加**，不影响 Task。

**调度契约（核心）**：调度器**不保证准时、不保证只调用一次、不保证一定被调用**（App 不打开就不跑），也**不做单飞 / 加锁**。因此 Task **必须自身幂等且并发安全**、容忍迟到与重复、能一次补齐多个错过的周期。

- **触发来源可插拔**：前台运行模块在 App 冷启动和恢复前台时提供一次周期检查机会，并使用一个一次性计时器选择后续触发；后台停止计时，恢复后按实际当前时间补齐。默认周期检查间隔为 15 分钟，自动触发的最小间隔为 3 分钟，两者可配置。周期检查评估全部任务，额外触发只评估有效期望时间已到的任务。日期相关界面刷新作为独立任务申请下一次本地午夜，通知可见性刷新申请最近一条未来消息的可见时间。后台周期调度（WorkManager 等）可独立接入，Task 不依赖触发来源。
- **下一次唤醒由调度器统一决策**：调度器保存各任务的时间提示，将提示与执行策略的下一次允许时间、失败冷却合并为有效候选；调用方通过 `updateTaskSchedule` 更新提示，前台运行模块订阅计划变化并重设计时器。任务执行结果更新提示，失效的旧执行结果不覆盖较新提示。没有时间提示的任务等待周期检查。自动触发的最小间隔按上一轮实际发起检查的时刻计算，显式用户操作不等待这个间隔。
- **运行策略由 Task 提供，水位由调度器管理**：`oncePerWindow` 按窗口大小与偏移划分本地日历固定窗口，窗口内成功后跳过后续普通触发；一日窗口默认以本地午夜对齐，账单生成、重定价与摊销采用此策略。`minInterval` 从成功完成时起计算最小间隔，还款提醒检查使用 1 小时。固定窗口记录本次 `run(now)` 覆盖的时点，跨窗口才完成的旧工作不消费新窗口；最小间隔记录实际完成时点。成功才推进水位，失败沿用独立重试退避。策略不创建计时器，也不提供严格的调用次数限流或一次送达保证。
- **重试由调度策略限频**：`retryLater` 和普通 `Exception` 不推进完成水位，默认从执行结束起冷却 15 分钟，连续失败间隔翻倍，上限 6 小时；成功后清除退避。冷却跨自然日延续，冷却结束时间可以作为下一次有效候选，不在一次触发中循环重试。重试策略可注入，显式 `force` 绕过运行策略和重试冷却。执行水位和重试记录均为进程内状态，冷启动重新扫描；并发执行仍被允许，但较早执行的迟到结果不得覆盖较新执行的调度状态。`Error` 继续向全局边界传播。
- **用户操作主动执行**：还款提醒设置保存后直接运行通知同步流程，再通过调度器主动执行通知可见性刷新任务以接收最新时间提示；`executeNow` 只绕过指定任务的自动执行限制，不强制执行其他任务。账单生成和普通还款用例不承担通知排程。
- **不编排跨 Task 顺序**：Task 间相互独立；跨域时序依赖由域自身补齐 / 回填逻辑消化，调度器不负责排序。

### 自动触发与周期检查的合并规则

设下一次周期检查时间为 `P`，自动触发最小间隔为 `M`，上一轮自动检查时刻为 `L`，最早有效期望时间为 `E`。候选时间 `C = max(E, L + M, 当前时间)`。

| 条件 | 本轮检查 | 下一次周期检查 |
| --- | --- | --- |
| 无时间提示，或 `C >= P` | 在 P 评估全部任务 | 本次实际检查时刻 + 周期间隔 |
| `C <= P - M` | 在 C 评估到期任务 | 保留 P |
| `P - M < C < P` | 在 C 提前执行周期检查，评估全部任务 | 本次实际检查时刻 + 周期间隔 |

边界使用严格不等号：P 为 10:15、M 为 3 分钟时，10:12 的候选保留 10:12 和 10:15 两次检查；10:13 的候选升级为周期检查，下一周期为 10:28。计时器迟到时使用实际当前时间；已经超过 P 时只执行一次周期补齐，不重放错过的回调。任务执行本身耗时或应用被暂停时，不承诺严格准点或最大实际延迟。

## Considered Options

- **生成逻辑与触发都写进各域、各搞一套**：拒绝。重复，且无法统一替换调度策略。
- **调度器保证准时 / exactly-once**：拒绝。本地无服务端无法保证，强行保证会把复杂度堆给调度器且仍不可靠；改为"弱保证 + Task 自幂等并发安全"更稳、更易演进。
- **由本 ADR 规定 Task 的幂等 / 并发实现机制**：拒绝。机制属域实现细节，统一规定会限制实现方；ADR 只定契约。

> 后台定时器（WorkManager / push）**不在拒绝之列**——它只是本次未采用的一种调度策略，未来可作为调度器实现接入，不影响 Task。

## Consequences

- 通用调度器不依赖任何域；域实现 Task 并注册（守 [ADR-0001](0001-业务域划分与账务核心独立性.md)）。
- `application/shared/task/` 分别存放 Task 定义、拉取调度器、前台运行模块与重试策略；具体 Task 放在 `application/<domain>/task/`，调用域内用例，不把定时触发职责混入业务用例文件。
- 触发来源（生命周期、前台计时器、是否引入 WorkManager 等）可独立演进或叠加；Task 提供所需运行策略，不依赖具体触发机制。
- Task 实现方自行保证幂等与并发安全；机制（如数据层唯一约束）属域实现，不在本 ADR 约束。
- 信贷账单生成是第一个 Task；其幂等 / 并发实现见信贷域文档。预设域周期记账后续注册。
- 前台运行模块统一管理计时器启动、暂停、恢复、释放和下一次唤醒；调度器管理执行资格、时间提示与重试状态。应用的前台运行状态持续作用于当前运行器实例，数据恢复等依赖重建后，新实例沿用该状态。前台模块合并自身进行中的检查机会，显式调用或其他触发来源仍可能产生重叠执行，任务的幂等与并发安全契约保持有效。
- 还款提醒通过独立发现任务同步本地消息和系统定时通知，不要求账单生成或还款用例调用通知。消息先保存到本地通知中心，是否可见按计划时间判断；OS 展示受权限与节电策略影响。通知中心历史与已读状态、系统排程身份与补发去重记录、任务的内存水位各自维护；系统通知清理不表示用户已读，排程过期不删除已发布的消息历史。
- 系统通知采用至多一次处理：向 OS 提交前先持久化排程登记，登记失败时不提交；登记成功后，提醒时间已过的同日提醒不重复补发，即使平台调用失败或进程中断。登记表示处理资格已消耗，不是成功送达或用户已读的凭据。未来排程在提醒时间前允许使用同一通知 ID 更新或修复，核对系统排程内容以识别未成功的更新。该取舍接受系统通知缺失，应用内消息仍按约定时间可见。
