# 仓储层与读路径分层

SmartFlow 的纯 UI / 报表读路径分为 infrastructure query source、application query service/read model、UI view model 三层。domain 不依赖 Drift watch、Stream、`TransactionScopeFilter` 或读侧投影口径；会参与领域规则判定的事实加载通过 domain port 表达。

## Considered Options

- 在 repository 或 SQL 中编码业务流程字面量：拒绝，因为统计和查询口径调整会散落到 infrastructure。
- 让 read model 持有账户名、图标、展示方向等 UI 装饰：拒绝，因为 UI 变化会推动查询模型变化。
- 在 repository 内按 purpose 分支编排数据：拒绝，因为 repository 会同时承担数据访问和业务判断。
- 让 domain 直接依赖 Drift 响应式原语：拒绝，因为 domain 会绑定具体持久化技术。
- 让 application 自己拼领域事实后替 domain 判断规则：拒绝，因为领域事实需求本身属于领域知识。

## Consequences

- application query side 定义查询接口、查询参数、scope filter 和 read model。
- infrastructure query implementation 只实现参数化数据访问和响应式触发，不承载领域规则判定。
- UI view model 负责名称查找、图标、格式化和展示派生。
- 领域规则事实加载使用专用 domain port 和领域上下文，不复用 application read model。
