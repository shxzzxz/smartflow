# 账户画像作为共享产品形态

账户画像（资金 / 报销 / 信用 / 贷款）是账户的**项目级产品形态**，承载建户、页面分组与业务入口编排，不表达账务事实。它由共享层的 `AccountProfileKind` 统一注册：每个画像绑定稳定 key、中文 label、图标与账务约束（账户类型、可选账务语义子类型），key 采用 `<域>.<画像>` 命名空间（`ledger.fund` / `ledger.reimbursement` / `credit.credit` / `credit.loan`），落库为账户的 `account_profile_key`。

遵循 [ADR-0001](0001-业务域划分与账务核心独立性.md)：画像既不属账务核心也不属任何兄弟业务域，加之它携带表现元数据、横跨多个业务域，故置于共享层、由其统一注册。

## Considered Options

- **画像 key / 枚举落在账务核心 ledger**：拒绝。画像不表达账务事实——账务核心只凭账户类型与账务语义子类型判断账户能否参与账务行为；把项目级产品形态塞进账务核心会污染其语言。
- **各业务域各自定义画像、UI 再聚合**：拒绝（当前）。画像总量小且稳定，集中注册的维护成本低于"各域贡献 + 聚合"的机制成本；为不确定的画像繁殖预留属过早抽象，待画像确需按域插件化再评估。
- **为画像单列一张表 / 加外键**：拒绝。画像是代码内枚举式注册表，落库只需账户行上的 `account_profile_key` 字符串；新增表与外键违背项目约束。

## Consequences

- `AccountProfileKind` 是账户画像的唯一真相源：新增画像在此增项，key 遵循 `<域>.<画像>` 命名空间，不得在别处另立 key。
- 画像的表现元数据（label / icon）只在共享层，与账务核心解耦。
- 落库不变：画像表达为账户 `account_profile_key` 字符串，无画像表、无外键。
