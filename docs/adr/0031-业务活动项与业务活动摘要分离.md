# 业务活动项与业务活动摘要分离

> 业务活动项与交易的一一关系及活动入口判断已由 [ADR-0032](0032-业务活动项与账务交易解耦.md) 修订；业务活动项与活动摘要分离的原则继续有效。

业务活动列表和交易明细视图使用不同的查询单位。把活动级摘要放进每笔交易的业务上下文，会让非锚点交易加载并展示不属于自己的活动信息，也会按交易重复活动摘要。因此读侧显式区分业务活动、业务活动项和业务活动摘要。

## Decision

- `BusinessActivity` 表示一项业务活动，由活动身份、锚点交易和一份 `BusinessActivitySummary` 组成。
- `BusinessActivityItem` 表示一笔实际交易在所属业务活动中的业务侧投影，只包含该交易的发生含义、局部分类分配和操作所需事实。
- `BusinessActivitySummary` 表示活动整体状态与进度，按活动身份返回一次，不按参与交易重复。
- 交易明细列表直接消费 `BusinessActivityItem`，不另建 `BusinessActivityItemSummary`；单笔交易不需要再次聚合。
- 业务活动视图使用锚点交易和活动摘要；交易明细视图使用实际交易和可选的业务活动项，不加载活动摘要。
- 业务活动入口由具体业务活动项的 kind 判断，不新增冗余的入口布尔字段。
- 非锚点交易详情只加载当前交易及其需要的局部业务事实和最小父级约束，不加载锚点交易组、兄弟交易或活动摘要，也不展示业务模块。
- 交易详情先装配本地 `TransactionDetailContext`；只有当前 item kind 表示活动入口时，再由上层详情查询加载 `BusinessActivity` 供业务模块和活动详情入口使用。
- 业务活动入口在交易明细视图中保留分类身份，并把业务活动项作为第三行说明；非入口交易改用本次交易语义的名称与固定图标，不展示分类身份或第三行。
- 业务活动项的发生含义由所属业务域解释；`transaction_view` 不在 adapter 中根据 `BusinessPurpose` 自行判断业务 kind。
- 业务活动项只携带当前交易的局部事实；活动状态、余额和进度只属于 `BusinessActivitySummary`。
- 业务活动页先由各来源查询锚点，归并后分别批量查询业务摘要和账务 anchor transaction，再装配 `BusinessActivity`。
- 成员发现和内容订阅分离：业务活动锚点页或账本交易页负责发现新增成员；内容流复用已选 anchor，按当前活动集合有界刷新摘要和锚点交易，不重新解析 activity ID 对应的 anchor。

## Consequences

- `transaction_view` 不再拥有包含活动摘要的通用交易上下文模型。
- 交易明细和非锚点交易详情不会因为所属活动历史增长而读取整项活动。
- 业务活动列表保留当前来源优先的分页归并，摘要只对最终页活动批量加载。
- 现有成员的内容刷新不发现集合外的新活动；成员集合变化时由外层重新订阅当前集合。
- Feature 根据稳定业务活动项类型选择局部展示与操作，不直接读取 owner 内部结构。
- 该模型只存在于读侧，不新增持久化业务活动、锚点字段、关联表或数据库外键。
