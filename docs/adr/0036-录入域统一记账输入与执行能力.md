# 录入域统一记账输入与执行能力

SmartFlow 使用录入域（`intake`）组织用户描述、外部来源资料和已授权周期规则到记账输入的解释与执行。识别录入、来源导入和周期记账属于同一域的不同能力，分别拥有候选输入、导入计划与批次、周期规则等模型。账务核心继续管理账户、交易、分项、分录、余额和过账规则。

## Considered Options

- 按截图、语音和文件等介质拆域：同一介质可以表达不同业务意图，输入渠道不能稳定表达业务职责。
- 将所有流程统一为导入批次：来源映射、批次与撤销属于来源导入；周期规则和一次性识别输入各有自己的生命周期，强制复用批次会引入无关状态。
- 把录入解释与规则执行纳入账务核心：来源知识、平台识别能力和规则执行状态会扩散到过账规则，破坏账务核心独立性。

## Consequences

- 来源导入从独立导入域归入录入域的 `import` 能力；识别录入、周期记账和模板记账按各自工作流逐步落地，不预建通用录入状态机或空实现。
- 能力目录位于 `application/intake/`、`domain/intake/`、`infrastructure/intake/`；Feature 继续按页面与用户工作流组织，通过录入 application facade 使用能力。
- 来源解析器保留导入草稿和来源实体语义；来源导入通过本能力的账务 port 与 infrastructure adapter 消费账务核心 facade，遵循 [ADR-0001](0001-业务域划分与账务核心独立性.md)。
- 导入批次的追踪与撤销继续采用 [ADR-0012](0012-导入批次按顶层交易追踪与撤销.md) 的交易组边界。数据库表、既有枚举 wire code、备份中的 `import/` 分区和导入错误码表达来源导入能力，不因领域目录改名而迁移。
- 周期任务遵循 [ADR-0006](0006-任务与调度分离的时间驱动生成.md)，规则执行与调度机制分离。
- 重复交易判断是面向已有交易、由各录入入口共用的能力，不作为领域划分依据。现有来源导入的去重范围扩展属于后续行为变更，须单独定义匹配规则并验证。
- 本决策调整 [ADR-0010](0010-导入域通过草稿计划适配账务核心.md) 中导入的独立业务域归属，以及 [ADR-0017](0017-数据管理域逻辑备份与快照恢复.md) 中导入业务归数据管理域的表述；草稿适配、批次撤销和完整备份契约继续适用。
