# 图标引用、分组与可移除品牌包

## 背景

SmartFlow 原有账户和分类图标通过裸 `iconKey` 引用，并由全局账户/分类风格在渲染时决定具体资源。不同视觉风格需要重复保存同一批图标，品牌图标又和项目自绘图标混在风格目录中，导致：

- 一条账户记录无法同时表达它选择的视觉风格，用户不能混用不同风格。
- 移除品牌资源会影响项目自绘资源的结构。
- 后续增加用户上传图标时，需要继续扩展全局风格分支。

## 决策

图标选择使用稳定的四段引用：

```text
source:type:group:key

builtin:account:rounded-line:bank-card
builtin:account:brand:alipay
user:account:my-icons:<uuid>
```

- `source` 表示资源来源，当前为 `builtin` 或 `user`。
- `type` 为 `account` 或 `category`。
- `group` 是稳定的分组 ID，可为视觉风格、品牌包或用户分组；显示名称可以修改，ID 不可跟随名称变化。
- `key` 是来源分组内的稳定资源键。

`BusinessIconRegistry` 是 UI 依赖的查询与解析模块。它组合一个或多个 `BusinessIconSource`，提供分组查询、搜索和精确引用解析；调用方不直接依赖 asset bundle 或文件目录。

内置图标通过声明式 manifest 注册：

```text
assets/styles/account/manifest.json
assets/styles/category/manifest.json
assets/styles/account/brand/manifest.json
```

风格分组和品牌分组都作为 `group` 参与选择，但品牌包位于账户资源目录内，可整体移除或替换。账户和分类不再保留全局图标分组设置；选择器直接展示分组，每条记录保存自己的完整引用。

用户图标通过独立的 `user` 来源接入。用户从“我的 → 交易 → 图标管理”上传 PNG、JPEG 或 WebP，应用校验并拒绝动图后，将图片等比归一化为 256×256 透明 PNG。图标清单、转换后的文件、占用检查和删除策略归数据管理域；账户和分类继续只保存完整引用，不新增数据库图标表。

用户图标按账户、分类分别属于固定分组 `my-icons`。分类图标可同时用于收入和支出分类；删除前由应用检查账户与分类引用，正在使用的图标不得删除。用户图标清单和文件共同进入逻辑备份，恢复时与数据库一起校验和替换。

迁移规则：

- 内置数据升级读取历史账户/分类图标设置，把现存裸 key 改写为完整引用。
- 品牌 key 在同一次迁移中写入 `brand` 分组，不留在渲染层长期兼容。
- 迁移完成后删除旧图标分组设置，运行时不重复扫描或兼容裸 key。
- 新选择的账户或分类图标直接保存完整引用。
- 渲染层只解析完整引用；裸 key 不再参与运行时回退。
- 显式引用缺失时使用通用图标并记录错误，不回退到另一风格。

## 后果

- 同一页面可以混用不同风格或来源的图标，后续可在已有记录上逐项迁移。
- 品牌图标可以独立隐藏、移除或替换，不需要改动风格 manifest 和账户数据结构。
- 用户图标文件随逻辑备份一起复制，不只备份引用元数据。
- 当前数据库列继续保存完整引用，暂不新增图标专用表或外键；内置数据升级完成后不会在渲染层接受裸 key。
- 新增图标分组时必须保证分组 ID 稳定，并补充引用解析、混合风格、旧 key 迁移和迁移幂等测试。
