# 账户子类型标准化与往来余额应收应付

SmartFlow 将账户子类型限定为从资产负债表科目提取的稳定账务性质，账户画像继续留在共享产品层。应收与应付采用账户级往来余额模型，不建立逐笔债权债务或核销关系；本决策同时确定普通应收、应付的借出、收回、坏账、借入、还款和债务豁免边界。

## Decision

- `AccountType` 固定为 `asset`、`liability`、`equity`、`income`、`expense`。
- `AccountSubtype` 的首组稳定值为 `fund`、`receivable`、`payable`、`loan`；`borrowing` 只表示借入账务行为，不表示账户子类型。
- 账务核心只依赖账户类型与子类型。账户画像不参与过账判断；共享层注册六种画像：`ledger.fund`、`ledger.reimbursement`、`ledger.receivable`、`ledger.payable`、`credit.credit`、`credit.loan`。
- 应收与应付是往来余额账户。借出增加应收，收回减少应收，坏账以坏账损失减少应收；借入增加 `payable` 或 `loan` 负债，还款减少负债，债务豁免以债务减免收入减少负债。
- 期初余额只表达启用 SmartFlow 前已存在的事实；余额调整只纠正账面差异。两者不替代有明确业务含义的收付、损失或减免。
- 借入与还款可作用于 `payable` 或 `loan`；收支直接形成应收或应付的赊销、赊购能力留待后续。
- 收回的 `primaryAmount` 是实际收到的现金总额，由本金和利息组成；本金减少应收，利息进入利息收入。坏账与债务豁免不得超过当前可减少余额；收回与还款允许余额穿零并由产品提示。
- `interestIncome`、`badDebtExpense`、`debtReliefIncome` 是系统创建且不可删除的收入/支出分类。利息收入纳入收支统计；坏账损失按支出处理，默认计入收支和预算并允许编辑两种排除标记；债务减免收入按收入处理，默认计入收支且只允许编辑统计排除标记。

## Migration

历史 `reimbursement` 子类型迁移为 `receivable`。信贷账户按 `kind` 与已知画像补齐三字段；无法判定的历史负债默认迁移为 `payable` 并记录告警，非空字段之间的真正冲突进入迁移错误报告，不静默覆盖。账户类型、子类型和画像在创建后不可变；系统资产/负债账户需要兼容子类型但不需要画像，权益、收入、支出账户不需要子类型或画像。

## Consequences

账务核心可以用子类型校验借出、收回、坏账以及负债借入、还款、豁免的账户角色，而不依赖信用卡、贷款、报销或合同等产品身份。新的账务行为沿当前状态交易模型编辑和删除，余额通过移除旧分录再应用新分录维护；不会引入逐笔应收单、应付单或独立状态机。
