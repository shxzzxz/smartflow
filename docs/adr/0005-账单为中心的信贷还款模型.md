# 账单为中心的信贷还款模型

信贷域采用**账单（Bill）为中心**的还款模型：账单是用户还款面对的统一目标，按 `(账户, 周期)` 唯一，内部由账单明细汇集消费与多个合同的期次。账单明细是借据侧计划与消费事实的投影，金额、还款日期和核销状态不可直接编辑；消费窗口可通过专用入口调整。普通查看只刷新 `OPEN` 账单，`BILLED` / `SETTLED` 由用户显式刷新时按来源重建；修正一律作用于来源（交易、计划）。核销以本金为准，由还款明细统一承载；账单分期是一种还款形态，不是明细状态。

账单生成双轨：信用账户**周期驱动**（出账日协调消费明细窗口），贷款账户**合同驱动**（期次按月归集进账单，无账户级周期参数）。账单本身只保存账户、账单月份和聚合状态；消费窗口与真实还款日期属于账单明细。

## Considered Options

- **还款直接绑计划期次（原模型）**：拒绝。无法承载出账日汇总消费、多合同合并账单、一次还款跨合同；消费信贷（无计划）无处安放。
- **账单只作实时聚合视图、不落表**：拒绝。部分还款归属、出账定格、与真实账单的差异对账都需要稳定的明细载体。
- **为消费信贷建"信用合同"求对称**：拒绝。合同 ⟺ 多期还款计划，消费信贷无计划，强建退化成空壳并复制账户余额。
- **出账后账单冻结不可变（本 ADR 初版）**：拒绝。补记交易、修改入账时间、计划修正都需要显式刷新路径；普通查看只刷新 `OPEN`，用户可手动刷新任意状态账单。
- **账单明细金额可手工编辑**：拒绝。改消费金额会与账户余额失配，改分期金额会与合同本金失配；消费窗口可通过专用入口调整并重新投影，其他修正一律作用于来源，利息 / 手续费差异由还款表单据实填写吸收。
- **贷款账户沿用账户级出账 / 还款日锚点（本 ADR 初版）**：拒绝。强制期次对齐账户周期无法表达末期对齐整年、季供等真实合同条款；改为合同驱动按月归集，"期次对齐账户周期"约束整体删除。
- **账单分期用明细状态 CONVERTED 表达**：拒绝。无法表达"明细 400 = 现金还 200 + 分期还 200"的混合核销，部分转分期还要拆明细行；分期还款作为还款形态统一走还款明细。
- **预生成未来全部期次账单（Eager）**：拒绝。信用账户只维护上一已出账周期与当前 OPEN 周期；贷款账户只生成当期账单，不生成 `+1` 期。
- **独立核销实体（核销单）**：拒绝。核销是"明细离开待还"的事件，由还款明细承载即可，不需要第四张表。
- **按还款状态与重算锚点冻结计划前缀（本 ADR 旧版）**：不再采用。它把计划纠正与履约状态耦合，妨碍补记或修改历史操作。改为完整条款与日期化操作驱动的统一计算；未来本金扣减仍只作用于其计息位置，普通还款和旧计划状态不参与算法。
- **还款记录不存日期或仅无交易时存日期**：拒绝。还款时间属于每笔还款自身的业务事实，不应随是否生成交易改变记录形态。所有还款自持还款时间；有交易时由信贷应用用例在同一数据库事务内同步维护交易时间，避免两个时间各自修改产生差异。

## Consequences

- 还款侧 `bills` / `bill_items` / `repayments` / `repayment_items` 四表；`installment_repayments` 废弃。`bills` 不再承担消费窗口；窗口和出账状态保存在 `bill_items` 的 `start_inclusive`、`end_inclusive`、`billing_state`。
- 还款记录**不存金额**：金额 = Σ 还款明细分项。所有还款自持还款时间，作为展示与本金扣减发生日期的依据；关联交易时间由信贷用例同步维护，还款账户从当前交易派生。`BILL` / `PREPAYMENT` 的 `transaction_id` 可空（导入 / 迁移核销），`INSTALLMENT` 天然无交易；`UNATTRIBUTED` 必须关联账务还款交易。
- 状态重判同时考虑应还金额、引用存在性和本金：存在应还金额且无还款明细引用为 `PENDING`；完全无应还金额的占位明细为 `PAID`；存在引用但本金未足额为 `PARTIALLY_PAID`；本金足额为 `PAID`。利息 / 手续费不阻塞核销。
- 还款创建、删除与修改通过 application settlement coordinator 推进或回退计划和合同状态；显式跳过或恢复通过合同聚合改变计划状态；合同详情可由用户显式按有效还款分摊校验并修复计划与合同状态；账单生成与刷新只重建账单投影，不把账单明细状态写回计划和合同。
- 提前还款统一为合同级 `PREPAYMENT`；其有效本金转换为本金扣减，增删改后按有效操作完整重算。不含本金时不改计划，计划变更不自动刷新账单。
- 自动生成与重算按合同条款和有效操作生成完整计划，覆盖人工调整；自定义合同的计划完全由用户手工维护。
- 计划计算、实际还款和状态维护分别负责。多阶段顺序传递日期与本金，各阶段使用自己的初始利率和重定价结果；计划保存后按还款事实修复合同与期次状态。见[业务规则 §6](../domains/credit/业务规则.md#6-合同维度操作)。
- 合同 XIRR 只消费合同与全部状态（含 `SKIPPED`）的计划现金流；实际还款（含提前还款）不参与资格判断。计划本金之和精确等于合同本金后，再判断现金流充分性和利率解。
- **现金分期放开**：DISBURSEMENT 合同可挂信用账户；贷款分期、现金分期和账单分期共用合同阶段配置与计划生成规则，产品标签（贷款 / 现金 / 账单分期）读侧派生，信用账户只影响账单投影和还款归集。
- 额度、欠款分桶、出账预览、XIRR 均为读侧派生；来源变化在刷新前体现为未归属欠款差额。
- 信贷账户参数（额度、出账日、还款日、出账日归属开关）由信贷域 `credit_liability_accounts` 持有并提供创建 / 编辑接口。
- `BillItem.id` 在同一账单连续刷新且来源仍存在时稳定。来源因移期或移除而消失后，刷新删除旧明细，并在同一事务中将引用它的还款分项 `bill_item_id` 置空；还款金额、实际日期、交易和原账单归属保留。新账单按当前计划完整投影，不自动转移或扣减旧还款。
- 空关联分项作为历史数据允许读取，编辑表格显示“无明细”；用户须显式移除无效分项、纠正分摊后才能保存。该方案接受历史录入与当前计划之间的暂时差异，不维护跨账期还款迁移或已还金额补偿机制。
