# 账单为中心的信贷还款模型

信贷域采用**账单（Bill）为中心**的还款模型：账单是用户还款面对的统一目标，按 `(账户, 周期)` 唯一，内部由账单明细汇集消费与多个合同的期次。账单明细是借据侧计划与消费事实的**只读投影**——落库但不可编辑，出账前自动跟随来源，出账后不自动改写、只提示差异、由用户显式同步；修正一律作用于来源（交易、计划）。核销以本金为准，由还款明细统一承载；账单分期是一种还款形态（分期还款），不是明细状态。

账单生成双轨：信用账户**周期驱动**（出账日截单、窗口链式衔接），贷款账户**合同驱动**（期次按月归集进账单，无账户级周期参数）。

## Considered Options

- **还款直接绑计划期次（原模型）**：拒绝。无法承载出账日汇总消费、多合同合并账单、一次还款跨合同；消费信贷（无计划）无处安放。
- **账单只作实时聚合视图、不落表**：拒绝。部分还款归属、出账定格、与真实账单的差异对账都需要稳定的明细载体。
- **为消费信贷建"信用合同"求对称**：拒绝。合同 ⟺ 多期还款计划，消费信贷无计划，强建退化成空壳并复制账户余额。
- **出账后账单冻结不可变（本 ADR 初版）**：拒绝。补记交易、修改入账时间、计划修正都需要修正路径；改为"只读投影 + 显式同步"——系统永不静默改写已出账账单，是否向来源收敛由用户裁决。
- **账单明细可手工编辑**：拒绝。改消费明细会与账户余额失配，改分期明细会与合同本金失配；修正一律作用于来源，利息 / 手续费差异由还款表单据实填写吸收。
- **贷款账户沿用账户级出账 / 还款日锚点（本 ADR 初版）**：拒绝。强制期次对齐账户周期无法表达末期对齐整年、季供等真实合同条款；改为合同驱动按月归集，"期次对齐账户周期"约束整体删除。
- **账单分期用明细状态 CONVERTED 表达**：拒绝。无法表达"明细 400 = 现金还 200 + 分期还 200"的混合核销，部分转分期还要拆明细行；分期还款作为还款形态统一走还款明细。
- **预生成未来全部期次账单（Eager）**：拒绝。改计划 / 提前还将级联改写未来账单；按需生成（信用账户按周期补齐、贷款账户补齐到当前月 +1）。
- **独立核销实体（核销单）**：拒绝。核销是"明细离开待还"的事件，由还款明细承载即可，不需要第四张表。

## Consequences

- 还款侧 `bills` / `bill_items` / `repayments` / `repayment_items` 四表；`installment_repayments` 废弃。
- 还款记录是**纯动作记录**：金额 = Σ 还款明细分项，日期与还款账户从有效交易沿更正链的 current parent 派生；`root_transaction_id` 可空——**所有还款形态支持不生成交易**（导入 / 迁移核销；分期还款天然无交易）。
- 核销与状态是金额关系的纯函数：`Σ 分摊本金 ≥ 应还本金 ⟺ 明细 PAID`，任何金额变化（同步、还款、更正）后状态重判；利息 / 手续费不阻塞核销，超额分摊允许；账单待还本金按 `max(0, 应还本金 - Σ 分摊本金)` 派生。
- 提前还款统一为合同级 `PREPAYMENT`，只重算发生日之后的 `PENDING` 计划；不跳过计划、不关闭合同。已出账账单不自动改写，差异以"与来源不一致"提示呈现，显式同步以 replace projection 收敛。
- **现金分期放开**：DISBURSEMENT 合同可挂信用账户；合同期次节奏由挂载账户类型决定（信用账户按账期生成、贷款账户按合同条款），产品标签（贷款 / 现金 / 账单分期）读侧派生。
- 额度、欠款分桶（含未归属欠款 = 负债余额 − 合同 PENDING 剩余本金 − 账单消费剩余本金）、出账预览、IRR（履约维度 + 本金完整性校验）均为读侧派生。
- 信贷账户参数（额度、出账日、还款日、账单起始期、出账日归属开关）由信贷域 `credit_liability_accounts` 持有并提供创建 / 编辑接口；账务核心 `accounts` 同名字段进入迁出过渡。
