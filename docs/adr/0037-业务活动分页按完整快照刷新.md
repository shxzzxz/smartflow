# 业务活动分页按完整快照刷新

业务活动分页需要合并多个来源的候选，再读取交易与业务摘要。将候选页和内容作为独立的持续结果流，会组合不同时刻的数据；删除时旧候选仍可引用已经消失的交易。分页以完整页作为查询与刷新单位，复用有界候选查询和批量内容读取，以一致读取快照和较小的监听接口替代分散的结果流协作。

## Decision

- `findPage` 在同一数据库读取事务中完成候选发现、归并排序、交易与摘要读取及页面装配。所有一次性查询必须等待完成，长期监听建立在事务外。
- `watchPage` 监听当前启用来源的候选及完整投影依赖。监听先建立，再发出首次加载通知；相关写入提交后的变更批次触发一次完整页查询。
- 变更依赖由消费端 infrastructure 的查询变更来源维护，使用去重的表集合。新增来源或增加一次性查询的读取依赖时，同步补充该集合。预算、保险等未参与该页读取的表不触发该查询。
- 首页、日历和筛选业务活动列表直接消费完整页面流，不再额外订阅分页成员的内容流。分页游标与内容来自同一次读取，不通过过滤缺失投影来修补页面。
- 内容表变化也重查候选；当前页查询保持有界。表级失效允许无关行变化触发重查，只有性能证据表明候选查询成为明显开销时，才重新评估分开刷新的优化。
- 查询失败向消费方报告，但不主动取消后续变更监听。取消页面订阅时释放该监听。
- 交易详情按已有活动集合进行有界内容订阅的能力保留。活动身份、活动项与摘要的分离继续遵循 ADR-0032；候选明确没有展示交易时，仍是合法的活动投影。

## Considered Options

- 候选结果流与内容结果流分别更新：可节省部分候选查询，但需要处理旧成员失效、切换和过期结果，增加分页一致性的维护成本。
- 写入成功后由调用方逐页触发刷新：需要维护写入口与读页面的关联，也要覆盖导入和后台写入。采用数据库依赖变更自动刷新。
- 区分成员与内容失效并建立刷新优先级调度器：当前允许内容变化时重查候选，不引入这层调度状态。

本决策修订 [ADR-0031](0031-业务活动项与业务活动摘要分离.md) 中业务活动分页的成员流与内容流协作方式，活动项、活动摘要和交易详情有界读取的语义继续有效。
