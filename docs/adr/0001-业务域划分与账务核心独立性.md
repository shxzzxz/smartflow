# 业务域划分与账务核心独立性

SmartFlow 将 `ledger` 作为账务核心 Shared Kernel：账户、交易、分录、过账规则和账务流图原语都归入账务核心。其它业务域可以消费账务领域能力，但账务核心不感知兄弟业务域；跨域用例由 application 层编排。

## Considered Options

- 把业务域身份编码进 `BusinessPurpose`：拒绝，因为 `BusinessPurpose` 应表达账务行为，不应成为业务域注册表。
- 让账务核心根据 `owner_*` 反向调用业务域：拒绝，因为这会让 `domain/ledger` 依赖兄弟业务域。
- 让消费域 application 直接依赖提供域 application：拒绝，因为跨域语义、错误转换和依赖方向会变模糊。采用消费域 domain port + infrastructure adapter；adapter 可以调用提供域 application facade。
- 让调用方复制账务事实加载规则：拒绝，因为账务规则需要哪些事实本身是 ledger 领域知识。

## Consequences

- `domain/ledger` 不 import `domain/credit` 等兄弟业务域；仅保存月度分类目标的预算归入 ledger，不建立 `domain/budget`。
- `owner_type / owner_id / owner_role` 只表达业务归属索引，不参与账务过账分支。
- 跨域写侧流程收口在消费域 application；application 只依赖本域 domain port，消费域 infrastructure adapter 调用提供域 application facade。
- 当前事务执行器支持嵌套事务；adapter 调用参与最外层用例事务。验收测试覆盖成功、ledger 内层失败、ledger 内层成功后 credit 外层失败三类，任一失败均整体回滚。
- 新功能若引入新的 entry/detail 拆分和过账规则，进入 ledger；若只在账务原语之上维护合同、订阅、目标、计划等状态机，则作为独立业务域。
