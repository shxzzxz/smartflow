# 数据管理域逻辑备份与快照恢复

SmartFlow 将导入、数据清理、同步和备份归入数据管理域。备份使用专用全库 snapshot gateway，在一个数据库事务中读取账务核心、信贷域、导入域的业务表和可迁移用户偏好；不通过多个普通 repository 逐笔重建。

## 决策

- 备份包是多文件逻辑包：`manifest.json`、`preferences.json` 和按 `ledger/`、`credit/`、`import/` 分区的 NDJSON 文件。
- manifest 独立记录 `formatVersion` 与 Drift `schemaVersion`，并为每个文件记录清单、行数、字节数和 SHA-256。金额使用最小单位整数，UUID、时间和稳定 wire code 原样保留。
- manifest 预留 `encryption` 字段；首版不自行实现加密，未来使用成熟的 AES-GCM 与口令派生库。
- 恢复语义是完整快照的整体替换：备份有而当前没有的记录插入，当前有而备份没有的记录删除，同 ID 不同内容以备份覆盖。一致时不执行写入。
- 恢复必须先读取、完整性校验、硬引用校验、借贷平衡校验和账户余额校验，再计算面向业务的差异摘要；最终替换在单个数据库事务中执行，失败时当前数据保持不变。
- `app_metadata` 只抽取 `settings.*` 用户偏好；日志、原始导入文件、临时草稿、更新渠道、UI 折叠状态和内置数据版本不属于备份。

## 取舍

- 不选择单一巨大 JSON：多文件 NDJSON 可流式处理并支持大表分片，ZIP 只作为可选传输容器。
- 不选择合并恢复或逐条冲突解决：首版目标是把本地账本恢复到某一时刻的确定状态，差异只服务于恢复前预览。
- 不在数据库层新增外键约束：引用完整性由恢复校验和现有写入路径负责，遵循项目约束。

## 后果

未来可在保持格式版本独立的前提下增加格式迁移、ZIP 封装和成熟的 AES-GCM 加密；数据库切换和后台任务暂停仍属于后续平台集成工作。
