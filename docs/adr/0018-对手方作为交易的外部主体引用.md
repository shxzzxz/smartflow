# 对手方作为交易的外部主体引用

交易可以通过分类、标签、账户和备注表达业务事实，但缺少稳定表达“和谁发生”的维度。租房押金、水桶押金等场景需要复用同一账户，同时区分房东、中介或供应商；把每个主体建成账户会放大账户维护成本，把主体当作标签又会混淆“属于什么事”与“外部主体是谁”。

## Decision

- 对手方是交易上可选的外部个人或组织，每笔交易最多一个。
- 对手方使用独立词表保存稳定 ID 与当前名称，交易只保存 `counterparty_id`，不复制名称。
- 对手方名称由用户直接创建和复用；录入时同一词表内的精确同名记录复用。
- 对手方名称不是账务事实，不进入交易分项、分录、余额、统计或预算。
- 对手方与标签相互独立：标签表达业务事件所属的项目或视角，对手方表达交易面对的外部主体。

## Considered Options

- 继续在交易中保存自由文本名称：拒绝。名称修改无法稳定指向同一主体，也缺少可搜索、可复用和后续筛选的基础。
- 为每个房东、中介或供应商创建账户：拒绝。账户承担账务分类和余额责任，不应因管理对象数量增长而膨胀。
- 用标签代替对手方：拒绝。标签可多选且描述业务归属，不能准确表达单一外部主体。
- 为本次单选需求预先建立交易与对手方关联表：拒绝。当前关系是交易到对手方的可空单值引用，直接保存 ID 已完整表达；未来出现多对手方需求时再迁移。

## Consequences

- schema v47 从历史 `counterparty_name` 去重建立词表并回填 ID，不重算余额或分录。
- 修改对手方名称会更新该主体在全量历史交易中的当前展示名称，因为交易引用的是稳定身份。
- 删除对手方需要应用层处理交易引用；数据库不建立外键。
- 对手方词表进入逻辑备份，旧备份中的名称在恢复时迁移为词表与 ID。
