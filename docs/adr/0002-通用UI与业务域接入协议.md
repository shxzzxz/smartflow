# 通用 UI 与业务域接入协议

SmartFlow 的通用交易 UI 通过 `transactions.owner_*` 元数据解析 `TransactionActionPolicy`，由 policy 把删除、编辑、改账户、改时间、改备注等 universal 动作路由到对应业务域。purpose-bound 动作仍由 `BusinessPurpose` 驱动，不进入 `TransactionActionPolicy`。

## Considered Options

- 让通用 UI 维护具体业务域分支：拒绝，因为每新增业务域都要修改交易详情页等通用 UI。
- 把退款、报销结案等 purpose-bound 动作塞进 `TransactionActionPolicy`：拒绝，因为接口会随账务行为膨胀。
- 让业务域 policy 同时持有业务域 service 和 `PostingAppService` 自行编排一致性：拒绝，因为一致性逻辑会散落在 UI 集成层。
- 用跳转替代原位 universal 动作：拒绝，因为同类交易在不同上下文会出现不一致交互。

## Consequences

- `TransactionActionPolicy` 是 `feature/transaction/` 的 UI 集成层契约，不属于任何 domain。
- `feature/transaction/` 可以 import 业务域 service；domain 不感知 `TransactionActionPolicy`。
- 业务域 service 对外提供领域语义的编辑入口，policy 只负责按 `owner_role` 路由和声明 UI 策略。
- 未识别 owner 的交易统一落到 unknown policy，只允许低风险元数据操作。
