# 测试规则

本文档定义测试覆盖范围、分层责任和冗余测试的处理标准。测试用于保护业务行为、数据一致性和关键交互，不要求每个类、方法或页面都有对应测试。

## 覆盖原则

- 按失败风险和对外行为选择测试，优先保护账务正确性、数据写入、跨域事务、迁移、导入与恢复。
- 在能完整验证该行为的最低层测试；高层验证自身的编排或交互契约，不重复穷举底层规则。
- 暂不设置全仓行覆盖率或分支覆盖率硬门槛。覆盖率只辅助发现未执行路径，关键行为的成功、边界、拒绝和失败恢复场景须按适用性覆盖，不能用总体百分比替代。
- 新增或修改关键行为时同步补充或调整测试；简单文案、样式、无逻辑数据结构等低风险变更不机械新增测试。
- 修复可自动验证的行为缺陷时，优先增加能复现原问题的回归测试；已有测试可表达该场景时直接扩展，不另建重复测试。

## 目录与分层

测试目录随结构演进逐步镜像，按需建立：

```text
test/core/
test/domain/
test/application/
test/infrastructure/
test/feature/
test/shared/
test/widget/
test/design_system/
test/app/
test/architecture/
```

数据库机制、repository、迁移和其它基础设施测试放在 `test/infrastructure/`；从 application 用例入口验证多模块真实协作的测试放在 `test/application/`，即使其使用内存数据库。不要只因使用数据库就改变测试归属。

| 对象 | 应覆盖的行为 | 测试方式与边界 |
| :--- | :--- | :--- |
| `core`、`domain` | 金额精度与舍入、借贷平衡、余额变化、业务不变量、日期边界、状态转换和非法输入 | 纯 Dart unit test；通过公开行为验证规则，不依赖 Flutter widget 或真实平台服务 |
| `application` | command 语义、用例编排、跨域协调、幂等、查询投影、异常传播和失败后的数据状态 | 普通编排使用 fake / mock port；事务和多模块持久化行为使用真实实现配合 Drift in-memory |
| `infrastructure` | SQL 查询与映射、写入语义、已知冲突转换、迁移、文件格式及平台适配契约 | 数据库使用 Drift in-memory，文件使用独立临时目录；平台调用使用对应替身，并按需补平台验证 |
| ViewModel / provider | 页面状态、command 组装、加载与提交结果、错误映射、确有影响的生命周期行为 | override application / query provider 或使用 fake，避免启动真实数据库与平台插件 |
| presentation / `shared` | 金额展示、日期分组、筛选、排序和业务展示语义 | 普通 unit test；输入和期望值来自需求示例或手工推导，不复用被测算法计算期望值 |
| View / widget / 设计系统 | 关键渲染、输入同步、禁用状态、用户交互和项目自定义组件行为 | widget test；不在页面层重新验证整套领域计算 |
| `app` / 架构约束 | 启动装配、全局错误兜底、provider 错误观察，以及文档明确的导入与依赖边界 | 针对真实装配或边界的测试；不为文件名、私有方法名等实现细节增加扫描断言 |

`domain` 的“纯 Dart”约束指测试内容不依赖 Flutter UI 或平台能力；仓库可统一通过 `fvm flutter test` 执行。

## 数据与事务的必要场景

涉及以下行为时，覆盖对应场景：

- **账务写入和修改**：验证分录借贷平衡、账户余额和相关业务记录的一致性；按需求覆盖零值、边界金额、舍入余数、非法状态和删除 / 重算影响。
- **跨域事务**：覆盖整体成功、ledger 内层失败、ledger 内层成功后 credit 外层失败，后两者均验证两侧实际数据整体回滚。与 [ADR-0001](../adr/0001-业务域划分与账务核心独立性.md) 保持一致。
- **迁移**：从受支持的旧 schema / 数据样例验证升级结果和失败行为，检查数据保留及必要转换，不只断言版本号变化。
- **导入、批量清理和备份恢复**：覆盖合法操作、无效数据、适用的重复执行 / no-op，以及中途失败后没有违反用例契约的部分写入。
- **引用关系**：验证应用规则维护的数据关联与删除行为；禁止通过新增数据库外键约束满足测试。

回滚测试必须在写入已经发生后注入故障，并读取数据库确认状态；仅断言 mock 事务执行器被调用或捕获到了异常不构成回滚验证。

## MVVM 测试

- ViewModel 覆盖状态转换、页面级校验、command 组装、submit 成功 / 失败和 `AppException` 到 UI outcome 的映射；普通 `Exception` 映射为未知错误，`Error` 继续传播。
- 复杂表单关注新增 / 编辑初始化、重复提交控制、提交结束后的状态恢复，以及异步数据到达时不覆盖用户输入等实际行为。
- provider 测试聚焦查询组合、筛选参数和确有风险的加载 / 释放时序，不测试 Riverpod 自身已经保证的通用机制。
- widget test 使用准备好的页面状态或轻量 ViewModel 替身，验证 View 正确渲染状态、收集输入、转发意图和执行导航 / 提示；不通过 widget 间接验证大段 application 流程。
- 同一表单的业务分支组合优先在 ViewModel 验证，页面保留代表性的交互场景，不要求每页覆盖所有业务组合。

## 日志与错误处理测试

日志按 [日志规范](logging.md) 的对外契约验证：

- 统一入口验证 Debug / Release 阈值、输出内容及不重复订阅；异常记录验证稳定 code、实际严重程度、原始 cause / stackTrace 的安全保留。
- 动作、provider、后台任务和全局边界验证各自负责的失败能够被记录；对可能重复上报的调用链验证同一次失败只记录一次，独立重试失败仍能记录。
- 数据边界使用含敏感值的样例，检查 message、error、provider 描述、堆栈路径及兜底输出，避免财务数据或原始文件内容泄漏。
- 文件日志验证写入与读取、跨日和大小轮转、保留清理、异常或不完整记录的读取容错，以及日志初始化 / 写入失败不会影响业务或递归记录。
- 日志查看保留有实际逻辑的筛选、排序、详情复制、清空及设置生效测试；按逻辑归属选择 unit 或 widget test。
- 全局 UI 验证 Release 不暴露技术详情，Debug 按错误展示规范提供详情；单独调用 handler 的测试不能替代实际安装与路由接线的验证。

公共日志契约集中测试，普通业务测试不逐条断言日志文案和输出顺序。只有日志内容本身是该缺陷的回归保障时，才增加对应断言；优先断言级别、code、必要上下文和敏感内容缺失，不绑定完整自然语言句子。

## 平台验证与 CI

- CI 保持 `fvm flutter analyze` 与 `fvm flutter test`。需要辅助排查覆盖缺口时可运行 `fvm flutter test --coverage`，报告不作为百分比合并门槛。
- 本地先运行受影响测试；涉及公共能力、跨层行为或测试删除时，提交前运行完整 analyze 与测试。仅修改文档时检查内容、链接和 diff，无须启动 Flutter 测试。
- 不要求所有页面有端到端测试。涉及文件选择、保存、分享、权限等真实平台能力时，按变更覆盖相应平台集成验证；暂无法稳定自动化时记录平台、操作步骤和结果作为人工验证依据。
- 测试固定时钟和必要的随机种子，独立管理数据库、临时文件及 provider 生命周期；清理全局 Logger 订阅和错误 handler 等修改，不依赖真实用户数据、外网或测试执行顺序。

## 冗余测试治理

是否保留测试，取决于它独立保护的行为和故障风险，不按测试数量、目录或测试类型批量删除。

可删除或合并的候选包括：

- 仅验证构造参数原样存取、无逻辑 getter、生成的 `copyWith` / 相等性等依赖已保证的行为；但手写校验、兼容格式或持久化契约仍需测试。
- 只断言某私有方法存在、内部调用次数或固定调用顺序，且这些细节并非用例契约；幂等、副作用次数、事务顺序等具有实际语义的断言保留。
- 多层重复穷举同一业务规则，高层没有新增交互、装配或数据一致性保障。
- 仅重复证明 Flutter / Riverpod / Drift 本身的通用行为，或固定文本、色值、widget 层级快照却不保护项目明确要求的 UI 契约。
- 相同准备过程、行为和断言重复出现的场景，可合并成参数化测试；不同边界值和历史故障不因结构相似而丢失。
- 产品行为已删除或被明确替换的过时测试。

删除前需指出原测试保护的行为、保留该保障的位置，或该行为已不再需要保护的依据。以更低层测试替换高层测试时，先确认替代测试覆盖原故障，保留必要的层间接线测试，再删除冗余部分并运行相关检查。

历史回归、事务回滚、迁移、真实持久化、关键交互和架构边界测试不能仅因慢、维护成本高或影响覆盖率而删除；优先修正测试边界、样例规模和隔离方式。删除后测试全绿并不能单独证明删除合理。

调整测试时，在变更说明中记录新增、合并和删除的行为依据。
