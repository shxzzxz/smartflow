# 设计系统

本文档定义 SmartFlow Flutter 工程内的设计系统落地规则。约束视觉值、主题、组件和业务视觉语义在代码中的归属。

## 1. 当前阶段

SmartFlow 当前处于 MVP 阶段，以 **A 级：最小可落地版** 为基础，并开始补充 B 级协作能力：

- 建立 token、theme、基础组件和业务组件的分层入口。
- 新增代码必须使用设计系统已有能力，不再扩散原始色值和魔法数。
- 存量代码不做一次性重构，采用“触达即治理”。
- 提供仅调试模式可见的组件示例页，集中检查组件状态、财务语义和手机布局表现。

后续升级到完整的 **B 级：标准协作版** 时，继续补充静态检查规则和更稳定的页面模式库。

## 2. 分层结构

```text
Token 源层 -> 主题映射层 -> 基础组件层 -> 业务组件层
```

```text
lib/design_system/
├── token/
│   ├── colors.dart        # 原始色板，不被页面直接消费
│   ├── component.dart     # 通用控件几何、状态透明度和边框 token
│   ├── spacing.dart       # 间距 token
│   ├── radius.dart        # 圆角 token
│   ├── typography.dart    # 字体 token
│   ├── elevation.dart     # 阴影 token
│   ├── form.dart          # 表单几何和状态 token
│   ├── motion.dart        # 动效 token
│   └── chart.dart         # 图表色 token
├── theme/
│   ├── app_color_scheme.dart       # Material 3 ColorScheme
│   ├── app_theme_extension.dart    # 财务、状态、图表等扩展语义
│   ├── app_text_theme.dart         # TextTheme
│   └── app_theme.dart              # ThemeData 组装
├── widget/              # 通用基础组件
└── showcase/             # 组件示例页

lib/widget/business/     # 跨 feature 复用的业务组件，可按视觉语义分组，例如 finance/、transaction/

assets/icons/             # 业务图标资源
├── account/
├── category/
└── tab/
```

### Token 源层

Token 源层是项目内视觉原始值的唯一来源，负责颜色、间距、圆角、字号、阴影、动效和图表色等基础值。

约束：

- token 命名按尺度或用途归类，如 `space4`、`radiusMd`、`durationFast`。
- 原始颜色只允许出现在 token 源层，业务页面禁止新增 `Color(0xFF...)`、hex、rgb 等写法。
- token 只定义值，不包含业务判断。

### 主题映射层

主题映射层将 token 映射为 Flutter 可消费的语义入口：

- Material 3 `ColorScheme`：品牌色、背景色、表面色、错误色等通用语义。
- `TextTheme`：标题、正文、标签等文本语义。
- `ThemeExtension`：Material 3 没有覆盖的状态、财务和图表语义。

Material 3 在 SmartFlow 中承担控件行为、状态、无障碍和 Flutter 实现基座，不作为默认视觉模板。按钮、输入框、搜索、页签、选择控件、反馈、弹层和导航等通用外观应在 `ThemeData` 的组件主题中统一映射为 SmartFlow 品牌视觉；只有组件主题无法稳定表达的交互或结构才新增基础组件。

消费边界：

- 颜色、文本、财务语义色优先通过 `Theme.of(context)`、`ColorScheme`、`ThemeExtension` 使用。
- 间距、圆角、动效时长等基础布局值允许通过 `AppSpacing`、`AppRadius`、`AppMotion` 直接使用。
- 页面层不直接读取原始色板 token。

### 基础组件层

基础组件放在 `lib/design_system/widget/`，只表达通用 UI 能力，不包含财务业务含义。

新增基础组件前先扫描 `lib/design_system/widget/` 下已有实现，避免重复造轮子

允许：

- `variant`：primary / outline / text 等。
- `size`：small / medium / large 等。
- `tone`：info / success / warning / danger 等通用状态。
- `state`：loading / disabled / selected 等。

禁止：

- 禁止出现 `IncomeButton`、`ExpenseBadge`、`AssetCard` 这类业务命名。
- 禁止在基础组件内部按账户类型、交易用途等业务字段改样式。
- 禁止在基础组件内部重新定义视觉 token。

`AppPopupMenuButton` 统一承载紧凑图标触发的弹出菜单。菜单项按交互语义声明：`AppPopupMenuAction` 执行命令后关闭菜单；`AppPopupMenuToggle`、`AppPopupMenuChoice`、`AppPopupMenuSelect` 和 `AppPopupMenuControl` 修改配置后保持菜单打开。页面只提供业务状态与回调，不自行处理菜单关闭或浮层内即时状态。

`AppSelectMenu` 统一承载选项查找、菜单渲染、当前选中态和变更回调；独立 Select 默认使用自适应锚定菜单，由 `AppDropdown`、`AppSettingsSelectRow` 分别提供左对齐和右对齐的触发器布局。`AppPopupMenuSelect` 属于嵌套菜单适配器，保留父菜单不关闭的交互语义，不复用独立 Select 的浮层定位。表单选择行仍由表单模块负责校验与外部选择流程，不直接复用设置行。

### 业务组件层

业务组件放在 `lib/feature/<feature>/widget/` 或 `lib/widget/business/`，用于沉淀财务领域的稳定表达。

`lib/widget/business/` 只放可渲染的业务组件，以及这些组件直接消费的轻量视觉语义类型。页面展示构建、查询辅助、跨页面 presentation helper 放在 `lib/feature/shared/presentation/`，避免业务组件目录变成页面数据适配的收纳目录。

典型组件：

- `MoneyText`：金额展示，统一正负号、颜色和格式。
- `MoneyInput`：金额输入，统一分位、小数、负数和校验反馈。
- `TransactionPurposeBadge`：交易用途标识。
- `AccountTypeTag`：账户类型标签。

同类表达在 2 个以上页面重复出现时，应优先抽为业务组件。

### 表单模块

表单使用“设计系统基础模块 + 业务输入模块”两层 seam：

- `AppFormSection`：表单分组标题、说明、表面和字段间留白。
- `AppPlainFormRow`：行式字段的标签、必填标识、辅助信息、错误信息和禁用状态。
- `AppPlainTextFormRow`：参与 Flutter `Form` 校验的文本输入行。
- `AppPlainSelectFormRow`：参与 Flutter `Form` 校验的整行选择字段。
- `AppSwitch`：紧凑视觉的通用开关，保留 Material 状态、语义与至少 48dp 触控目标。
- `AppPlainSwitchRow`：开关行的名称、可选描述和禁用状态；描述缺省时不占据布局空间。
- `MoneyPlainFormRow`：金额格式、金额校验和数字输入规则。
- 账户、分类、交易金额面板等带业务语义的输入保留在 `lib/widget/business/`。

表单视觉规则：

- 页面通过标题、分组表面、排版和留白建立层级，不在普通字段之间插入 `Divider`。
- 同一分组内的字段使用统一最小高度和间距；不同分组使用更大的 section gap。
- 编辑表单的文字、数字和选择值从统一值列起点左对齐，选择指示和开关停在行尾；纯展示详情继续使用值右对齐。
- 普通字段标签使用 14sp，字段值使用 15sp，辅助说明和错误使用 12sp；层级主要通过颜色和字重表达。
- 数值加单位属于一个复合字段，在值列内横向布局；出账日与还款日等并列字段使用各自带标签的等宽双列，窄屏或大字号时允许纵向排列。
- 标签、辅助信息、错误、禁用和只读状态由表单基础模块统一表达，页面不重复配置样式。
- `feature/` 表单页面不直接创建 `TextField`、`TextFormField`、`DropdownButtonFormField` 或 `InputDecoration`；需要特殊交互时，在设计系统或明确的业务输入模块中提供 adapter。
- 金额、账户和日期等字段的解析、校验和选择行为必须复用现有输入模块，不在页面复制。

设置页使用独立的即时配置行：

- `AppSettingsSwitchRow`：标题和说明在左，开关在右，支持整行切换与禁用态。
- `AppSettingsSelectRow`：标题和说明在左，当前值与右箭头在右，点击整行打开 Select 菜单。
- 设置行不替代表单行：它不参与 `Form` 校验，也不承载错误、必填或输入焦点状态。
- 设置行不替代弹出菜单项：`AppPopupMenuToggle`、`AppPopupMenuChoice` 和 `AppPopupMenuSelect` 继续负责菜单保持打开、关闭和嵌套选择等菜单语义。

Modal Bottom Sheet 只是页面容器，应按内部工作流选择表单行、设置行或紧凑 Select，不因处于弹层而新增一套控件。

### 组件示例页

组件示例页位于 `lib/design_system/showcase/`，通过路由 `/dev/design-system` 访问，并在“我的 → 开发工具”中提供入口，所有构建均可用。

当前只提供手机单栏布局，页面结构为“标题 → 搜索 → 横向分类 → 示例单元”。分类固定为：

- 设计基础
- 基础控件
- 表单与输入
- 选择器与弹层
- 反馈与状态
- 布局与容器
- 数据展示
- 财务表达
- 业务图标
- 交易与列表

约束：

- 示例必须直接消费现有 token、主题、基础组件和业务组件，不复制组件内部样式。
- 示例使用本地固定数据和页面内状态，不读取数据库、Provider 或业务查询。
- 交互组件应可实际操作，并至少覆盖正常、禁用、加载、错误或空状态中的适用状态。
- 横向分类使用页签语义，不把每个分类渲染成相互独立的按钮或 Chip。
- 一个示例单元只展示一个组件族；同一组件的不同状态可以并列展示，不把无关组件拼装在同一个单元中。
- 示例单元使用统一的 `AppSurface` 卡片承载一个组件族，通过白色表面、柔和阴影、标题、组件名和留白建立整体感。
- 展示卡片类组件时，应在示例卡片内提供可区分的预览背景或边界，避免同色卡片嵌套后层级不清。
- 基础组件示例使用“主要按钮”“加载状态”“卡片标题”等通用组件或状态文案；业务组件才使用对应领域语言。
- 新增稳定组件或视觉语义时，同步补充对应示例和 widget test。

## 3. 语义体系

### Material 语义

品牌、背景、表面、边框、禁用、错误等通用视觉语义优先使用 Material 3 `ColorScheme` 和 `TextTheme`，不在页面层另起命名。

### 状态语义

通过 `ThemeExtension` 提供：

- `success`
- `warning`
- `danger`
- `info`

`danger` 用于删除、失败、错误等通用危险状态，不等同于支出。

### 财务语义

通过 `ThemeExtension` 提供：

- `income`
- `expense`
- `transfer`
- `asset`
- `liability`
- `equity`

约束：

- `income` 不等同于 `success`。
- `expense` 不等同于 `danger`。
- `transfer` 保持中性表达，不在不同页面随意换色。
- `asset`、`liability`、`equity` 是账户域语义，不退化为具体色名。

### 图表语义

- 通用分析图使用 `chart1` ~ `chart8`：系列槽位按固定顺序取用，不循环复用；系列数超过槽位时尾部折叠为"其他"（`chartOther`）。
- 系列色亮/暗两套均需通过色盲可分性、亮度带与对表面对比度校验后才能进 token；调整色值或顺序后必须重新校验。
- 明确表达财务概念的图表使用财务语义色 `income`、`expense`、`asset`、`liability`、`equity`。
- 同一图表模块内不要混用系列语义和领域语义。

### 分析页面模式

- 页面层不直接配置第三方图表库；坐标轴、刻度采样、tooltip、空状态和图表几何由 `feature/<feature>/widget/` 下的适配组件收口。
- 数值图表必须提供纵轴刻度（金额用紧凑格式，刻度取整到干净数值），tooltip 只做补充信息，不承担唯一读数途径；同一页面的 tooltip 使用统一的反色底样式与金额格式。
- 时间序列必须根据观察区间选择粒度：月度可按日、年度按月，长自定义区间按周或月聚合，避免依赖横向滚动承载过密数据。
- 窄屏横轴只保留少量代表性刻度，并保证首尾刻度不会与相邻刻度重叠。
- 分析页使用“页面身份 → 本期概览 → 主趋势 → 次级分析”的层级，不让所有筛选器和图表拥有相同视觉权重。
- 同一区域存在多个次级展示维度时，保留一个主切换控件，其余选项收进菜单或筛选面板。
- 加载新区间时保留上一次内容降透明度过渡，不整页回退为加载指示。
- 关键分析页面至少保留一个手机宽度下的 widget test，覆盖页面层级、文本溢出和关键交互；系统字体相关视觉在目标 Android 设备上验证。

## 4. 编码规则

新增视觉值只能来自：

1. token 源层定义的常量。
2. 主题映射层暴露的 `ColorScheme`、`TextTheme`、`ThemeExtension`。
3. 基础组件或业务组件暴露的变体。

明确禁止：

- 在 widget 中新增长期存在的原始色值。
- 在页面层临时定义财务颜色、状态颜色或图表色。
- 在基础组件中写入财务业务判断。
- 在业务组件或页面中重新定义底层 token。

允许的临时例外：

- 历史 widget 中尚未迁移的原始样式。
- 第三方组件必须覆盖样式时，应优先封装统一适配层。
- 修复业务问题时，未触及区域可以暂不顺手重构。

原则：可以保留存量，不可以新增同类债务。

## 5. 平台与无障碍

- 当前阶段仅面向 Android。Android 约束应用的系统交互、返回行为、窗口与安全区、键盘、焦点、触控目标和无障碍能力，不限制 SmartFlow 的品牌视觉表达。
- Material 3 作为行为与实现基座，通过 `ThemeData`、设计 token 和基础组件建立 SmartFlow 自有视觉语言，不直接沿用默认 Material 外观作为产品风格。
- 圆角卡片、柔和阴影、品牌色和平台中性的排版可以跨平台使用；不引入 iOS 状态栏、Cupertino 控件、iOS 日期选择器等平台专属交互隐喻。
- 可点击控件不设全局统一的触控尺寸；按使用场景确定触控目标：列表行、按钮、表单控件等主交互保持舒适尺寸，图表浮层按钮、紧凑工具等空间受限场景允许更小的可视尺寸，同时通过扩大透明命中区域保留可点击性，并保留 Flutter Material 控件提供的焦点、状态和语义能力。
- 支持跟随系统暗黑模式，亮色和暗色主题共用同一套 token 源。
- 财务正负表达不能只依赖颜色，应结合 `+` / `-`、文案或结构。
- 状态表达不能只依赖颜色，应辅以图标、文案或布局差异。

## 6. 演进规则

- 新增页面优先复用已有基础组件和业务组件。
- 新增财务视觉语义前，先补充本规范和 `ThemeExtension`。
- 高频重复模式先进入 `lib/feature/<feature>/widget/`，跨 feature 复用后迁移到 `lib/widget/business/`。
- 完整 B 级阶段继续补充 `custom_lint` 或静态扫描，限制原始色值和 token 越层消费。
