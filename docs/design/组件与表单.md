# 组件与表单

本文档只记录组件职责、通用交互、组合方式和表单规范，不记录具体页面或某个表单的字段清单、内容与布局。页面行为以代码和交互测试为准。总体入口见 [05. 设计系统](../05.%20设计系统.md)。

## 基础组件层

基础组件放在 `lib/design_system/widget/`，只表达通用 UI 能力，不包含财务业务含义。新增前先扫描已有实现，并核对 [组件治理](组件治理.md) 与 [组件清单](组件清单.md)，避免重复造轮子。

组件差异通过明确的参数表达：

- `variant`：primary / outline / text 等视觉变体。
- `size`：常规、紧凑等尺寸。
- `tone`：info / success / warning / danger 等通用状态语义。
- `state`：loading / disabled / selected 等交互状态。

基础组件不使用 `IncomeButton`、`ExpenseBadge`、`AssetCard` 这类业务命名，不按账户类型或交易用途改样式，也不在组件内部重新定义视觉 token。

### 表面、列表与反馈

- `AppSurface` 统一表面、圆角、描边与阴影；消费方只声明所需变体。
- `AppListSection` 将列表行组合在同一表面内，统一处理行间的内缩分隔线；`header` 承载表面外的分组标题。
- `AppSectionHeader` 使用 `groupTitle`（15sp、w400）表达分组层级，`trailing` 承载同行操作。
- `AppListDivider` 用于同一列表表面内的行间分隔；其他方向或语义的分隔由对应组件负责。
- `AppEmptyState` 统一空状态的标题、辅助说明和可选操作，支持页内紧凑布局。
- `AppStatusBanner` 统一状态提示的语义、排版和可选右侧操作。

### 选择器与浮层

`AppPopupMenuButton` 统一承载紧凑图标触发的弹出菜单。`AppPopupMenuAction` 执行命令后关闭菜单；`AppPopupMenuToggle`、`AppPopupMenuChoice`、`AppPopupMenuSelect` 和 `AppPopupMenuControl` 修改配置后保持菜单打开。消费方提供状态与回调，不自行处理菜单关闭或浮层内即时状态。

分段单选统一使用 `AppSlidingSegmentedControl`，选项通过同文件的 `AppSegment` 声明。表单通过 `AppPlainSegmentedFormRow` 接入校验、禁用与重置，并沿用表单值字号；控件保留选中、禁用语义和 Material 点击、焦点行为。

`AppSelectMenu` 统一承载选项查找、菜单渲染、当前选中态和变更回调。独立 Select 使用自适应锚定菜单，由 `AppDropdown`、`AppSettingsSelectRow` 分别提供左对齐和右对齐的触发器。`AppPopupMenuSelect` 是嵌套菜单适配器，保留父菜单不关闭的交互语义，不复用独立 Select 的浮层定位。表单选择行负责校验与外部选择流程，不直接复用设置行。

`AppGroupedChoiceGrid` 承载“分组标题 + 紧凑网格”的选择结构，通过 `AppChoiceGridGroup` 和 `AppChoiceGridItem` 以数据驱动渲染。每组按可用宽度、最小项宽和大字号约束独立计算列数，最多四列；标准项高 64dp，使用 8dp 间距。网格项不使用描边，组件不渲染浮层级标题。业务含义、稳定 ID、图标与回调由消费方提供。连续图标浏览使用 `IconChoiceGrid`。

`AppChoiceChipGroup` 承载少量互斥短选项的单选胶囊，选项由 `AppChoiceChipOption` 声明。支持自动换行和等宽两种布局，并提供 `regular`、`compact` 两种尺寸。紧凑尺寸使用 12sp 字号，收紧水平内边距和选项间距，适合密集筛选与表单选项；大字号下按实际文本高度增高。选项含义、文案、选中值和变更回调由消费方提供，组件只负责呈现与交互语义。

`AppRegionPickerSheet` 承载逐级单选，父级只用于导航，点击配置的最后一级完成选择。数据与层级由消费方传入，组件不内置行政区划数据；路径页签允许返回上级，变更父级后清除原下级路径。

Modal Bottom Sheet 只负责容器，内部根据工作流复用表单行、设置行或 Select，不因处于弹层而另建一套控件。

## 业务组件层

业务组件放在 `lib/feature/<feature>/widget/` 或 `lib/widget/business/`，沉淀领域中的稳定表达。`lib/widget/business/` 只放可渲染的组件，以及组件直接消费的轻量视觉语义类型；页面展示构建、查询辅助与跨页面 presentation helper 放在 `lib/feature/shared/presentation/`。

业务组件沉淀可复用的展示与输入协议，具体页面的查询编排、命令与导航由对应工作流管理。业务状态到文案、格式与语义 tone 的映射留在 presentation 层。组件自己的通用行为与页面组合规则分开维护。

常用业务表达与组合能力：

- `MoneyText` 统一金额正负号、颜色和格式；`AdaptiveMoneyText` 在受限金额列中优先保留精确值，无法容纳时使用紧凑格式，列宽稳定时不可逐行缩小字号。
- `MoneyInput`、`MoneyPlainFormRow` 统一金额输入、分位、小数、负数和校验反馈。
- `AccountPickerSheet`、`AccountPickerOptionsSheet` 统一账户单选及其轻量选项契约；消费方提供候选范围、选中项和选择回调。
- `CategoryPickerSheet` 承载分级单选，返回稳定分类 ID，区分可选目标与仅用于导航的父级；单选与级联多选保持独立组件。
- `AppInlineActionButton` 统一紧凑图标文字操作的尺寸、排版、溢出和禁用表现；不可执行时保留占位并降低内容透明度。
- `AppDetailSummaryCard` 统一标题、重点指标和辅助信息的层级；文本指标在列内换行，单行金额按可用宽度缩放。
- `FinanceActivityRow` 统一活动图标、事件、日期、辅助文字、金额与整行点击；`period` 构造表达年度或月度期间，不补造实际发生日期。
- `AppStatusBadge` 统一语义 tone、紧凑变体、背景透明度和文字样式。
- `AppSupportingItems` 统一多段辅助信息的换行、间距、状态色和单行省略。

同类表达在两个以上独立消费场景重复出现时，按 [组件治理](组件治理.md) 的判据评估是否抽为业务组件，不以视觉相似作为唯一依据。

## 页头组件

所有页头由 `AppPageHeader` 承载，不使用 `AppBar` 或 `SliverAppBar`。页头分左侧控制、中间核心内容、右侧操作三段；消费方声明内容与动作，组件负责布局和共享外观。

### 内容与交互

- 文本标题使用 `AppPageHeader`，副标题只补充上下文；自定义标题控件使用 `AppPageHeader.custom`。
- `leading` 承载自定义左侧控件，提供时替代自动返回按钮。返回键按当前路由能否返回自动出现，只有抑制返回或接管返回时才显式配置。
- 操作区使用 `AppHeaderIconButton`、`AppHeaderTextButton` 或 `AppPopupMenuButton`，不由消费方配置图标尺寸、约束或视觉密度。图标操作控制在三个以内，其余收进菜单。
- `AppHeaderTabs` 与 `TabBarView` 的控制器同步；不依赖 `TabController` 的切换使用 `AppSlidingSegmentedControl` 的 `header` 变体。
- 页签支持点击与内容区左右滑动。`TabBarView` 使用原生滑动；状态驱动的切换通过 `AppTabSwipeRegion` 调用与点击相同的回调，按顺序切换相邻项，首尾不循环，保留输入、筛选和滚动状态。
- 纵向滚动与子组件的横向手势保持各自职责。消费方通过空回调禁用切换，并按工作流控制提交期间的交互。
- 加载、空态和错误态保留页头与路由返回入口。表单提交操作使用 `AppHeaderTextButton` 表达禁用与加载状态。

### 几何与外观

- 两侧控件距屏幕边缘 16dp，与内容水平边距一致；页头位于正文留白和最大宽度约束之外。
- 默认布局中，标题与整组核心控件相对整个页头居中，按较宽的一侧对称预留空间，三段垂直居中。
- `singleRow` 布局按左右控件的实际宽度分配空间，核心内容在剩余内容区内居中，三段始终同行；首页使用这一布局，账本长名称在左侧控件内省略。
- 默认布局中的普通长标题在中心可用宽度内单行省略；完整核心控件放不下或中心过窄时独占第二行。
- 经典外观使用不透明背景，控件移除玻璃外壳、高光与投影，Tab 保留纯色轨道和胶囊选中态；经典与玻璃外观保持相同几何与交互。
- 玻璃外观使用全宽 `AppFrostedSurface.background` 与悬浮控件两层表面。背景滤镜独立裁切，控件投影保留在背景层之上，颜色跟随主题。
- 页头背景覆盖顶部安全区，`AppScaffold` 保存顶部边距，`AppPageHeader` 向上绘制背景；控件仍由 `SafeArea` 避让，内容布局尺寸保持一致。
- 玻璃左侧控件使用圆角方形，右侧使用带细分隔线的胶囊操作组；悬浮控件只保留一圈玻璃轮廓，阴影与表面同位。
- 整组 Tab 共用悬浮表面，选中态使用轻底色和主题色文字，不另加高光、描边或投影。
- 页头图标统一使用 24dp 字形，紧凑按钮沿用页头 token，保留 Material 状态、焦点和语义能力；返回图标使用 Remix 图标集。
- 月份切换按钮采用 `compact` 变体，横向占位 28dp、高度 36dp，月份文字不另加水平留白，收紧箭头与月份之间的间距。
- 文本标题使用 18sp、w400，月份文字使用 20sp、w500，Tab 沿用控件字号。
- 一级页签的页头保持吸顶，保证常用控制与操作入口可访问。

## 表单模块

表单由设计系统基础模块与业务输入模块组合：

- `AppFormSection`：分组标题、说明、表面和字段留白，`trailing` 承载标题同行操作。
- `AppPlainFormRow`：左右或上下布局的标签、必填标识、辅助说明、错误与禁用状态；上下布局的说明与错误沿输入区左侧对齐。
- `AppPlainTextFormRow`、`AppPlainSelectFormRow`：参与 Flutter `Form` 校验的文本输入与选择行。
- `AppPlainSegmentedFormRow`：将分段选择接入校验、禁用与重置。
- `AppPlainChoiceChipFormRow`：将胶囊选择接入标签、禁用和校验，默认使用紧凑尺寸并预留两行选项高度；单行垂直居中，超过预留行数后自然增高。
- `AppPlainTextAreaFormRow`：多行文本，默认左右布局；`AppPlainFormRowLayout.vertical` 使用标签在上、整宽输入区在下的结构，复用主题圆角边框与填充。配置 `maxLength` 时限制长度并显示字数，未配置时不限制、不计数，支持自动聚焦。
- `AppSwitch`、`AppPlainSwitchRow`：紧凑开关及其标签、可选说明与禁用状态，说明缺省时不占空间。
- 金额、账户、分类等业务输入复用对应业务组件，不在页面重复实现解析与选择。

### 视觉与校验

- 通过标题、分组表面、排版和留白建立层级，普通字段之间不插入分隔线。
- 同组字段使用统一最小高度与间距，组间使用更大的留白。
- 编辑值从统一值列起点左对齐，选择指示和开关位于行尾；纯展示详情使用值右对齐。
- 普通字段标签和值使用 15sp，分别沿用 `formLabel`、`formValue`；强调值使用 `formValueEmphasis`，占位文字使用 `onSurfaceVariant`。列表、设置标题与操作文字使用各自语义样式。
- 辅助说明和错误使用 12sp，错误使用 `error` 语义颜色，层级主要通过字重和语义颜色表达。
- 数值与单位作为复合字段布局；并列字段根据窄屏和大字号约束允许纵向排列。
- 标签、辅助说明、错误、禁用和只读状态由基础模块统一表达，消费方不重复配置样式。
- `feature/` 表单页面不直接创建 `TextField`、`TextFormField`、`DropdownButtonFormField` 或 `InputDecoration`；特殊交互由设计系统或业务输入模块提供适配。
- 字段校验接入 Flutter `Form`，页面组合与 ViewModel 的职责遵循 [Feature MVVM 职责边界](../engineering/feature-mvvm.md)。

### 设置行

设置行承载即时配置，与参与提交校验的表单行保持独立：

- `AppSettingsRow` 统一标题、说明、最小高度、水平留白和整行点击，右侧 `child` 只承载配置控件。
- `AppSettingsSwitchRow` 组合设置行与开关，支持整行切换和禁用。
- `AppSettingsSelectRow` 组合设置行、当前值与选择入口。
- 新类型复用 `AppSettingsRow`，不重定义标题、内边距或行高；子控件高度不反向改变设置行的基础高度。
- 设置行不参与 `Form` 校验，不承担字段错误、必填或输入焦点，也不替代弹出菜单项的保持打开与关闭语义。

## 组件示例与验证

示例位于 `lib/design_system/showcase/`，用于验证组件能力，不查询真实业务数据。

- 直接消费已有 token、主题与组件，不复制内部样式。
- 使用本地固定数据和页面内状态，不读取数据库、provider 或业务查询。
- 交互应可操作，并覆盖正常、禁用、加载、错误、空状态中适用的场景。
- 一个示例单元只展示一个组件族，同一组件的不同状态可以并列。
- 统一使用 `AppSurface` 承载示例，通过表面、排版和留白表达层级；嵌套卡片时保留可区分的预览背景或边界。
- 基础组件使用通用文案，业务组件使用对应领域语言。
- 新增稳定组件或视觉语义时，补充对应示例与有意义的 widget test；验证窄屏、大字号与交互状态。
