# 组件与表单

本文档定义基础组件、业务组件、表单模块和组件示例页的职责边界。总体入口见 [05. 设计系统](../05.%20设计系统.md)。

## 基础组件层

基础组件放在 `lib/design_system/widget/`，只表达通用 UI 能力，不包含财务业务含义。

新增基础组件前先扫描 `lib/design_system/widget/` 下已有实现，避免重复造轮子。

允许：

- `variant`：primary / outline / text 等。
- `size`：small / medium / large 等。
- `tone`：info / success / warning / danger 等通用状态。
- `state`：loading / disabled / selected 等。

禁止：

- 禁止出现 `IncomeButton`、`ExpenseBadge`、`AssetCard` 这类业务命名。
- 禁止在基础组件内部按账户类型、交易用途等业务字段改样式。
- 禁止在基础组件内部重新定义视觉 token。

`AppPopupMenuButton` 统一承载紧凑图标触发的弹出菜单。菜单项按交互语义声明：`AppPopupMenuAction` 执行命令后关闭菜单；`AppPopupMenuToggle`、`AppPopupMenuChoice`、`AppPopupMenuSelect` 和 `AppPopupMenuControl` 修改配置后保持菜单打开。页面只提供业务状态与回调，不自行处理菜单关闭或浮层内即时状态。

`AppSelectMenu` 统一承载选项查找、菜单渲染、当前选中态和变更回调；独立 Select 默认使用自适应锚定菜单，由 `AppDropdown`、`AppSettingsSelectRow` 分别提供左对齐和右对齐的触发器布局。`AppPopupMenuSelect` 属于嵌套菜单适配器，保留父菜单不关闭的交互语义，不复用独立 Select 的浮层定位。表单选择行仍由表单模块负责校验与外部选择流程，不直接复用设置行。

## 业务组件层

业务组件放在 `lib/feature/<feature>/widget/` 或 `lib/widget/business/`，用于沉淀财务领域的稳定表达。

`lib/widget/business/` 只放可渲染的业务组件，以及这些组件直接消费的轻量视觉语义类型。页面展示构建、查询辅助、跨页面 presentation helper 放在 `lib/feature/shared/presentation/`，避免业务组件目录变成页面数据适配的收纳目录。

典型组件：

- `MoneyText`：金额展示，统一正负号、颜色和格式。
- `MoneyInput`：金额输入，统一分位、小数、负数和校验反馈。
- `TransactionPurposeBadge`：交易用途标识。
- `AccountTypeTag`：账户类型标签。

同类表达在 2 个以上页面重复出现时，应优先抽为业务组件。

## 页面头部

所有页面的头部由 `AppPageHeader` 单独承载，页面不再使用 `AppBar` 或 `SliverAppBar`。页头分返回、标题、操作三段，页面只声明业务内容，几何与控件规格由组件收口。

结构规则：

- 标题为文本时使用 `AppPageHeader`，副标题用于补充页面上下文，不承载操作或状态。
- 标题位需要放置月份选择器、周期选择器或页签时使用 `AppPageHeader.custom`，其余段落保持一致。
- 返回键按当前路由能否返回自动出现：一级 tab 页不显示，二级页显示。页面只在需要抑制返回键或接管返回动作（例如离开前确认）时显式配置。
- 操作区主要放 `AppHeaderIconButton` 和 `AppPopupMenuButton`；页面不设置 `iconSize`、`constraints`、`visualDensity` 等尺寸参数。
- 同一页面的头部图标操作控制在 3 个以内，其余操作收进 `AppPopupMenuButton`。

几何规则：

- 页头文字与图标字形距屏幕边缘的光学间距固定为 16，与页面内容水平边距一致；图标按钮贴边时用触控盒留白抵消，对齐的是字形而不是触控盒。
- 页面内容水平边距统一使用 16，不再混用 20。
- 头部图标统一 24 字形、48 触控盒；深浅、禁用和悬浮状态由 Material 状态层表达。
- 一级 tab 页的头部吸顶，不随内容滚动，保证筛选、新建和菜单入口常驻。
- 返回图标使用 Remix 图标集，不引入 Material 或 Cupertino 的返回隐喻。

表单录入页的头部是唯一例外：记账、账户、分类等表单页需要居中的工作流标题和带文字的“保存”主操作，可保留自有头部布局（居中标题、主操作按钮），但必须复用页头几何与控件规格——返回图标、`appHeaderIconButtonStyle` 和 `AppHeaderTokens`，不得自定义 `iconSize`、`constraints` 或返回图标。

## 表单模块

表单使用“设计系统基础模块 + 业务输入模块”两层 seam：

- `AppFormSection`：表单分组标题、说明、表面和字段间留白。
- `AppPlainFormRow`：行式字段的标签、必填标识、辅助信息、错误信息和禁用状态。
- `AppPlainTextFormRow`：参与 Flutter `Form` 校验的文本输入行。
- `AppPlainSelectFormRow`：参与 Flutter `Form` 校验的整行选择字段。
- `AppSwitch`：紧凑视觉的通用开关，保留 Material 状态、语义与至少 48dp 触控目标。
- `AppPlainSwitchRow`：开关行的名称、可选描述和禁用状态；描述缺省时不占据布局空间。
- `MoneyPlainFormRow`：金额格式、金额校验和数字输入规则。
- 账户、分类、交易金额面板等带业务语义的输入保留在 `lib/widget/business/`。

### 表单视觉规则

- 页面通过标题、分组表面、排版和留白建立层级，不在普通字段之间插入 `Divider`。
- 同一分组内的字段使用统一最小高度和间距；不同分组使用更大的 section gap。
- 编辑表单的文字、数字和选择值从统一值列起点左对齐，选择指示和开关停在行尾；纯展示详情继续使用值右对齐。
- 普通字段标签使用 14sp，字段值使用 15sp，辅助说明和错误使用 12sp；层级主要通过颜色和字重表达。
- 数值加单位属于一个复合字段，在值列内横向布局；出账日与还款日等并列字段使用各自带标签的等宽双列，窄屏或大字号时允许纵向排列。
- 标签、辅助信息、错误、禁用和只读状态由表单基础模块统一表达，页面不重复配置样式。
- `feature/` 表单页面不直接创建 `TextField`、`TextFormField`、`DropdownButtonFormField` 或 `InputDecoration`；需要特殊交互时，在设计系统或明确的业务输入模块中提供 adapter。
- 金额、账户和日期等字段的解析、校验和选择行为必须复用现有输入模块，不在页面复制。

### 设置行与弹层

设置页使用独立的即时配置行：

- `AppSettingsSwitchRow`：标题和说明在左，开关在右，支持整行切换与禁用态。
- `AppSettingsSelectRow`：标题和说明在左，当前值与右箭头在右，点击整行打开 Select 菜单。
- 设置行不替代表单行：它不参与 `Form` 校验，也不承载错误、必填或输入焦点状态。
- 设置行不替代弹出菜单项：`AppPopupMenuToggle`、`AppPopupMenuChoice` 和 `AppPopupMenuSelect` 继续负责菜单保持打开、关闭和嵌套选择等菜单语义。

Modal Bottom Sheet 只是页面容器，应按内部工作流选择表单行、设置行或紧凑 Select，不因处于弹层而新增一套控件。

## 组件示例页

组件示例页位于 `lib/design_system/showcase/`，通过路由 `/dev/design-system` 访问，并在“我的 → 开发工具”中提供入口，所有构建均可用。

当前只提供手机单栏布局，页面结构为“标题 → 搜索 → 横向分类 → 示例单元”。分类固定为：

- 设计基础
- 基础控件
- 表单与输入
- 选择器与弹层
- 反馈与状态
- 布局与容器
- 数据展示
- 财务表达
- 业务图标
- 交易与列表

约束：

- 示例必须直接消费现有 token、主题、基础组件和业务组件，不复制组件内部样式。
- 示例使用本地固定数据和页面内状态，不读取数据库、Provider 或业务查询。
- 交互组件应可实际操作，并至少覆盖正常、禁用、加载、错误或空状态中的适用状态。
- 横向分类使用页签语义，不把每个分类渲染成相互独立的按钮或 Chip。
- 一个示例单元只展示一个组件族；同一组件的不同状态可以并列展示，不把无关组件拼装在同一个单元中。
- 示例单元使用统一的 `AppSurface` 卡片承载一个组件族，通过白色表面、柔和阴影、标题、组件名和留白建立整体感。
- 展示卡片类组件时，应在示例卡片内提供可区分的预览背景或边界，避免同色卡片嵌套后层级不清。
- 基础组件示例使用“主要按钮”“加载状态”“卡片标题”等通用组件或状态文案；业务组件才使用对应领域语言。
- 新增稳定组件或视觉语义时，同步补充对应示例和 widget test。
