# 组件清单

本文档是 SmartFlow 组件治理的当前基线，规则见 [组件治理](组件治理.md)。清单记录稳定共享组件和已发现的重复候选；源码、测试和组件示例仍是最终事实来源。

## 基线信息

- 核对日期：2026-10-19
- 基线提交：`7a21e7f0`
- 统计范围：`lib/`，排除 `*.g.dart` 和 `*.freezed.dart`
- 代码规模：约 677 个 Dart 文件，其中 55 个生成文件
- Widget 类：约 492 个，其中约 296 个为私有类
- 分层分布：`feature/` 约 343 个，`widget/` 约 73 个，`design_system/` 约 72 个

按类名统计的组件结构约包括 59 个 Row、28 个 Section、26 个 Card、15 个 Header、11 个 Summary、8 个 Badge。该统计只用于定位候选，不等于重复数量。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| stable | 契约和消费场景稳定，继续复用 |
| watch | 已有相似实现或边界风险，需要后续复核 |
| merge-candidate | 已确认存在重复或明显分化，等待子 Issue 处理 |
| deprecated | 不再新增使用，等待迁移后删除 |

| ID | 组件族 | 结果 |

| CG-003 | 列表分隔线与辅助信息 | 账单和账户列表统一使用 `AppListDivider` 与 `AppSupportingItems`；通用 `AppSupportingText` 取代两套重复 presentation 类型；现金流纵向分隔线保留独立实现 |

## 当前结论

- 设计系统已有较高的基础组件采用率，主要问题不是缺少所有组件，而是覆盖面不均、语义契约不稳定和缺少持续发现机制。
- 状态标签、详情操作按钮、列表辅助结构、状态透明度和财务 summary row 已完成统一，后续优先处理空状态和 section 容器。
- 防回归仍以文档规则和现有测试为主；暂不引入额外的静态扫描或 PR 流程门禁。
- 页面私有组件密度是组件边界风险，不代表每个私有类都需要提升为公共组件。
