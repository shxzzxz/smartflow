# 编码与演进规则

本文档定义视觉值的消费边界、允许的迁移例外和设计系统演进规则。总体入口见 [05. 设计系统](../05.%20设计系统.md)。

## 编码规则

新增视觉值只能来自：

1. token 源层定义的常量。
2. 主题映射层暴露的 `ColorScheme`、`TextTheme`、`ThemeExtension`。
3. 基础组件或业务组件暴露的变体。

明确禁止：

- 在 widget 中新增长期存在的原始色值。
- 在页面层临时定义财务颜色、状态颜色或图表色。
- 在基础组件中写入财务业务判断。
- 在业务组件或页面中重新定义底层 token。

允许的临时例外：

- 历史 widget 中尚未迁移的原始样式。
- 第三方组件必须覆盖样式时，应优先封装统一适配层。
- 修复业务问题时，未触及区域可以暂不顺手重构。

原则：可以保留存量，不可以新增同类债务。

## 演进规则

- 新增页面优先复用已有基础组件和业务组件。
- 新增财务视觉语义前，先补充本规范和 `ThemeExtension`。
- 高频重复模式先进入 `lib/feature/<feature>/widget/`，跨 feature 复用后迁移到 `lib/widget/business/`。
- 完整 B 级阶段继续补充 `custom_lint` 或静态扫描，限制原始色值和 token 越层消费。
