# 发布流程

SmartFlow 使用 GitHub Actions 构建 Android APK、创建 GitHub Release，并通过 GitHub Pages 发布应用内更新清单。

## 发布入口

- APK 托管在 GitHub Release assets。
- 更新清单托管在 GitHub Pages：
  - `https://shxzzxz.github.io/smartflow/update-stable.json`
  - `https://shxzzxz.github.io/smartflow/update-beta.json`
  - `https://shxzzxz.github.io/smartflow/update-dev.json`
- 应用默认从 GitHub Pages 读取 `update-{channel}.json`。

## Tag 规则

- `v1.2.3-dev.1`：创建 prerelease，更新 `dev` 清单。
- `v1.2.3-beta.1`：创建 prerelease，更新 `beta` 和 `dev` 清单。
- `v1.2.3`：创建正式 release，更新 `stable`、`beta` 和 `dev` 清单。

tag 版本号必须与 `pubspec.yaml` 的 `version` 名称一致。例如：

```yaml
version: 0.2.0-beta.1+20
```

对应 tag：

```text
v0.2.0-beta.1
```

`+20` 是 Flutter/Android 构建输入的基础构建号。使用 ABI 分包时，Flutter 会为每个分包生成真实 Android `versionCode`，例如 `arm64-v8a` 会在基础值上加 ABI 偏移。发布清单会记录每个分包的真实 `androidVersionCode`，应用内更新按当前设备匹配分包的 `androidVersionCode` 判断是否可覆盖安装。

## GitHub 配置

首次启用前，需要在 GitHub 仓库里完成这些配置。

### Actions 权限

进入 `Settings > Actions > General > Workflow permissions`：

- 选择 `Read and write permissions`
- 勾选 `Allow GitHub Actions to create and approve pull requests` 不是必需项

### Pages

进入 `Settings > Pages`：

- Source 选择 `GitHub Actions`

### Android 签名 Secrets

进入 `Settings > Secrets and variables > Actions`，添加：

- `SMARTFLOW_ANDROID_KEYSTORE_BASE64`
- `SMARTFLOW_ANDROID_KEYSTORE_PASSWORD`
- `SMARTFLOW_ANDROID_KEY_PASSWORD`
- `SMARTFLOW_ANDROID_KEY_ALIAS`

`SMARTFLOW_ANDROID_KEYSTORE_BASE64` 是 release keystore 文件的 base64 内容。Windows PowerShell 可用：

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("android\smartflow-release.jks"))
```

CI 构建出来的 APK 必须使用与已安装版本相同的签名证书，否则 Android 会拒绝覆盖安装。

## 发布产物

每次发布会上传：

- 通用 APK：`smartflow-{version}.apk`
- ABI 分包：
  - `smartflow-{version}-arm64-v8a.apk`
  - `smartflow-{version}-armeabi-v7a.apk`
  - `smartflow-{version}-x86_64.apk`

更新清单会写入 `universalApk` 和 `apks` 分包列表：

- `universalApk` 仅作为 GitHub Release 的人工下载资产信息。
- `apks` 是应用内自动更新候选包，必须包含每个 ABI 分包的真实 `androidVersionCode`。
- 应用内自动更新只选择当前设备支持的匹配 ABI 分包；找不到匹配分包时不回退到通用 APK。
