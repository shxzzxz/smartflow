# 信贷域数据模型

本文描述信贷域的表、字段语义与关键约束。金额字段一律以基础币种最小单位（分）整数存储；每表含 `created_at`、`updated_at`。遵循项目约束：**不使用数据库外键**，表间引用为逻辑引用，由应用层维护一致性。

时间归属说明：交易以账务核心 `transactions.posted_at` 的日期部分作为**入账日期**参与周期归属；交易时间 `occurred_at` 不决定账单周期。

## 1. 账户侧

### 1.1 credit_liability_accounts

信贷域自有的账户扩展表，每个信贷账户（信用 / 贷款）一行。

```text
credit_liability_accounts
- account_id              账务核心账户 id，唯一
- kind                    账户类型：CREDIT 信用账户 / LOAN 贷款账户；与账务账户 account_profile_key（credit.credit / credit.loan）一一对应
- credit_limit_minor      授信额度；可空（贷款账户如借呗也可填）
- billing_day             出账日 day-of-month，1–28；仅信用账户，贷款账户为空
- repayment_day           还款日 day-of-month，1–28；仅信用账户
- billing_day_to_next     出账日当天交易计入下一期（默认 true）；仅信用账户
```

要点：

- `credit_limit_minor` / `billing_day` / `repayment_day` 由本表持有，账务核心 `accounts` 同名字段进入**迁出过渡**，读写收口信贷域接口。
- 出账日 / 还款日只开放 1–28（回避月末日期边界）；**修改自下一张账单生效**，已出账与当前 OPEN 账单不动。
- 信贷账户创建 / 编辑由信贷域接口编排（账务核心建账 + 本表扩展行）。
- `kind` 建户时由调用方（前端按所选画像）直接传入并落库、之后不变；与 `account_profile_key`（`credit.credit` / `credit.loan`）一一对应，但不由其反推。信贷域内以本列判信用 / 贷款。

## 2. 借据侧

本节 §2.1–2.2 描述合同与计划主表；分期产品和阶段配置见 §2.3。schema v33 起，阶段配置是计算条款的唯一来源，合同主表仅保存合同整体信息；总期数、首末还款日和总手续费由阶段条款派生。

### 2.1 installment_contracts

分期合同主表。只在有多期还款计划时存在；消费信贷无合同。

```text
installment_contracts
- id
- product_id                  来源产品逻辑引用，可空
- product_name                创建时产品名称快照，可空
- custom_rules                本笔结构与规则的编辑开关
- day_count / rounding / tail_difference  整份计划计算约定
- liability_account_id        挂载的负债账户 id（信用 / 贷款账户均可）
- source_type                 DISBURSEMENT 放款类 / BILL_CONVERSION 账单转换类
- source_repayment_id         BILL_CONVERSION 非空：回指创建它的分期还款记录；DISBURSEMENT 为空
- disbursement_account_id     放款入账资产账户 id；DISBURSEMENT 且建放款交易时非空，迁移不建交易时为空
- disbursement_transaction_id 放款交易 id；与 disbursement_account_id 同空 / 同非空
- principal_minor             合同本金（BILL_CONVERSION = Σ 分期还款分摊本金）
- borrowing_date              借款日 / 合同起算日（物理列 start_date）
- status                      ACTIVE 进行中 / SETTLED 全部计划已核销或跳过
- note
```

要点：

- **期次节奏由挂载账户类型决定**：挂信用账户的合同（账单分期、现金分期）期次由系统按账期生成，首期 = 下一个出账周期；挂贷款账户的合同期次按合同条款（允许末期对齐整年、季供等不规则日期）。
- **产品标签派生不落库**：DISBURSEMENT + 贷款账户 = 贷款分期；DISBURSEMENT + 信用账户 = **现金分期**；BILL_CONVERSION = 账单分期。
- 还款方式、利率、计息、手续费、期数及还款日期只保存于合同所属阶段。合同加载必须取得完整阶段配置，缺失时明确报错，不从主表或计划反推条款；计划只在显式重算时按条款重新生成。
- 金融条款不变量由阶段条款校验：手续费和利率非负，利率值与单位共同构成利率；创建和编辑均提交完整阶段条款，不再提供主表单字段金融参数修改协议。
- `DISBURSEMENT`：放款双字段**同空**（迁移，不建放款交易）**或同非空**。`BILL_CONVERSION`：放款双字段必空、`source_repayment_id` 必非空，合同创建不写账务交易。

### 2.2 installment_schedules

还款计划——借据侧的**前瞻真相**，表达"未来打算怎么还"。

```text
installment_schedules
- id
- contract_id
- stage_id                    所属合同阶段配置 id，逻辑引用；旧库升级时回填
- period_no                   期序号，从 1 起；(contract_id, period_no) 唯一
- expected_repayment_date     预期还款日
- expected_principal_minor    预期本金
- expected_interest_minor     预期利息
- expected_fee_minor          预期手续费
- status                      PENDING 待还 / PARTIALLY_PAID 部分已还 / PAID 已核销 / SKIPPED 跳过
- note
```

约束与语义：

- 仅 `PENDING` 行可编辑金额 / 日期、移动或跳过；`PARTIALLY_PAID` / `PAID` / `SKIPPED` 均不可编辑。只有 `SKIPPED` 可恢复为 `PENDING`。
- `SKIPPED` 期次不进账单（用于迁移已还期次等人工跳过场景），可撤销回 `PENDING`。提前还款不会自动跳过期次。
- 合同状态校验以关联账单明细上的有效还款分摊为事实来源重判非 `SKIPPED` 状态；`SKIPPED` 永不自动修改。异常或缺失引用只报告，不作为核销事实。
- 计划日期按 `period_no` 严格递增。重算只作用于重算锚点之后的连续待还尾部，计息起点取锚点期次的计划日期；首次生成时第一期取合同借款日（见《业务规则》§6.2）。
- 计划行不参与账户余额或统计口径；账单明细是计划期次的只读投影，对账接点见 §3.2。

### 2.3 分期产品与阶段配置

分期产品保存可复用的阶段结构和计算规则，分期合同保存本笔贷款的完整条款，还款计划保存具体期次及其状态。用户从“我的”页面管理产品，新建贷款分期时选择产品并填写本笔参数。

#### 表关系与归属

- 新增分期产品表 `installment_products`，保存产品身份、名称和整份计划的计算约定。
- 新增分期阶段配置表 `installment_stage_configs`，每个阶段单独一行；产品和合同分别对应多条阶段配置。
- 阶段配置以 `id` 标识身份，以 `owner_type`（产品 / 合同）、`owner_id` 标识归属，以 `position` 表达顺序；`(owner_type, owner_id, position)` 唯一。
- 产品与合同共用表结构，各自拥有独立配置行。创建合同时复制产品规则并补齐本笔参数；修改产品不改写既有合同，合同编辑与重算使用合同自己的条款。
- 合同主表保留账户、本金、借款日等整体信息；各阶段的还款方式、利率、期数等迁入阶段配置。标准天数、舍入方式与尾差处理仍是整份计划的计算约定，由产品持有并复制到合同，不在每个阶段重复保存。
- 计划行记录所属合同阶段的稳定标识，阶段归属随期次保存；免还阶段不产生期次。
- 表间均为逻辑引用，不使用数据库外键；引用存在性及跨表一致性由应用层维护。

#### 稳定规则与本笔参数

| 信息 | 产品阶段 | 合同阶段 |
| --- | --- | --- |
| 阶段类型、顺序 | 保存 | 从产品复制 |
| 还款方式 | 保存适用值 | 从产品复制 |
| 各期间隔 | 保存适用值，例如 1 个月或 12 个月 | 从产品复制 |
| 利率单位、计息方式 | 保存适用值 | 从产品复制 |
| 固定额算法 | 等额本息阶段保存 | 从产品复制 |
| 期数 | 不保存 | 按本笔确定 |
| 利率值 | 不保存 | 按本笔确定 |
| 期末本金信息 | 不保存金额、比例或保留本金配置 | 按本笔确定 |
| 指定固定额 | 不保存 | 使用指定固定额算法时填写 |
| 手续费配置 | 不保存 | 按本笔确定 |
| 具体阶段日期 | 不保存首期、末期还款日、免还结束日、计息起点等日期信息 | 按本笔确定 |

产品也不保存本笔参数的默认值、占位输入或填写模式。新建合同的填写项由阶段类型、还款方式及计算规则决定，无需通用的“固定值 / 待填写 / 默认值”配置机制。期数与各期间隔不同：前者属于本笔贷款，后者表达产品的还款节奏。

产品可以选择“指定固定额”算法，但不保存具体金额；可以选择“一次性手续费”还款方式，但不保存手续费配置。期末本金的缺省行为沿用阶段位置与还款方式的既有规则，例如非末阶段先息后本缺省承接全部期初本金；需要显式指定时在合同中填写。

#### 本笔贷款的自定义开关

选择产品后，默认使用复制到本笔合同的阶段结构和计算规则。用户始终可以填写本笔本金、期数、利率值、日期及其他适用参数。

- 通过“自定义本笔贷款”开关进入可修改阶段结构与计算规则的状态；开关默认关闭。
- 开启时以当前本笔配置为起点，允许增删、排序阶段及修改适用计算规则，修改仅作用于本笔合同，不回写产品。
- 开关控制结构与规则的编辑状态，不改变合同持有独立阶段配置的存储关系；已有合同的编辑仍受历史期次与还款状态约束。
- 关闭开关保留本笔修改，只锁定阶段结构与计算规则的编辑；合同参数仍可填写。

#### 不同阶段的字段差异与校验

阶段配置采用类型标识、明确的可空列及按类型校验：`stage_kind` 区分免还阶段与还款阶段，`repayment_method` 区分还款方式。领域模型继续通过不同阶段类型和专用值类型表达有效配置，持久化为同一张表不要求领域对象也包含全部可空属性。

- 产品行只保存稳定规则，本笔参数列必须为空。
- 合同行补齐适用于本阶段的实际参数。不适用的字段必须为空，例如免还阶段不带还款方式和利率参数，非等额本息阶段不带固定额算法及指定固定额。
- 选择指定固定额算法的合同行必须有有效金额；一次性手续费阶段只表达一次还款，不保存无意义的多期与计息参数。
- 切换阶段类型或还款方式时清除不再适用的字段，保存时重新校验，不能只通过页面隐藏字段保证有效性。
- 产品完整性与合同完整性分别校验：产品阶段结构和规则合法即可保存；合同必须补齐必要参数，通过日期递增、本金衔接和计划计算校验。
- 产品行缺少利率值不表示免息，也不能将现有合同的“利率单位与数值同空或同非空”约束直接套到产品行。产品阶段必须先转换为有效合同条款，才能交给还款计划引擎。
- 简单行内不变量可使用数据库 `CHECK`；跨阶段约束由领域层校验，聚合保存由应用层保证原子性。

例如，助学贷款产品保存免还、先息后本、本金摊还三个有序阶段的规则。创建合同后保存另外三条归属合同的配置，免还结束日、实际利率、各阶段期数等由本笔贷款确定。

#### 多阶段提前还款重算

多阶段沿用单阶段的重算锚点、冻结期次和剩余本金计算规则，将锚点之后的连续待还尾部按合同原有阶段组织后，交给同一还款计划引擎顺序计算。

例如三阶段贷款在阶段 2 中间提前还款，且重算锚点仍位于阶段 2：阶段 1 和阶段 2 不晚于锚点的期次冻结，重算阶段 2 的尾部及完整阶段 3。阶段 3 的期初本金承接阶段 2 重算后的期末本金，各阶段继续使用自己的还款方式、利率和计算约定。具体行为见[业务规则 §6.3.1](业务规则.md#631-多阶段重算)。

若阶段原指定期末本金超过重算后的期初本金，本次计算的期末本金取期初本金，当前阶段待重算部分的本金分摊为 0，余额继续传递到下一阶段，利息与手续费仍按本阶段条款计算。该调整只作用于重算输入，合同原指定值保留，以便提前还款修改或删除后重新计算；末阶段气球贷仍在末期归还调整后的余额。

#### 迁移与备份

- schema v32 增加产品表与阶段配置表，合同增加来源产品、名称快照、自定义开关与计算约定，计划增加 `stage_id`。
- 旧合同按原有参数回填一条合同阶段配置，沿用 30/360、四舍五入与动态实际期利率固定额算法；原来未持久化的指定固定额不根据计划猜测回填。既有计划身份、日期、金额和状态保持不变。
- schema v33 在同一迁移事务中完成旧阶段回填、删除主表旧列和重建索引。v32 已有阶段条款原样保留，不以主表旧摘要覆盖；其后的合同读写只使用阶段配置。旧版多期一次性手续费配置迁为等额本金免息加手续费，保持原计算语义。
- 新备份格式版本为 3，合同行不再包含阶段参数。格式 1 的旧单阶段快照在导入入口补齐阶段；格式 2 的已有阶段快照保留其阶段，并移除主表旧字段。升级后的完整快照经过阶段归属、产品禁止字段、计算规则及计划关联校验后恢复；运行时无旧字段回退。
- 阶段结构或期数改变后，保存前必须显式预览重算；重算不允许移除或移动冻结期次的阶段归属。产品已有合同引用时只允许归档，未使用产品可以删除。

## 3. 还款侧

### 3.1 bills

账单——还款侧聚合，按 `(账户, 周期)` 唯一，是用户还款的统一目标。

```text
bills
- id
- account_id            所属负债账户 id
- period                账单期 YYYYMM；与 account_id 构成唯一身份与生成幂等键
- start_date            周期起算日（消费窗口下界）；仅信用账户，贷款账单为空
- billing_date          出账日（消费窗口上界）；仅信用账户
- repayment_date        还款日（到期日）；仅信用账户；贷款账单读侧取明细最早日期
- status                OPEN 累积中 / BILLED 已出账待还（含部分已还）/ SETTLED 已了结
```

约束与语义：

- **信用账户（周期驱动）**：消费窗口 = `[start_date, billing_date)`，出账日当天交易归属由 `billing_day_to_next` 决定（默认下期）。**窗口链式衔接**：新账单 `start_date` = 上一张 `billing_date`（首张按锚点回推），改出账日不破坏连续性。
- **贷款账户（合同驱动）**：只生成当期账单，`period` = 当前 YYYYMM；同月多合同期次合并，三个日期字段为空；空账单也生成，不预生成下一期。
- `status` 是明细状态的**事务内维护投影**，不变量 **`SETTLED ⟺ 无 PENDING / PARTIALLY_PAID 明细`**；`SETTLED` 只由非 `OPEN` 账单投影而来，还款更正可回退。
- 了结性质（纯现金 / 含分期还款 / 含跳过）从还款明细形态与明细状态派生，不细分账单状态。

### 3.2 bill_generation_suppressions

```text
account_id            账户 ID；与 period 构成主键，不使用外键
period                账单期 YYYYMM
created_at            用户删除账单并抑制自动重建的时间
```

- 该表记录用户对自动生成的否定意图，不是账单软删除或账务事实。
- Task 命中抑制记录时不创建对应账期；显式补建会清除记录。

### 3.3 bill_items

账单明细——账单内每条应还来源，是与合同对账的接点。**只读投影：不可编辑，修正作用于来源。**

```text
bill_items
- id
- bill_id
- item_type                 CONSUMPTION 消费 / INSTALLMENT 分期
- contract_id               分期明细非空；消费明细为空
- schedule_id               分期明细非空，指向来源计划期次
- repayment_date            还款日期冻结副本：信用账户 = 账单还款日；贷款 = 期次真实日期
- expected_principal_minor  应还本金
- expected_interest_minor   应还利息
- expected_fee_minor        应还手续费
- status                    PENDING 待还 / PARTIALLY_PAID 部分已还 / PAID 已核销 / SKIPPED 跳过
```

约束与语义：

- **分期明细：一条明细 = 一个 (合同, 期次)**，同一张账单内一个合同最多一条；细分标签（贷款 / 账单 / 现金分期）由合同派生。**消费明细：一张账单一条聚合明细**，金额 = 消费净额（口径见《业务规则》），利息 / 手续费为 0；逐笔消费留在账务流水，不逐笔建明细。
- **已还金额不存**，派生 = Σ `repayment_items`（按分项）。
- **状态判定**：存在应还金额且无还款明细引用 = `PENDING`；完全无应还金额的占位明细 = `PAID`；存在引用且 `Σ 分摊本金 < 应还本金` = `PARTIALLY_PAID`；`Σ 分摊本金 ≥ 应还本金` = `PAID`。利息 / 手续费不阻塞核销；超额分摊允许。
- 逾期判定按明细 `repayment_date`（明细级），账单级聚合展示。
- 账单刷新是**替换来源投影**：刷新后该账单的明细集合等于当前来源投影，旧的 stale 明细被移除。同一账单内来源仍存在时复用明细 id；期次跨账期后旧、新账单使用不同物理明细和 id，允许在旧账单刷新前短暂并存。

### 3.4 repayments

还款记录——一次还款动作一行。**不存金额**——金额 = Σ 还款明细分项。每笔还款自身持有还款时间；有交易时由信贷用例同步维护关联交易的交易时间，还款账户从关联的当前交易派生。

```text
repayments
- id
- repayment_type     BILL 账单还款 / INSTALLMENT 分期还款 / PREPAYMENT 提前还款
                     / UNATTRIBUTED 未归属还款
- target_type        BILL 账单 / CONTRACT 合同 / ACCOUNT 账户
- target_id
- transaction_id      关联稳定的 DEBT_REPAYMENT 交易 ID；`BILL` / `PREPAYMENT` 可空，`INSTALLMENT` 必空，`UNATTRIBUTED` 必非空
- repayment_date      还款时间；所有还款必填，包含时分秒，与关联交易的 occurred_at 一致
```

约束：

- `BILL` / `INSTALLMENT` ⟺ `target_type = BILL`；`PREPAYMENT` ⟺ `CONTRACT`；`UNATTRIBUTED` ⟺ `ACCOUNT`。
- `repayment_date` 始终非空，读侧统一读取还款记录。创建有交易还款时使用同一个时间写入两侧；修改关联交易时间时，由信贷应用用例在同一数据库事务内同步更新两侧，任一步失败则整体回滚。
- 存量数据升级时，有交易还款从关联交易的 `occurred_at` 回填；无可用关联交易时保留已有还款时间，仍缺失时间的历史记录使用 `created_at` 兜底。
- `INSTALLMENT` 必无交易（`transaction_id` 空），且被一个 `BILL_CONVERSION` 合同的 `source_repayment_id` 回指。
- `UNATTRIBUTED` 必须生成还款交易（`transaction_id` 非空），记录通过账户交易读取与管理。
- 交易修改保持 ID 不变，因此还款记录无需在修改交易时重写引用。

### 3.5 repayment_items

还款明细——所有还款形态的**统一金额载体**。

```text
repayment_items
- id
- repayment_id
- bill_item_id                账单级形态（BILL / INSTALLMENT）非空 = 分摊到账单明细；
                              合同 / 账户级形态为空 = 单条金额行
- allocated_principal_minor   本金
- allocated_interest_minor    利息
- allocated_fee_minor         手续费
- allocated_discount_minor    优惠
```

约束（写入时校验）：

- 有交易时，同一 `repayment_id` 下各分项之和 = 该还款交易在账务核心的对应分项之和；无交易还款跳过该校验。
- `INSTALLMENT` 只允许分摊到消费明细（不支持分期的分期）。

## 4. 对账关系与派生口径

```text
还款交易(DEBT_REPAYMENT) ──根id── repayments ──▶ repayment_items ──▶ bill_items ──▶ schedule 期次 ──▶ contract
（可空：无交易还款）                                  （bill_item_id 可空：合同/账户级）
```

- **未归属欠款**（账户级派生桶）= 账户负债余额 − Σ 合同 `PENDING/PARTIALLY_PAID` 计划行剩余本金 − Σ 账单消费明细剩余本金。差额定义天然兜底期初欠款、余额调整和待刷新差额；刷新后差额迁入账单应还。为负表示溢缴。
- **可用额度** = `credit_limit_minor` − 账户负债余额（余额由 entries 实时累计）。
- **IRR / APR / EAR（合同维度）**：现金流只由合同本金与全部状态（含 `SKIPPED`）的计划预期金额派生，不读取实际还款事实。全部计划本金精确守恒、现金流充分且存在利率解时计算。
- 账单列表、详情与债务桶按多个 `bill_item_id` 一次批量聚合还款分项，避免逐明细查询。
