# 信贷域设计

本文是信贷域的概览与导航，定义域的定位、边界、两类账户、核心概念与聚合关系。表结构、业务规则、场景示例拆分到同目录的子文档。

## 1. 定位与边界

信贷域在账务核心的**借入 / 还款**能力之上，管理负债履约：借款、分期、合同、还款计划、账单、还款。它不表达账务事实，也不改变分录借贷平衡或收支统计口径。

SmartFlow 定位为记账类应用，信贷能力以**记录与追踪真实产品已发生 / 将发生的事**为目标，不承担金融计算职责：

- **不**承诺与各家产品（花呗、银行）的还款金额完全一致。系统按标准方式生成初始数据，产品差异由**修正来源（交易、计划）和还款时据实填写**兜底。
- **不**自动计算逾期罚息、节假日顺延；产品实收的年费 / 罚息 / 取现费等记为该账户的交易，自然进入消费净额。
- 用户的还款行为发生在真实产品里，App 只是记录。真实产品保证了"不会超额、不会还未入账的钱"，App 的职责是**让记录向真实账单收敛**。

## 2. 与账务核心的关系

遵循 [ADR-0001](../../adr/0001-业务域划分与账务核心独立性.md)：信贷域消费账务核心能力，账务核心不感知信贷域。

- 沿用账务行为 `BORROWING`、`DEBT_REPAYMENT` 与 `REPAYMENT_PRINCIPAL / REPAYMENT_INTEREST / REPAYMENT_FEE / REPAYMENT_DISCOUNT` 分项。
- **业务归属标记**：放款交易（owner = 合同）、还款交易（owner = 还款记录）打 owner 标记；**消费交易不标记**——消费与账单的关系靠读时重算维系，记账写侧零负担。
- 通用交易 UI 对 owner 标记交易：日期、结算账户、备注**直接可改**（不触碰核销与状态）；**金额性修改与删除**路由到信贷域页面。
- 跨域写侧流程收口在 application 层编排；**信贷账户的创建 / 编辑接口由信贷域提供**（编排账务核心建账 + 信贷扩展行）。

## 3. 两类账户与双轨账单

信贷域只面向负债账户（`account_type = LIABILITY`），按账户画像分两类，账单生成机制分轨：

| 账户类型 | 账户画像 | 典型 | 账单机制 | 账单内容 |
| :--- | :--- | :--- | :--- | :--- |
| 信用账户 | `credit.credit` | 信用卡、花呗 | **周期驱动**：出账日截单，窗口链式衔接 | 消费净额 + 挂载合同期次（账单分期、现金分期） |
| 贷款账户 | `credit.loan` | 借呗、房贷 | **合同驱动**：期次按月归集，无账户级周期参数 | 贷款分期期次（支持不规则、季供） |

两类账户共用同一套合同 / 计划 / 还款模型；**合同的期次节奏由挂载账户类型决定**——挂信用账户的合同期次由系统按账期生成（天然对齐），挂贷款账户的合同期次按合同条款。

## 4. 核心概念与聚合

```text
借据侧（前瞻："未来打算怎么还"）           还款侧（本期："该还多少、已还多少"）
──────────────────────────────          ──────────────────────────────────
分期合同 installment_contracts            账单 bills（按 账户 × 周期 唯一）
   └─ 还款计划 installment_schedules           └─ 账单明细 bill_items（消费 / 分期）
          （N 期预期，可编辑可重算）
                                          还款记录 repayments（一次还款动作）
        提前还款 / 改计划                       └─ 还款明细 repayment_items
        作用在借据侧，重算未来计划                   （金额分项；账单级形态分摊到账单明细）
```

关键设计原则：

1. **账单是统一还款目标。** 用户永远对一张账单还款，不直接对计划期次还款；出账前对本期消费的偿还也是对当期 OPEN 账单的账单还款。
2. **账单是来源的只读投影，落库但不可编辑。** 每条明细记得来源（消费净额 / 某合同某期计划），账户详情展示或用户手动刷新时按来源重算。**修正一律作用于来源**：消费不对改交易，计划不对改计划行。
3. **类型下沉到明细，明细只分两类。** 消费 / 分期；贷款分期、账单分期、现金分期等细分标签由合同与挂载账户派生。
4. **金额与日期的事实在还款明细与交易，可派生的量不存储。** 还款金额 = Σ 还款明细分项；还款日期、还款账户从有效交易派生；明细已还 = Σ 指向它的还款明细；账单状态 = 明细状态投影；欠款分桶读侧派生。
5. **核销以本金为准，且是金额关系的纯函数。** `Σ 分摊本金 ≥ 应还本金 ⟺ 明细 PAID`。任何让两侧金额变化的操作之后重新执行该判定（**状态重判**）；利息 / 手续费据实记录、不阻塞核销；超额分摊允许。

**没有"信用合同"。** 合同 ⟺ 多期还款计划，只在放款分期（贷款分期 / 现金分期）、分期还款（账单分期）时存在。消费信贷在被分期之前没有合同，其偿还走账单还款（出账前挂当期 OPEN 账单）。

## 5. 账单生命周期总览

```text
信用账户：OPEN（周期开始打开，内容跟随来源）
            └─出账日─▶ BILLED（已出账待还，停止自动变化）
                          └─最后一条待还明细核销/跳过─▶ SETTLED
贷款账户：生成即 BILLED ──────────────────────────────▶ SETTLED
```

- 账单状态是明细状态的**事务内投影**，不变量 `SETTLED ⟺ 无 PENDING / PARTIALLY_PAID 明细`；还款更正可使其回退。
- 信用账户出账日是**双重职责日**：冻结上一周期 + 打开下一周期。
- **逾期判定下沉明细级**（按明细冻结的还款日期），账单级只做聚合展示；**逾期不滚动**，未还明细留在所属账单。
- 账单生成由时间驱动 Task 拉取执行（[ADR-0006](../../adr/0006-任务与调度分离的时间驱动生成.md)），幂等键 `(账户, 周期)`；信用账户维护上一已出账与当前 OPEN，贷款账户只生成当期。

## 6. 还款形态总览

| 形态 | 作用对象 | 还款明细 | 账务交易 | 对计划 / 合同的影响 |
| :--- | :--- | :--- | :--- | :--- |
| 账单还款 `BILL`（含本期提前还款） | 账单（OPEN 仅限消费明细） | 分摊到账单明细 | 可有可无 | 明细核销 → 期次 PAID |
| 分期还款 `INSTALLMENT`（账单分期） | BILLED 账单 | 分摊到消费明细 | 无 | 创建账单分期合同 |
| 提前还款 `PREPAYMENT` | 合同 | 单条金额行 | 可有可无 | 只重算发生日之后的 PENDING 计划，不跳过计划，不关闭合同 |
| 未归属还款 `UNATTRIBUTED` | 账户 | 单条金额行 | 可有可无 | 无；偿还未归属欠款 |

- "本期提前还款"不是独立类型：对当前 BILLED 账单做账单还款即是，利息 / 手续费据实填写。
- **所有形态支持不生成账务交易**（导入 / 迁移核销；分期还款天然无交易）。
- 信用账户出账前还消费 → 对当期 OPEN 账单的账单还款（只分摊到消费明细）；还更远未出账期次 → 提前还款；未归属还款只偿还未归属欠款（期初欠款、余额调整等）。
