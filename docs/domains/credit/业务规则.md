# 信贷域业务规则

本文定义信贷域"账户与周期如何组织、账单如何生成与刷新、还款如何记录、状态如何联动"。表结构见《[数据模型](数据模型.md)》，端到端示例见《[业务场景流程示例](业务场景流程示例.md)》。

## 1. 信贷账户与周期

### 1.1 账户参数

- 信贷账户由信贷域接口创建 / 编辑（编排账务核心建账 + `credit_accounts` 扩展行）。
- 信用账户必填出账日、还款日（1–28）；贷款账户无周期参数。
- 出账日 / 还款日**修改自下一张账单生效**：已出账与当前 OPEN 账单保持原窗口，每个 YYYYMM 最多一张账单。

### 1.2 周期归属

- 交易按**入账日期**（本阶段 = `occurred_at` 日期部分）归属周期窗口；出账日当天交易归本期 / 下期由 `billing_day_to_next` 决定（默认下期）。退款同规则（§8）。
- **账单起始期**（仅信用账户）：账单只从该期开始生成，默认 = 建账所在周期，导入迁移时可调。早于起始期的交易不生成账单，净欠款落入未归属欠款（§7）。

### 1.3 账户归档

- 归档**不设前置约束**（归档是展示层概念，不是业务了结）；归档时若存在未结清明细 / 计划，弹确认告知"归档后不再生成新账单"。
- 归档账户停止生成新账单，已有账单 / 合同 / 还款保留，仍可查看与补还款；取消归档后 Task 自动补齐缺失周期。

## 2. 账单生成（双轨）

账单生成是[时间驱动生成（ADR-0006）](../../adr/0006-任务与调度分离的时间驱动生成.md)的一个 **Task**：补齐"截至 `now` 应生成而未生成"的账单，幂等键 `(账户, 周期)`，数据层唯一约束兜底并发，可一次补齐多个错过的周期。调度器不保证准时、不保证只调一次。

### 2.1 信用账户：周期驱动

以出账日 5 号、还款日 25 号为例：

| 时段 | 账单状态 | 内容 |
| :--- | :--- | :--- |
| 上月 05 ~ 本月 04 | OPEN | 分期明细已落库；消费明细落库且**自动跟随**流水变化 |
| 本月 05 出账日 | OPEN → BILLED | 消费明细以当刻消费净额定格；同时打开下一周期账单 |
| 本月 05 ~ 25 | BILLED | 待还，25 到期 |

- 生成范围 `[max(账单起始期, 已生成最大期+1), 当前期]`；出账动作（冻结 + 开新）在补齐逻辑内完成。
- 窗口链式衔接：新账单 `start_date` = 上一张 `billing_date`。

### 2.2 贷款账户：合同驱动

- 该账户全部合同中，预期还款日落在 M 月的非 `SKIPPED` 期次，合并进 `(账户, M)` 账单，**生成即 BILLED**。
- 期次日期完全按合同条款：末期对齐整年、季供、不规则日期均可；没有期次的月份不生成账单。
- 补齐到**当前月 +1**（保留约一个月的提前还本期窗口）；更远期次提前还走提前还本金。

### 2.3 账单状态与了结

- 不变量：**`SETTLED ⟺ 无 PENDING 明细`**；`SETTLED` 只由 `BILLED` 投影而来；每次明细离开 / 回到 `PENDING` 时同事务维护。
- 了结性质按需派生：全部明细经现金核销 = 现金还清；含分期还款分摊 = 转过分期；混合场景看明细。
- **逾期判定明细级**（按明细 `repayment_date`），账单级聚合展示；**逾期不滚动**，未还明细留在所属账单，"总待还"用跨账单聚合视图。

## 3. 账单明细与刷新

### 3.1 消费净额口径

消费明细金额 = 窗口内**使该信用账户负债增加的交易**（普通支出、转账转出 = 取现、报销垫付）− 窗口内入账并命中该账户的退款。

排除：**借款**（已被合同期次覆盖，计入即与现金分期双算）、期初余额、余额调整（落未归属桶）、**还款**（任何形态的还款都不冲减消费净额——出账前对本期消费的偿还挂在当期 OPEN 账单上，作为分摊进入已还，见 §4）。净额为负按 0 出账，差额经余额自然落入未归属桶（溢缴）。

### 3.2 明细不可编辑，修正作用于来源

1. **消费明细不对** → 改交易（补记 / 更正 / 改入账日期）。直接改明细是错的：账单与账户余额会失配。
2. **分期明细不对** → 改还款计划 `PENDING` 行；账单页点击明细跳转合同编辑页。实还与计划差零头同此路径——先改后还、或先还后改再同步，状态重判都会收敛。
3. **利息 / 手续费与实际不同**（提前还本期等） → 还款表单据实填写，核销以本金为准，不需要改账单。

不支持凭空增删明细；导入缺口由未归属欠款 + 无交易还款承接（§7、§10）。

### 3.3 刷新规则与时机

| 时机 | 行为 |
| :--- | :--- |
| OPEN 期间来源变化 | 明细自动跟随（仅信用账户存在 OPEN） |
| 出账日 | 以当刻来源值定格，此后停止自动变化 |
| BILLED 后来源变化 | 不自动改；查询接口返回"与来源不一致"提示 |
| 用户点"同步" | 按来源重算覆盖存储值 |

- **读时惰性重算**：账单查询路径（列表 / 详情 / 还款表单加载）返回前重算 OPEN 账单明细，与存储值不同则回写；出账 Task 执行时强制重算一次定格。BILLED 读时重算仅用于生成不一致提示，不落库。**写侧（记账、改交易、改计划）不感知账单。**
- 计划日期跨月修改的同步 = 明细**改挂目标账单**（保持明细 id 与已有分摊），目标月账单不存在则顺手生成。
- **状态重判**：任何让"应还本金"或"分摊本金"变化的操作（同步、还款、更正、计划修改）之后，重新执行核销判定，明细可 `PAID ↔ PENDING` 互转，账单状态投影联动。

## 4. 账单还款（`BILL`）

针对一张账单，一次可覆盖多条明细；一次还款针对一张账单。贷款账单生成即 `BILLED`；信用账户 `BILLED` 账单可还全部明细，**`OPEN` 账单也可还、但只分摊到消费明细**——"还未出账消费"就是对当期 OPEN 账单的账单还款，出账时明细带着已还进入 `BILLED`（应还 / 已还 / 待还连续），分期期次出账前不经账单还（走提前还本金 / 结清）。

1. 填**还款总额与优惠**（默认），展开可分别填本金 / 利息 / 手续费。
2. 分摊建议：**FIFO（默认）**——分项先手续费、再利息、后本金；明细间先分期、后消费。**均摊**备选。策略只是表单建议层，用户可在网格中任意调整，模型不感知。
3. **超额分摊允许**：建议永不主动超额；用户手动改超出应还时提示但不阻断（据实优先），多还部分经余额落入未归属桶（溢缴）。
4. 落库：1 笔 `DEBT_REPAYMENT` 交易（分项 = Σ 还款明细分项；无交易还款跳过）+ 1 条还款记录 + N 条还款明细。
5. 核销联动：明细分摊本金够数 → `PAID` → 推进期次 `PAID` → 合同全期次 `PAID`/`SKIPPED` → 合同 `SETTLED`；账单无 `PENDING` → `SETTLED`。

**提前还本期**：还款日前对当前 `BILLED` 账单做账单还款，不是独立类型；利息 / 手续费因提前而变少的据实填写，可偏离明细应还，不影响计划。

**部分还**：允许；未够数明细保持 `PENDING`，进度由明细派生。

**无交易还款**：所有还款形态支持 `root_transaction_id` 为空——钱的流动已在别处发生（导入 / 迁移），只补信贷侧核销与状态推进。

## 5. 分期还款（`INSTALLMENT`，账单分期）

以分期合同代替现金完成核销的还款形态，债务总额不变、只改还款节奏：

1. 对 `BILLED` 账单发起，**只能分摊到消费明细**（不支持分期的分期），可全额或部分。
2. 落库：1 条还款记录（无交易）+ 还款明细分摊到消费明细 + 1 个 `BILL_CONVERSION` 合同（本金 = Σ 分摊本金，`source_repayment_id` 回指还款记录）+ 还款计划（首期 = 下一个出账周期）。
3. 核销走统一规则：明细 400 = 现金还 200 + 分期还 200，两条还款明细合计够数即 `PAID`；"是否转过分期"从还款明细形态派生。
4. 新合同未来期次按账期进入后续账单。

## 6. 合同维度操作

### 6.1 合同创建

**放款类（`DISBURSEMENT`）**：输入放款入账资产账户、挂载负债账户、本金、期数、日期、还款方式、利率、计息方式、总手续费。**可选择不创建放款交易**（迁移，借款已实际发生于他处），放款双字段同空；创建交易时写 1 笔 `BORROWING` 并打 owner 标记。

- 挂贷款账户 = 贷款分期，期次按合同条款；挂信用账户 = **现金分期**，期次由系统按账期生成。**借款交易不计入消费净额**（§3.1）。

**账单转换类（`BILL_CONVERSION`）**：由分期还款触发（§5），不写账务交易。

### 6.2 参数与计划解耦

- 参数是输入快照，编辑写回但**不自动重算计划**。
- `PENDING` 行可手工微调金额 / 日期；**`PAID` / `SKIPPED` 行不可编辑、不随还款更正调整**——计划是预期，实际真相在还款明细。
- **重算是显式动作**，三个触发点：合同创建、用户点"按参数重算"、提前还本金；只覆盖 `PENDING` 行（金额覆盖、日期保留），UI 先展示重算预览。
- `PENDING` 期次可置 `SKIPPED`（不进账单，用于迁移已还期次），可撤销。

### 6.3 提前还本金（`EXTRA_PRINCIPAL`）

- 写还款记录（目标 = 合同）+ 单条还款明细（金额载体）；交易可选。
- 重算：剩余本金 = Σ(`PENDING` 行本金) − 本次本金；剩余期数 = `PENDING` 行数（期数不变、摊薄月供）；按合同参数重摊。
- **已出账账单不自动改**；当期明细受影响走"不一致提示 + 显式同步"。合同保持 `ACTIVE`。

### 6.4 提前结清（`EARLY_SETTLEMENT`）

- 写还款记录 + 单条还款明细（可含违约金入手续费分项）；交易可选。
- 剩余 `PENDING` 计划与当期账单中该合同的 `PENDING` 明细置 `SKIPPED`；合同 `CLOSED`。

### 6.5 提前还更远期次

要还的不是当前 `BILLED` 账单、而是更远未出账期次时，走**提前还本金**；边界：当前 `BILLED` 账单 → `BILL`，更远期次 / 直接砍本金 → `EXTRA_PRINCIPAL`。

### 6.6 合同删除

- 物理删除仅允许在合同**无任何关联还款**且**无放款交易**时；已发生还款的合同走提前结清落 `CLOSED` 保留历史。

## 7. 未归属还款（`UNATTRIBUTED`）与未归属欠款

```text
未归属欠款 = 账户负债余额 − Σ 合同 PENDING 计划行本金 − Σ 账单消费明细未还本金
```

- 账单侧**只算消费明细**且按**存储值**取数（分期债由计划侧统一覆盖，避免双算）。本桶是差额定义，天然承接一切未被计划侧与账单侧覆盖的余额，典型来源：期初欠款、余额调整、起始期前导入净额，以及**待同步差额**——补记 / 更正 / 改入账日期落入已出账窗口、尚未同步的金额（§3.3），同步后迁入账单应还。**未出账消费不在桶内**，它由当期 OPEN 账单的消费明细覆盖（§4）；为负 = 溢缴，明确展示。
- 未归属还款：写还款记录（目标 = 账户）+ 单条还款明细，交易可选；不碰任何账单 / 合同。**偿还上限 = 未归属欠款桶**；想还本期消费应走对 OPEN 账单的账单还款。

## 8. 退款

退款是账务核心 `REFUND` 交易：

- **退入资产账户**（花呗退支付宝余额等）：不影响信用账户与账单，天然支持。
- **退回信用账户**：按入账日期归属周期窗口，冲减该窗口消费净额；"冲抵下期" = 退款入账日期设到下期窗口，无需特殊机制。
- 入账日期落入已出账窗口（补记 / 改日期）：走"不一致提示 + 显式同步"。

## 9. 还款的更正与删除

- 还款记录存 `root_transaction_id`，有效交易沿更正链查询（`business_state = current`），**交易更正不回写还款记录**；金额变更经信贷域接口重写还款明细 + 状态重判。
- **通用交易 UI 权限**（owner 标记的还款 / 放款交易）：日期、结算账户、备注直接可改（不触碰核销与状态）；金额性修改与删除显示横幅并路由信贷页。
- **删除联动**（有交易先按账务核心规则冲销）：
  - `BILL`：删还款明细 → 状态重判（明细 / 期次回 `PENDING`，账单 `SETTLED` 回退）。
  - `INSTALLMENT`：删还款明细与记录，级联其创建的合同——合同无其他关联还款时连同计划删除；有则**阻止删除并引导先处理合同侧**。
  - `EXTRA_PRINCIPAL`：删除后重新触发 `PENDING` 计划重算（撤销效果）。
  - `EARLY_SETTLEMENT`：被结清置 `SKIPPED` 的期次与明细恢复 `PENDING`，合同回 `ACTIVE`。
  - `UNATTRIBUTED`：仅冲销 / 删记录。
  - 无交易还款：无可冲销，直接删记录与明细并执行同样联动；入口在还款记录列表（§11）。
- 合同状态联动：被撤销还款若曾使合同 `SETTLED`，回退 `ACTIVE`。

## 10. 导入与迁移

立场：**导入带来账务事实（交易、余额），信贷侧从切点开始管**。

| 场景 | 处理 |
| :--- | :--- |
| 早于账单起始期的交易 | 不生成账单；净欠款落未归属桶，未归属还款消化 |
| 起始期设早、补出历史账单 | 历史账单显示未还 → 无交易账单还款批量核销 |
| 导入数据里的还款 | 不匹配账单，作普通交易入账；信贷侧核销由用户用无交易还款补——"有交易无核销"与"有核销无交易"互补，合计一致 |
| 进行中的分期合同 | 建合同不建放款交易；已还期次置 `SKIPPED`，或用无交易的提前还本金 / 提前结清表达中间状态 |
| 期初欠款 | 账务核心期初余额承载，落未归属桶 |

## 11. 读侧派生与展示

- **可用额度** = 授信额度 − 账户负债余额。**欠款分桶**：账单欠款 / 合同未来欠款 / 未归属欠款。
- **IRR / APR / EPR（履约维度）**：现金流 = 有交易的还款明细（按有效交易日期）+ 未来 `PENDING` 计划流；**本金完整性校验不过（合计 ≠ 合同本金）则不计算**，展示"不可计算"。无交易还款不入现金流。
- **账单查询**：按月账单概要查询；日历页按明细 `repayment_date` 展示；**不做主动提醒**。"与来源不一致"提示随查询接口返回。
- **还款记录管理**：在目标对象详情页展示与管理——账单详情列该账单全部还款记录（含无交易、分期还款），合同详情列提前还 / 结清，账户信贷页列未归属还款；无交易还款列表以 `created_at` 标"记录于"。
