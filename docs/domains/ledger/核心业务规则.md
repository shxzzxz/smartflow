# 核心业务规则

本文描述当前状态交易模型下的创建、修改、删除、父子交易与统计规则。

## 1. 一笔交易的完整表达

一笔交易由 `transactions`、`transaction_details` 和 `entries` 在同一数据库事务内提交。entries 必须借贷平衡；details 描述业务组成，不参与余额计算。

## 2. 修改交易

- 修改保持 `transactions.id` 不变。
- `created_at` 保持不变，`updated_at` 随写入更新。
- 备注、对手方、交易时间和入账时间等基础信息可走轻量更新。
- 金额、账户、分类、用途或父派生分录变化时，必须加载完整交易组并生成 rewrite plan。
- 对受影响交易整体重建 details/entries；不保存修改前快照。

## 3. 父子交易

- 父交易 `parent_transaction_id IS NULL`。
- 子交易的 `parent_transaction_id` 指向稳定父交易 ID，且创建后不可修改。
- 创建子交易时继承父交易的统计与预算排除配置。
- 修改父交易时，只能重算子交易中由父事实派生的账务表达。
- 子交易自身金额、时间、到账账户、对手方、备注、用途和父 ID 不得被父交易修改隐式改变。

## 4. 支出与报销垫付互转

仅允许：

```text
DAILY_EXPENSE ↔ REIMBURSEMENT_ADVANCE
```

规则：

- 无子交易时，目标交易能合法过账即可转换。
- 只有退款时允许转换；退款 ID 与自身事实保持不变，只重算其父派生抵减账户。
- 已有报销到账或结束报销时，报销垫付不能转为普通支出。
- 报销垫付下，退款与报销到账共同核销同一笔报销应收；未结束时的待核销金额为：
  `垫付金额 - 累计退款 - 累计报销到账`。
- 修改后的父金额不得小于累计退款与累计报销到账金额之和。
- 普通支出转报销垫付时，整组统计/预算排除标记重置为 `false`。
- 报销垫付转回普通支出时保留当前标记值。

## 5. 结束报销编辑锁

存在 `REIMBURSEMENT_CLOSE` 时，禁止修改会改变结算金额的事实，包括父金额、更早退款和报销到账，以及垫付转支出。

仍允许修改基础信息、付款账户、报销支出分类和报销应收账户；修改应收账户时同步重建相关子交易的父派生分录。删除 close 后交易组重新开放。

## 6. 删除

- 删除父交易：原子删除父交易、全部子交易及其 details/entries。
- 删除普通子交易：只删除目标子交易。
- 删除 close：交易组恢复为未结束状态。
- 删除时同步移除分录对账户余额的影响。
- 账务核心不检查 owner；跨域清理由所属 application service 负责。

### 分类迁移与删除

活跃分类树恒为二层，一级和二级分类均可直接记账。分类移动只改变活跃树中的层级关系。

- 分类迁移一次只处理一个源分类，不递归处理子树；源、目标必须是同类型活跃分类且不能相同。
- 迁移命中交易组内引用源分类的分录，以及报销垫付保存的支出分类事实；每个命中的顶层交易组通过既有交易编辑与重写规则改到目标分类。
- 整批迁移由一个 application 用例事务包裹，任一交易组重写失败时全部回滚，不产生部分迁移。
- 迁移只改变交易的当前分类事实，不移动分类节点，也不自动删除源分类。
- 删除一次只处理单个分类。分类仍有子分类、分录引用或报销垫付分类引用时拒绝删除；满足条件时物理删除。
- 删除不再归档分类，也不保留用于统计归并的第三层挂载节点。迁移完成后，用户需要单独再次发起删除。

## 7. 余额维护

日常修改：

```text
remove(old entries impact)
apply(new entries impact)
save affected accounts
rewrite affected transaction rows/details/entries
```

以上步骤必须位于同一 `TransactionRunner` 事务内。v20 → v21 数据迁移不重算余额，因为迁移只归并当前有效事实并移除旧版本链记录。

## 8. 统计与预算

- 默认流水直接查询当前 transactions，不再折叠版本。
- 顶层流水使用 `parent_transaction_id IS NULL`。
- 子交易按 `parent_transaction_id = parent.id` 加载并在详情中展示。
- 收支统计以分类账户上的 entries 借贷净额计算。
- 数据库按真实分类账户聚合金额；application 查询层加载活跃两层分类树，组装一级总额与二级分类自身金额。
- 一级分类总额等于一级自身直接金额与全部二级分类金额之和；一级自身金额以“未细分”项呈现，并使用一级分类的真实 ID。
- 统计区间内存在命中分录的物理分类生成统计项，借贷净额允许为零；一级分类只要自身或任一二级分类存在统计活动就返回，其总额允许为零。
- 一级自身“未细分”项与二级分类采用相同活动判断；完全没有命中分录的节点不生成统计项。前端只消费已组装的分类统计读模型，不沿 `parent_id` 自行拼树。
- `is_excluded_from_stats = true` 的交易组不进入收支统计。
- `is_excluded_from_budget = true` 的交易组不进入预算统计。

退款在支出分类上产生 CREDIT 分录，因此会自然抵减支出；无需红字冲销记录。

## 9. 交易列表查询

- 对外分类筛选表达一个活跃分类选择：一级分类通常展开为自身与全部二级分类，二级分类只匹配自身，“未细分”只匹配一级自身。
- 结算账户筛选只接受活跃资产或负债用户账户；不存在、归档或系统账户按无匹配结果处理。
- 分类与结算账户是两个独立维度。仓储分别匹配分类分录和结算账户分录，两个维度同时存在时取交集。
- 分类树校验与展开属于 application 查询层，仓储只接收已展开的物理分类 ID。
- 分类与结算账户都通过实际交易的分录匹配；`topLevelOnly` 只控制返回顶层交易还是父子实际交易。首页返回顶层交易，账户详情与统计贡献流水返回实际命中的父交易或子交易。
- 列表主分类由用途决定：日常支出/收入解析唯一合法方向且金额等于主金额的分类分录，候选缺失或不唯一时返回空；报销垫付读取显式支出分类事实。读侧不依赖分录顺序，写侧不新增唯一性约束。
- 交易列表读模型只暴露主分类引用、结算分录引用和调整摘要；完整分录、交易分项及详情字段继续由详情读模型提供。
- 列表订阅同时响应交易、分录、交易分项与账户快照变化；分类改名、换图标或调整父子关系后重新展开筛选并投影列表。
