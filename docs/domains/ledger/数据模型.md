# 数据模型

本文描述账务核心采用“当前状态交易模型”后的核心表与字段语义。跨模块决策见 ADR-0009 与 ADR-0016。

## 1. 基本约定

- 金额以基础币种最小单位整数存储。
- 不使用数据库外键；父子关系和业务引用由 domain/application 显式校验。
- `transactions` 与 `transaction_lines` 共同表达完整交易信息，是过账输入的完整快照。
- `entries` 由过账规则从交易分项生成，是账户余额、收支统计与预算统计的账务真相。
- 交易分项与分录不同构，二者合计不相等；不得对分项施加借贷平衡校验。

## 2. accounts

`accounts` 承载资产、负债、权益、收入和支出账户。`balance_minor` 保存当前余额，由交易写入时按旧分录与新分录的差量同步维护。

关键字段：

```text
id
name
account_type
account_subtype
account_profile_key
group_id
parent_id
balance_minor
sort_order
archived_at
system_key
source
```

系统账户通过唯一的 `system_key` 标识，包括期初余额、报销差额收入、利息支出、手续费支出、优惠收入和幽灵账户。

`group_id` 是用户账户在资产页中的展示分组引用，允许为空且不使用数据库外键；`sort_order` 表示该分组内的账户顺序。二者不改变账户类型、余额、过账规则或统计口径。归档账户保留其分组和排序信息，恢复后继续使用。

收入、支出账户构成活跃两层分类树：`parent_id = NULL` 表示一级分类，非空时指向同类型活跃一级分类。一级和二级分类均可直接记账。分类迁移改写交易当前事实后，只有无子分类且无交易引用的分类才能物理删除；schema v25 起不再用 `archived_at + parent_id` 表达分类统计归并。

## 3. account_groups

`account_groups` 保存用户在资产页管理的普通账户展示分组：

```text
id
name
sort_order
version
created_at
updated_at
```

分组可容纳任意账户画像；账务核心不赋予分组名称额外语义。删除分组时，引用它的账户（包括归档账户）会改为未分组。

## 4. budgets

`budgets` 保存月度总预算与支出分类预算，不使用数据库外键：

```text
id
month_key
account_id
amount_minor
sort_order
created_at
updated_at
```

- `month_key` 使用 `YYYYMM` 整数表达月份。
- `account_id = NULL` 表示总预算，非空时引用支出分类账户。
- 总预算按 `month_key` 唯一；分类预算按 `(month_key, account_id)` 唯一。
- `sort_order` 保存当月分类预算的展示顺序，总预算固定使用 `0`。
- 分类迁移或删除不级联改写预算；读侧只展示仍有活跃分类的分类预算。

## 5. transactions

一条 `transactions` 记录表示一笔业务事件的当前事实。

```text
id
business_purpose
occurred_at
posted_at
primary_amount_minor
counterparty_name
note
parent_transaction_id
is_excluded_from_stats
is_excluded_from_budget
source_kind
owner_type
owner_id
owner_role
created_at
updated_at
```

不再保存交易版本根、修改链角色、上一版本或业务版本状态。修改交易时保持 `id` 不变；删除交易时物理删除记录。

### 5.1 一层交易组

```text
父交易 P：parent_transaction_id = NULL
├── 子交易 C1：parent_transaction_id = P.id
├── 子交易 C2：parent_transaction_id = P.id
└── 子交易 C3：parent_transaction_id = P.id
```

- 只支持一层父子关系。
- 子交易的 `parent_transaction_id` 创建后不可修改。
- 父交易 ID 是交易组的稳定身份。
- 删除父交易会在一个数据库事务中删除整个交易组；删除子交易只删除目标子交易。

### 5.2 business_purpose

```text
DAILY_EXPENSE
DAILY_INCOME
TRANSFER
REFUND
REIMBURSEMENT_ADVANCE
REIMBURSEMENT_RECEIPT
REIMBURSEMENT_CLOSE
DEBT_REPAYMENT
BORROWING
OPENING_BALANCE
BALANCE_ADJUSTMENT
```

只有 `DAILY_EXPENSE` 与 `REIMBURSEMENT_ADVANCE` 允许互相转换。其它用途只能在同一用途内修改。

报销垫付交易组中，`REFUND`、`REIMBURSEMENT_RECEIPT` 与结束前的报销结算共同占用垫付金额。未结束时待核销金额为 `primary_amount_minor - refund_total - reimbursement_received_total`，不得出现重复核销。

### 5.3 交易组级字段

`is_excluded_from_stats` 与 `is_excluded_from_budget` 是交易组级配置，但冗余存储在父子交易行上。所有写路径必须同步整组；普通支出转报销垫付时两项统一重置为 `false`。

`owner_type / owner_id / owner_role` 只表达业务归属。账务核心保存和透传这些字段，不在运行时校验 owner，也不反向调用其它业务域。

## 6. transaction_lines

```text
id
transaction_id
line_no
role
account_id
amount_minor
created_at
updated_at
```

一条记录表示交易在业务语言中的一条分项。`role` 与 `business_purpose` 的合法组合由过账规则约束。

`account_id` 的可空性由 `role` 固定，不逐行可变：用户账户角色必填，规则账户角色恒空并在过账时按 `system_key` 解析。因此 `account_id` 为空只有一个含义——该角色的账户由过账规则决定。「无账户」属于用户账户角色，按既有语义填幽灵账户。

`line_no` 表达录入顺序，用于多分项时的展示顺序，不承担行标识。

`openingBalance` 与 `balanceAdjustment` 两个角色的 `amount_minor` 带符号存储；其余角色恒为正，方向由角色与账户类型决定。

同一维度内的多条分项各自对交易总额守恒，彼此不建立归属关系。一笔交易同时含多个分类与多个结算账户时，不表达“哪个结算账户支付了哪个分类”——该事实不存在。

修改账务表达时，受影响交易的分项整体删除并按当前过账指令重新生成，不逐行 diff，也不以自身作为重建输入。

## 7. entries

```text
id
transaction_id
account_id
direction
amount_minor
created_at
updated_at
```

- 同一交易的借方合计必须等于贷方合计。
- 分录由过账规则从交易分项生成，自身不保存角色字段。角色是交易分项的事实，读侧不再从方向、账户类型与金额反推角色。
- 分录会补出分项中不存在的腿（报销差额、手续费支出、利息支出、期初权益），也会合并同账户的腿，因此分录条数与分项条数不对应。
- 当前仍保留既有金额能力，本轮不新增金额正负数据库约束。
- 修改账务表达时，受影响交易的 entries 整体替换。
- 日常修改先移除旧 entries 对余额的影响，再应用新 entries 的影响。
- 日常删除只移除被删 entries 的余额影响。

## 8. 外部交易引用

信贷域使用稳定交易 ID：

```text
repayments.transaction_id
installment_contracts.disbursement_transaction_id
```

schema v20 → v21 迁移会把旧版本 ID 映射为稳定父交易 ID，并保持 `accounts.balance_minor` 原值不变。

### 8.1 旧归档分类迁移

schema v24 → v25 将旧归档分类迁移到其同类型活跃归并目标：

- 把源分类的 `balance_minor` 合并到目标分类；
- 将 `entries.account_id`、`transactions.reimbursement_expense_account_id` 和导入分类映射改指目标分类；
- 删除已完成迁移的旧归档分类节点。

该迁移不新增表或业务字段，只清理旧的分类归档归并表示，使升级后的数据符合“迁移交易后物理删除分类”的当前模型。
