# 业务场景流程示例

本文用典型流程说明当前状态交易模型如何保持稳定身份和父子事实。

## 1. 修改支出分类并同步退款

初始交易组：

```text
P 支出 100，分类=餐饮
└── R 退款 20，抵减分类=餐饮
```

用户把 P 的分类改为交通：

```text
P.id 不变，支出分类改为交通
R.id 不变，金额/时间/退款到账账户不变
R 的父派生抵减分类改为交通
```

写入时整体替换 P 与 R 的受影响分项与分录，并按旧/新分录差量维护账户余额。

## 2. 普通支出转报销垫付

```text
P 支出 100，分类=差旅，排除统计=true
└── R 退款 20
```

转换后：

```text
P.id 不变，用途=REIMBURSEMENT_ADVANCE
P 记入报销应收账户，排除统计/预算均重置为 false
R.id 不变，退款抵减账户从差旅分类改为报销应收账户
```

退款累计超过新父金额时拒绝转换。

## 3. 报销垫付转回普通支出

- 没有报销到账和 close：允许。
- 只有退款：允许，退款父派生分录重算为支出分类抵减。
- 已有 `REIMBURSEMENT_RECEIPT`：拒绝。
- 已有 `REIMBURSEMENT_CLOSE`：拒绝。

转换回普通支出时，当前保存的统计/预算排除标记继续保留并重新显示。

## 4. 退款与报销到账共同核销

```text
P 垫付 100
├── R 退款 20
└── C1 报销到账 60
```

交易组仍未结束时，待核销金额为 `100 - 20 - 60 = 20`：

- 新增退款最多 20；
- 新增报销到账最多 20；
- 修改 R 或 C1 时，也按移除当前子交易后的剩余金额校验。

退款与报销到账的累计金额不得超过垫付金额，否则会重复核销同一笔报销应收。

结束报销后交易组锁定；若之后确实发生退款，先删除结束报销，录入退款，再按新的待核销金额重新结束报销。

## 5. 修改报销应收账户

```text
P 垫付，应收账户=A
├── R 退款
├── C1 报销到账
└── C2 结束报销
```

应收账户改为 B 时，P、R、C1、C2 的相关父派生分录统一改为 B；所有子交易的 ID、金额、时间、用户选择的收款账户和备注保持不变。该操作即使存在 close 也允许，因为结算金额不变。

## 6. close 编辑锁

存在 close 时：

- 修改父金额：拒绝。
- 修改更早到账或退款金额：拒绝。
- 垫付转支出：拒绝。
- 修改备注、付款账户、分类或应收账户：允许。
- 删除 close：允许，交易组重新开放。

## 7. 普通应收：借出、收回与坏账

```text
借出 100：资金 -100，应收 +100
收回本金 60、利息 2：资金 +62，应收 -60，利息 +2
坏账 40：应收 -40，坏账损失 +40
```

借出和收回本金仅改变资金与应收余额，不进入收支或预算统计；利息单独计入收入。收回本金可以超过当前应收余额，提交前提示但不阻断。坏账不得超过当前应收余额；默认计入支出和预算，可选择排除统计或预算。

## 8. 普通应付：借入、还款与债务豁免

```text
借入 100：资金 +100，应付 +100
还款本金 40：资金 -40，应付 -40
债务豁免 60：应付 -60，债务减免收入 +60
```

借入和还款本金仅改变资金与应付余额，不进入收支或预算统计；还款本金可以超过当前应付余额，提交前提示但不阻断。债务豁免不得超过当前应付余额；默认计入收入，可选择排除统计，但不提供预算排除。

## 9. 删除

删除子交易 R：只移除 R 及其余额影响。

删除父交易 P：在同一数据库事务内移除 P、全部子交易、所有分项与分录，并移除整个交易组的余额影响。

## 10. 分类迁移与删除

初始分类与交易组：

```text
食品餐饮
└── 午餐

P 支出 100，分类=午餐
└── R 退款 20，抵减分类=午餐
```

用户把“午餐”的交易迁移到“食品餐饮”后：

```text
P.id、R.id 不变
P 的支出分类改为食品餐饮
R 的父派生抵减分类同步改为食品餐饮
```

P 与 R 在同一个顶层交易组重写；若整批迁移中的任何交易组失败，之前已处理的组一并回滚。迁移完成后“午餐”仍存在，用户再次发起删除；只有它没有子分类和交易引用时才物理删除。

## 11. 分类统计与钻取

```text
食品餐饮自身金额 30
└── 午餐金额 70
```

统计读模型返回“食品餐饮 total=100”，并包含“午餐=70”和使用食品餐饮真实 ID 的“未细分=30”。点击食品餐饮匹配自身与午餐；点击午餐只匹配午餐；点击未细分只匹配食品餐饮自身。

分类贡献流水按实际父子交易查询。例如结束报销子交易产生“差额支出”分类分录时，点击该分类返回结束报销子交易，不归并为垫付父交易。

统计项以是否存在命中分录判断，而不是以净额是否非零判断：

```text
食品餐饮 total=0
├── 午餐=100
└── 晚餐=-100
```

上述一级分类及两个二级分类都保留。若同一二级分类在区间内支出与退款抵消为零，该二级分类也保留并可钻取贡献流水；完全没有命中分录的分类不返回。

## 12. v20 → v21 迁移

迁移前：

```text
P0：id=P0, root=P0，旧父版本
P1：id=P1, root=P0，当前父版本
C1：id=C1, root=P0, parent=P1，当前子交易
```

迁移后：

```text
P：id=P0，业务内容取 P1
C1：id=C1, parent=P0
```

历史版本、补偿记录及其内部行被删除；repayment 和 installment 的交易引用同步映射到 P0；账户余额字段不重算。

## 13. v24 → v25 分类迁移

```text
旧归档分类 A，parent_id=B，balance=100
活跃分类 B，balance=200
```

升级后，A 的分录、报销支出分类事实和导入分类映射改指 B，B 的物化余额变为 300，A 被删除。升级过程不保留旧归档分类查询 fallback。
