# 业务场景流程示例

本文用典型流程说明当前状态交易模型如何保持稳定身份和父子事实。

## 1. 修改支出分类并同步退款

初始交易组：

```text
P 支出 100，分类=餐饮
└── R 退款 20，抵减分类=餐饮
```

用户把 P 的分类改为交通：

```text
P.id 不变，支出分类改为交通
R.id 不变，金额/时间/退款到账账户不变
R 的父派生抵减分类改为交通
```

写入时整体替换 P 与 R 的受影响 details/entries，并按旧/新分录差量维护账户余额。

## 2. 普通支出转报销垫付

```text
P 支出 100，分类=差旅，排除统计=true
└── R 退款 20
```

转换后：

```text
P.id 不变，用途=REIMBURSEMENT_ADVANCE
P 记入报销应收账户，排除统计/预算均重置为 false
R.id 不变，退款抵减账户从差旅分类改为报销应收账户
```

退款累计超过新父金额时拒绝转换。

## 3. 报销垫付转回普通支出

- 没有报销到账和 close：允许。
- 只有退款：允许，退款父派生分录重算为支出分类抵减。
- 已有 `REIMBURSEMENT_RECEIPT`：拒绝。
- 已有 `REIMBURSEMENT_CLOSE`：拒绝。

转换回普通支出时，当前保存的统计/预算排除标记继续保留并重新显示。

## 4. 修改报销应收账户

```text
P 垫付，应收账户=A
├── R 退款
├── C1 报销到账
└── C2 结束报销
```

应收账户改为 B 时，P、R、C1、C2 的相关父派生分录统一改为 B；所有子交易的 ID、金额、时间、用户选择的收款账户和备注保持不变。该操作即使存在 close 也允许，因为结算金额不变。

## 5. close 编辑锁

存在 close 时：

- 修改父金额：拒绝。
- 修改更早到账或退款金额：拒绝。
- 垫付转支出：拒绝。
- 修改备注、付款账户、分类或应收账户：允许。
- 删除 close：允许，交易组重新开放。

## 6. 删除

删除子交易 R：只移除 R 及其余额影响。

删除父交易 P：在同一数据库事务内移除 P、全部子交易、所有 details/entries，并移除整个交易组的余额影响。

## 7. v20 → v21 迁移

迁移前：

```text
P0：id=P0, root=P0，旧父版本
P1：id=P1, root=P0，当前父版本
C1：id=C1, root=P0, parent=P1，当前子交易
```

迁移后：

```text
P：id=P0，业务内容取 P1
C1：id=C1, parent=P0
```

历史版本、补偿记录及其内部行被删除；repayment 和 installment 的交易引用同步映射到 P0；账户余额字段不重算。
