# 业务场景流程示例

转账手续费的交易组排除配置示例：转账 100 元，另付手续费 5 元，转出账户减少 105 元、转入账户增加 100 元。两个开关均关闭时收支支出与预算已用均为 5 元；只开启不计收支时为 0 元与 5 元；只开启不计预算时为 5 元与 0 元；均开启时两者为 0 元。本金始终不进入两种统计，配置不改变余额。纯转账也可保存配置，之后增加手续费时按已保存配置生效。

本文用典型流程说明当前状态交易模型如何保持稳定身份和父子事实。

## 1. 修改支出分类并同步退款

初始交易组：

```text
P 支出 100，分类=餐饮
└── R 退款 20，抵减分类=餐饮
```

用户把 P 的分类改为交通：

```text
P.id 不变，支出分类改为交通
R.id 不变，金额/时间/退款到账账户不变
R 的父派生抵减分类改为交通
```

写入时整体替换 P 与 R 的受影响分项与分录，并按旧/新分录差量维护账户余额。

## 2. 支出录入场景与账务输入

```text
交易编排域创建垫付编排实例并计算自承担 / 垫付应收
                         ↓
账务核心接收显式分类、自承担、应收与结算分项
```

AA、报销、代付及逐笔／账户跟踪方式由交易编排域管理。交易通过 `orchestration.advance` owner 指向垫付编排实例；owner 不保存场景。

账户垫付的退款从属于对应垫付交易；到账和结清均为独立顶层交易，不建立父子关系，也不追踪到具体垫付交易。

## 3. AA 多分类垫付

```text
P 付款 300
分类总额：餐饮 120，差旅 180
自承担：餐饮 40，差旅 60
垫付应收：200
```

过账结果：

```text
借 餐饮 40
借 差旅 60
借 垫付应收账户 200
贷 付款账户 300
```

分类总额分项保留完整的分类构成，不直接生成分录；自承担分项由交易编排域计算并显式提交，账务核心只校验守恒。

## 4. 普通支出与逐笔垫付互转

- 无子交易时，目标用途能合法过账即可转换。
- 只有退款时允许转换，退款 ID 与自身事实不变，只重算父派生抵减账户。
- 已有垫付到账或垫付结清时禁止转为普通支出。
- 转换后整组保留原统计/预算排除标记。
- 账户垫付不参与用途转换。

## 5. 垫付退款拆分与垫付到账

```text
P AA 交易总额 70，3 人，垫付应收 46.68，自承担 23.32
├── R 退款 20：自承担退款 6.66，垫付退款 13.34
└── C1 垫付到账 10
```

退款时从原总额与垫付应收反算 3 人，并用退款后的总额 `70 - 20 = 50`
重新计算自承担 `16.66` 与垫付 `33.34`，差异形成上述退款构成：

- 自承担退款 `23.32 - 16.66 = 6.66`，冲减原支出分类；
- 垫付退款 `46.68 - 33.34 = 13.34`，冲减垫付应收；
- 待收回金额为 `46.68 - 13.34 - 10 = 23.34`；
- 本次退款后仍可退款 `50`，后续退款继续按剩余总额反算。

普通垫付退款保持当前自承担与剩余交易总额的比例。例如当前总额 70、自承担
20、垫付 50，退款 7 时自承担退款为 2、垫付退款为 5。多分类退款先确定本次
分类退款分配，再按同一退款构成把自承担退款分配到这些分类；多账户只作用于
退款到账分配。

账户垫付的退款仍是所属垫付交易的子交易。账户垫付的到账是独立顶层交易，通过
`owner_type = orchestration.advance` 归入编排实例，不读取或校验逐笔待收回金额。

## 6. 修改垫付应收账户

```text
P 垫付，应收账户=A
├── R 退款
├── C1 垫付到账
└── C2 垫付结清
```

逐笔垫付的应收账户改为 B 时，P、R、C1、C2 的相关父派生分录统一改为 B；所有子交易的 ID、金额、时间、用户选择的收款账户和备注保持不变。

## 7. 逐笔结清

存在垫付结清子交易时：

- 修改父金额或垫付应收：拒绝。
- 修改更早到账或退款金额：拒绝。
- 垫付转支出：拒绝。
- 修改备注、付款账户、分类总额事实或应收账户：允许。
- 删除结清子交易：允许，交易组重新开放。

结清少收时，自承担部分落入调用方选择的任意有效普通支出分类，不要求属于原垫付分类；坏账部分计入系统内置坏账损失分类，多收部分计入垫付补偿。账户垫付的结清不建立全局关闭状态。

## 8. 普通应收：借出、收回与坏账

```text
借出 100：资金 -100，应收 +100
收回本金 60、利息 2：资金 +62，应收 -60，利息 +2
坏账 40：应收 -40，坏账损失 +40
```

借出和收回本金仅改变资金与应收余额，不进入收支或预算统计；利息单独计入收入。收回本金可以超过当前应收余额，提交前提示但不阻断。坏账不得超过当前应收余额；默认计入支出和预算，可选择排除统计或预算。

## 9. 普通应付：借入、还款与债务豁免

```text
借入 100：资金 +100，应付 +100
还款本金 40：资金 -40，应付 -40
债务豁免 60：应付 -60，债务减免收入 +60
```

借入和还款本金仅改变资金与应付余额，不进入收支或预算统计；还款本金可以超过当前应付余额，提交前提示但不阻断。债务豁免不得超过当前应付余额；其收入按交易组配置决定是否计入收支，预算排除配置可保存，但没有支出分录时不改变预算金额。

## 10. 删除

删除子交易 R：只移除 R 及其余额影响。

删除父交易 P：在同一数据库事务内移除 P、全部子交易、所有分项与分录，并移除整个交易组的余额影响。

## 11. 分类迁移与删除

初始分类与交易组：

```text
食品餐饮
└── 午餐

P 支出 100，分类=午餐
└── R 退款 20，抵减分类=午餐
```

用户把“午餐”的交易迁移到“食品餐饮”后：

```text
P.id、R.id 不变
P 的支出分类改为食品餐饮
R 的父派生抵减分类同步改为食品餐饮
```

P 与 R 在同一个顶层交易组重写；若整批迁移中的任何交易组失败，之前已处理的组一并回滚。迁移完成后“午餐”仍存在，用户再次发起删除；只有它没有子分类和交易引用时才物理删除。

## 12. 分类统计与钻取

```text
食品餐饮自身金额 30
└── 午餐金额 70
```

统计读模型返回“食品餐饮 total=100”，并包含“午餐=70”和使用食品餐饮真实 ID 的“未细分=30”。点击食品餐饮匹配自身与午餐；点击午餐只匹配午餐；点击未细分只匹配食品餐饮自身。

分类贡献流水按实际父子交易查询。例如垫付结清子交易产生自承担支出分录时，点击该分类返回垫付结清子交易，不归并为垫付父交易。

统计项以是否存在命中分录判断，而不是以净额是否非零判断：

```text
食品餐饮 total=0
├── 午餐=100
└── 晚餐=-100
```

上述一级分类及两个二级分类都保留。若同一二级分类在区间内支出与退款抵消为零，该二级分类也保留并可钻取贡献流水；完全没有命中分录的分类不返回。

## 13. v20 → v21 迁移

迁移前：

```text
P0：id=P0, root=P0，旧父版本
P1：id=P1, root=P0，当前父版本
C1：id=C1, root=P0, parent=P1，当前子交易
```

迁移后：

```text
P：id=P0，业务内容取 P1
C1：id=C1, parent=P0
```

历史版本、补偿记录及其内部行被删除；repayment 和 installment 的交易引用同步映射到 P0；账户余额字段不重算。

## 14. v24 → v25 分类迁移

```text
旧归档分类 A，parent_id=B，balance=100
活跃分类 B，balance=200
```

升级后，A 的分录、垫付分类事实和导入分类映射改指 B，B 的物化余额变为 300，A 被删除。升级过程不保留旧归档分类查询 fallback。
