# 摊销编排

## 1. 域职责

`orchestration` 的摊销能力管理预付费用和预收收入的计划、期次、正常退款、终止和定时确认。账户、交易、分项、分录与余额仍由账务核心负责。

摊销不复用信贷分期合同或垫付实例。初始收付、摊销退款和终止退还在账务核心使用转账；期次确认和终止确认使用支出或收入。计划所属交易都是独立顶层交易，通过 `owner_type = orchestration.amortization` 关联计划，不使用父子交易。

## 2. 计划

计划分为预付费用和预收收入：

- 预付费用使用 `asset / prepaidExpense` 递延账户，初始付款从资金账户转入递延账户；
- 预收收入使用 `liability / deferredIncome` 递延账户，初始收款从递延账户转入资金账户。

计划保存摊销类型、原始金额、递延账户、首期日期、间隔单位、间隔数、期数、初始收付交易和状态。计划还保存原始分类分配和原始资金账户分配，两者分别合计等于原始金额。

计划不保存对手方、备注、不计收支或不计预算配置。相关字段属于具体账务交易，由每笔交易独立维护。

计划状态为进行中、已完成或已终止。全额退款后计划进入已完成，不新增“已退款”状态。

## 3. 净额与期次

净摊销金额是原始金额扣除累计摊销退款后的基数。每次正常退款后，计划按当前净摊销金额重新等额分摊全部期次，尾差计入最后一期。

每期分类金额从计划当前分类余额自动计算。正常摊销按期次分类余额比例分配；每期保存当前分类构成，零金额期次不保存分类分项。

计划建立时生成全部期次。日、月、年日期均以首期日期为锚点：日间隔按自然日增加，月与年间隔按日历增加并处理月末。

定时任务只处理到期且金额大于零的待摊销期次，可一次补齐打开 App 前错过的多个期次。零金额期次直接视为完成，不生成交易，也不阻止计划完成。

## 4. 摊销退款

摊销退款是独立的计划级事实，通过分类分配和结算分配减少净摊销金额。退款允许用户显式填写每个分类的退款金额和每个资金账户的到账金额，两组分配合计都必须等于退款金额。

摊销退款不包含退款手续费；确有费用时作为独立交易记录。

退款分类不要求维持原分类比例。分类退款减少计划的当前分类余额，结算退款决定实际资金流向，两个维度不建立逐项对应。

退款分类只改变摊销基数和业务展示，不生成冲减原分类的退款分录。实际账务从递延账户转回资金账户；否则后续期次已经按净额减少，再生成分类退款分录会造成重复冲减。

每次退款后：

- 按新净额重算全部期次金额和分类分项；
- 已生成的确认交易保持交易 ID，按当前事实改写金额和分类；
- 新金额为零的期次删除确认交易并转为零金额完成；
- 原金额为零、新金额大于零的期次恢复为待摊销；
- 计划继续摊销，除非净额归零。

退款事实不重复保存备注、时间、入账时间、对手方、统计或预算配置，这些信息由关联退款转账交易持有。

## 5. 全额退款

当前净摊销金额全部退款后：

- 计划净额归零；
- 已生成的正金额确认交易删除并同步回冲余额；
- 所有期次保留为计划历史，但不再生成确认交易；
- 计划标记为已完成；
- 退款转账作为独立账务事实保留。

## 6. 摊销终止

终止与正常退款不同。终止结束计划，并把终止时剩余的待摊销金额分成“实际退还”和“立即确认”两部分。

终止按本地自然日判断：

- 终止日之前到期的正金额期次生成并保留；
- 终止日当天已经生成的期次保留；
- 终止日之后已经生成的确认交易删除并回冲余额；
- 终止日之后尚未生成的期次取消。

用户分别填写终止分类退还和终止结算退还。两者可以自由输入，不要求按当前分类比例或期次余额比例；两组分配合计都必须等于终止实际退还金额。

终止确认按分类派生：

```text
分类终止确认 = 分类当前待摊销余额 - 分类终止退还
```

终止确认合计等于待摊销总额减终止实际退还金额。终止确认金额大于零时生成支出或收入交易；终止退还金额大于零时生成转账。两部分在同一应用事务内完成，之后计划标记为已终止。

## 7. 交易与展示

计划所属交易使用账务核心的交易字段保存交易时间、入账时间、备注、对手方、标签以及不计收支、不计预算配置。这些字段允许像普通收入或支出交易一样逐笔修改。

交易业务时间与期次应摊销日期相互独立。修改摊销交易的业务时间或入账时间只改变该笔交易的展示和统计归属，不修改期次日期、期次金额或计划进度；计划进度仍以期次的应摊销日期为准。

期次金额、期次日期、期次分类、递延账户以及退款和终止引起的计划重算由摊销用例控制。

摊销退款、终止退还、初始收付在账务核心中仍是转账，但计划详情和交易列表必须使用摊销业务投影：

- 初始收付展示为“摊销”，分类来自计划分类分配；
- 期次确认展示为“摊销”，分类来自期次分类分配；
- 正常退款展示为“摊销退款”，分类来自退款分类分配；
- 终止退还展示为“摊销终止退还”，分类来自终止分类退还分配；
- 终止确认展示为“摊销终止确认”，分类来自终止剩余分类。

初始收付、正常退款和终止退还的分类展示不改变其转账分录，也不直接进入收支、预算或分类统计。只有期次确认和终止确认产生实际收入或支出分录。

## 8. 计划纠错

摊销详情和摊销交易详情都是管理入口。摊销详情概览的主指标展示待摊金额、已摊销和累计退款，辅助信息展示原摊销额、净摊销额、首期日期、摊销期数、期次间隔和间隔数，不展示摊销类型；计划期次只展示期次、应摊销日期、金额与状态，不展示分类或账户。摊销初始收付和期次确认交易详情展示退款、终止、编辑和删除入口；摊销退款或摊销终止交易详情只管理当前事实，不再次展示退款和终止操作。摊销交易详情继续展示分类、账户及普通交易字段。

摊销计划详情和交易详情都复用统一重算链路。重算按顺序读取原始金额、分类分配和已有退款，计算净摊销金额与分类余额，再根据摊销配置重建全部期次、协调已有确认交易并补齐到期期次。已有确认期次保持交易身份；不存在的零金额期次删除交易。

配置编辑只调整摊销期数、首期日期、间隔方式和间隔数，不修改摊销类型、金额、分类分配、资金分配或普通交易字段。配置保存后不与已有确认期次或退款做历史状态冲突检查，而是直接基于当前计划事实完整重算。原金额、分类分配、递延账户和资金分配通过初始交易编辑维护，修改后也调用同一重算链路。

摊销计划详情中的摊销退款行和摊销终止行点击进入对应交易详情，再由交易详情进入编辑页；配置编辑入口进入独立配置页。计划详情操作栏始终展示配置编辑、摊销退款和摊销终止，当前计划不允许退款或终止时相应按钮保持可见并禁用。摊销退款可从计划详情动态行右滑删除，也可从退款交易详情删除；删除对象始终是该笔退款及其转账交易，删除后恢复净额并重算期次，不得删除整项计划。

摊销终止行点击进入终止编辑页，右滑显示“删除摊销终止”。删除终止会移除终止确认和终止退还交易，恢复终止时取消的期次，并立即补齐截至当前时间已经到期的期次；终止前已经确认的期次、正常退款和实际支付保持不变。

删除计划删除初始收付、期次确认、退款、终止和计划自身，包括全部关联账户分项。删除属于不可恢复操作，必须在同一应用事务内完成，任一步失败均整体回滚。
