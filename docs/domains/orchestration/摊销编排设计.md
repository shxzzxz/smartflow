# 摊销编排

## 1. 域职责

`orchestration` 的摊销能力管理预付费用的逐期确认、预收收入的逐期确认、提前终止和定时生成。账户、交易、分项、分录与余额仍由账务核心负责。

摊销不复用信贷分期合同，也不复用垫付实例。它只组织既有转账、支出和收入原语。

## 2. 计划与账户

计划分为两种：

- 预付费用：使用 `asset / prepaidExpense` 账户；初始资金从资金账户转入此账户，确认时记支出，提前退款时从此账户转回资金账户。
- 预收收入：使用 `liability / deferredIncome` 账户；初始资金从此账户转入资金账户，确认时记收入，提前退款时从资金账户转回此账户。

计划通过 `deferralAccountId` 引用承载未确认余额的账户。该账户可以承载多个计划，因此计划剩余金额按计划自身期次和交易计算，不读取共享账户余额代替。

## 3. 计划

计划保存：

- 类型、递延账户、收入或支出分类；
- 总额、首期日期、日/月/年间隔和确认期数；
- 整组默认的不计收支、不计预算配置；
- 初始转账交易；
- 终止时间、终止确认交易和退款交易。

每期金额按最小货币单位等额拆分，尾差计入最后一期。日、月、年日期均以首期日期为锚点计算：日间隔按自然日增加，月与年间隔按日历增加并处理月末。

计划所属交易使用 `owner_type = orchestration.amortization`。初始、确认和退款交易是独立顶层交易，不使用父子关系。

## 4. 配置

计划默认配置在交易创建时复制到该交易自身的 `is_excluded_from_stats`、`is_excluded_from_budget`。复制后以交易字段为实际口径，因此组内交易可以有不同配置。

修改计划默认配置时，默认只影响未来生成的交易；用户明确选择应用到整组时，由摊销 application 用例在一个事务内批量覆盖现有计划交易。

转账手续费不属于预付或预收本金，按转账交易自身配置参与收支统计和预算。

## 5. 自动生成

计划建立时生成完整期次计划。定时任务只处理到期且尚未生成的期次，可一次补齐打开 App 前错过的多个期次。

每期生成与期次标记在同一事务中完成。计划期次序号和生成交易引用必须唯一，任务可以接受重复或并发调用。

## 6. 提前终止

终止按本地自然日判断：

- 终止日之前的到期期次生成并保留；
- 终止日当天已经生成的期次保留；
- 终止日之后已经生成的确认交易删除并回冲余额；
- 终止日之后尚未生成的期次取消。

终止时剩余递延余额为计划总额扣除保留的确认金额。实际退款不得大于该余额；差额作为终止确认金额，默认使用原分类，允许调用方显式选择分类。

终止确认与退款使用同一终止应用事务。退款为普通转账，不是已确认收支退款。
