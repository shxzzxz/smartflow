# 保险域数据模型

本文描述保险域的表、字段语义与关键约束。金额统一以基础币种最小单位（分）的整数保存；日期按本地日历日期保存；缴费年月保存为 `YYYY-MM`。遵循项目约束：**不使用数据库外键**，表间引用为逻辑引用，由应用层维护一致性。

## 1. 被保险人

### 1.1 insured_people

```text
insured_people
- id
- name                 姓名
- birth_date           出生日期
- relationship         与用户的关系
- gender               性别
- note                 备注；可空
- avatar_preset        预设头像 key
```

- 姓名不能为空白。
- 出生日期必须在 1900 年至 2100 年之间，并且不能晚于当前日期。
- `relationship` 为本人、配偶、子女、父母或其他；`gender` 为男、女或未知。
- `note` 可选，去除首尾空白后最多 100 个字符。
- `avatar_preset` 只能引用 App 内置头像，不保存用户上传图片或外部文件路径。
- 年龄不落库，按出生日期与查询日期派生。

## 2. 商业保险

### 2.1 commercial_insurances

```text
commercial_insurances
- id
- name                         保险名称
- insurer_name                 保险公司名称
- category                     险种大类
- product_form                 产品形态；可空
- coverage_start_date          保障开始日期
- coverage_end_date            保障结束日期；可空
- lifetime                     是否终身保障
- coverage_amount_minor        保额；可空
- coverage_amount_note         保额说明；可空
- premium_amount_minor         缴费金额；可空
- premium_frequency            缴费频率；无缴费计划时为空
- premium_note                 缴费说明；可空
```

- `category` 为医疗、重疾、意外、寿险或其他。
- `premium_frequency` 为一次性、月缴、季缴、半年缴、年缴或其他。缴费金额与缴费说明依附于缴费频率。
- 保障结束日期不得早于开始日期；终身保障不得保存结束日期。
- 保额与缴费金额不得为负。
- 商业保险状态不落库，由保障期间与查询日期派生。

### 2.2 commercial_insurance_insured_people

```text
commercial_insurance_insured_people
- commercial_insurance_id      商业保险 id
- insured_person_id            被保险人 id
```

- 以 `(commercial_insurance_id, insured_person_id)` 为唯一身份，表达商业保险与被保险人的多对多关系。
- 同一商业保险至少保留一条关联；关联人员不得重复。

### 2.3 coverage_responsibilities

```text
coverage_responsibilities
- id
- commercial_insurance_id      所属商业保险 id
- kind                         责任类型
- name                         责任名称
- sort_order                   展示顺序
```

- `kind` 为医疗、重疾、意外、寿险、伤残、其他或自定义。
- 受控责任项的名称与责任类型对应；仅自定义责任项使用用户填写的名称。
- 责任项按 `sort_order` 展示，顺序非负。

### 2.4 responsibility_points

```text
responsibility_points
- id
- responsibility_id            所属保障责任项 id
- label                        要点名称
- value                        要点内容
- sort_order                   展示顺序
```

- 要点名称与要点内容均不能为空。
- 同一责任项内，去除首尾空白后的要点名称不得重复。
- 要点按 `sort_order` 展示，顺序非负。

### 2.5 insurance_attachments

```text
insurance_attachments
- id
- commercial_insurance_id      所属商业保险 id
- file_name                    原始文件名
- storage_key                  文件存储标识
- mime_type                    媒体类型
```

- 一张商业保险可拥有多份附件。
- 文件名、存储标识和媒体类型均不能为空。
- 本表保存附件元数据；附件内容由应用私有文件存储管理。

## 3. 社保医保

### 3.1 social_medical_insurances

```text
social_medical_insurances
- id
- insured_person_id            参保人 id
- region                       参保地区
- participant_type             参保类型
```

- `participant_type` 为职工或居民。
- 每条记录只关联一名被保险人；同一被保险人可以有多条社保医保记录。
- 记录不保存保障期限、缴费计划、聚合级缴费基数、个人账户、参保凭证或保障责任项。

### 3.2 social_medical_contribution_records

```text
social_medical_contribution_records
- social_medical_insurance_id  所属社保医保记录 id
- year_month                   缴纳年月，YYYY-MM
- contribution_base_minor      缴费基数
```

- 以 `(social_medical_insurance_id, year_month)` 为唯一身份；同一社保记录内一个月份只有一条缴费记录。
- 缴费基数不得为负。

## 5. 派生与引用关系

```text
insured_people
  ├─< commercial_insurance_insured_people >─ commercial_insurances
  ├─< social_medical_insurances ─< social_medical_contribution_records
  └─< social_pension_insurances ─< social_pension_contribution_records

commercial_insurances
  ├─< coverage_responsibilities ─< responsibility_points
  └─< insurance_attachments
```

- 被保险人年龄、商业保险保障状态和成员保障读模型均为派生结果，不单独持久化。
- 商业保险与其关联成员、责任项、要点和附件之间为逻辑归属；删除商业保险时由应用层清理全部从属数据。
- 社保记录与其缴费记录之间为逻辑归属；删除社保记录时由应用层清理该记录的缴费记录。
- 被保险人被商业保险或社保记录引用时，应用层拒绝删除。
