# 保险域设计

本文是保险域的概览，定义域的定位、聚合关系与读模型。表结构与字段语义见《[数据模型](数据模型.md)》，业务不变量与操作结果见《[业务规则](业务规则.md)》。

## 1. 定位与边界

保险域用于记录家庭成员已经持有的商业保险和社保，并以被保险人为主线浏览保障信息。它保存用户确认过的保障摘要与合同附件，不替代保险合同，也不根据摘要推导理赔、现金价值或待遇。

域内边界如下：

- 商业保险与社保分开建模；社保以一条统一记录承载医保、养老、工伤、生育和失业类型。
- 保险公司只保存名称文本，不建立保险公司或保险产品目录，也不复用账务对手方。
- 参保地区只保存文本，不建立区域政策主数据。
- 商业保险的缴费计划只记录频率、期数和期缴金额摘要，不生成期次；社保用逐月缴费记录表达缴费基数变化。
- 保险域不建立账务交易，不参与支出、预算或账户余额计算。
- 不提供缴费与续保提醒、AI 合同解读、养老金试算、保障责任模板、理赔、现金价值、退保、保单贷款或受益人管理。

## 2. 核心聚合

```text
InsuredPerson [AR]
  ├─ 商业保险（多对多）
  └─ 社保（一对多，每条记录只关联一人）

CommercialInsurance [AR]
  ├─ 被保险人关联
  ├─ 保障责任项
  │    └─ 责任要点
  └─ 合同附件

SocialInsurance [AR]
  └─ 缴费记录
```

- `InsuredPerson` 是被保险成员，姓名与出生日期独立维护。
- `CommercialInsurance` 是一张商业保单。一张保单可覆盖多名成员，一名成员也可持有多张商业保单。
- `SocialInsurance` 是一条社保记录，社保类型为医保、养老、工伤、生育或失业。每条记录只属于一名被保险人，可随时间新增多条记录。
- 保障责任项、责任要点和附件由商业保险拥有，不作为独立聚合根。
- 缴费记录由对应社保记录拥有，表达每月缴费基数，不形成独立聚合根。

## 3. 读模型

成员保障读模型由跨聚合只读投影组成，不建立新的持久化聚合，也不改变商业保险与社保两个聚合的边界：

```text
InsuranceMemberListItem
- insuredPersonId
- name
- age
- commercialInsuranceCount
- hasSocialInsurance

MemberCoverageOverview
- insuredPerson
- commercialInsurances[]
- socialInsurances[]

InsuranceListItem
- sourceType
- insuranceId
- title
- subtitle
- summary

CommercialInsuranceListItem
- insurance
- insuredPeople[]
- status                 由保障期间与查询日期派生

InsuranceOverview
- members[]
- commercialInsurances[]
- activePolicyCount      保障中及终身保单数量
- coveredMemberCount     在保障保单覆盖的唯一被保险人数
- coverageAmountTotal    按被保险人累计的在保障保额
```

- 成员年龄由出生日期与当前日期派生，不持久化年龄。
- 商业保险状态由保障期间与当前日期派生，不持久化状态。
- 保险总览的保额只统计保障中及终身保单；共享保单按每名被保险人各累计一次，保额缺失按 0 计算。
- 成员保障详情同时给出商业保险和社保两个集合；社保列表项保留统一记录标识，并展示具体社保类型。
- 社保记录不派生保障开始、结束或缴费完成状态，只展示参保信息与已记录的缴费月份数。

## 4. 附件与数据归属

- 商业保险可保存多份合同附件；附件包含文件名、存储标识、媒体类型与创建时间。
- 附件文件属于商业保险的业务资料，附件元数据随商业保险持久化；删除商业保险或单份附件时一并清理对应文件。
- 所有跨表引用由应用层校验。数据库不使用外键。
