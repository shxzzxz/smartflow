# 保险域业务规则

本文定义保险域的成员维护、商业保险、社保记录、删除联动与成员读侧规则。表结构见《[数据模型](数据模型.md)》，域边界见《[领域设计](保险域设计.md)》。

## 1. 被保险人

- 被保险人的姓名和出生日期必填。
- 出生日期必须是有效日历日期，且不能落在未来。
- 关系必填，固定为本人、配偶、子女、父母或其他；性别必填，固定为男、女或未知。
- 头像只能从 App 内置预设中选择，不支持上传相册图片或外部图片。
- 备注可选，去除首尾空白后最多 100 个字符；空白备注不保存。
- 年龄按出生日期与查询日期派生，不保存年龄字段。
- 被保险人可以修改姓名、关系、出生日期、性别、备注和预设头像；修改后，成员列表、年龄和所有关联保险的成员展示同步变化。
- 被保险人被任一商业保险或社保记录引用时不可删除。
- 未被引用的被保险人可以删除，删除只移除成员本身。

## 2. 商业保险

### 2.1 基本信息

- 保险名称、保险公司和险种大类必填；产品形态可选。
- 保险公司是自由文本；系统不建立保险公司主数据，也不将其写入账务对手方。
- 险种大类固定为医疗、重疾、意外、寿险或其他。
- 产品形态用于补充定期寿险、增额寿险、终身寿险等产品描述，不影响险种大类。
- 投保人和受益人均可选，以用户输入的文本保存；去除首尾空白后为空时不保存，空值表示未记录。
- 投保人记录个人或单位名称，不改变保单的被保险人关联；受益人记录姓名、法定或其他合同约定，不限定为身故受益人。
- 新增或编辑保单资料时维护基本信息、保障期间、保额、投保人与受益人。

### 2.2 保障期间与状态

- 保障开始日期必填，保障结束日期可选。
- 结束日期不能早于开始日期。
- 终身保障使用明确的终身标记；终身保障不得同时保存结束日期。
- 非终身保障的开始日和结束日均包含在保障期间内。
- 商业保险状态由保障期间与查询日期派生：

| 条件 | 状态 |
| :--- | :--- |
| 标记为终身保障 | 终身 |
| 当前日期早于开始日期 | 未开始 |
| 当前日期位于开始日至结束日之间 | 保障中 |
| 当前日期晚于已记录的结束日期 | 已结束 |

- 非终身且未记录结束日期时不派生“已结束”状态。

### 2.3 保额与缴费计划

- 保额金额可选，且不得为负。
- 缴费计划可选。记录缴费计划时至少选择缴费频率；缴费频率为一次性、月缴、年缴或其他。
- 期缴金额与缴费期数可选；期缴金额不得为负，缴费期数存在时必须为正整数。
- 缴费配置在商业保单保存后独立维护，可修改或清除频率、期数与期缴金额。新建保单不录入缴费信息；编辑保单资料、保障责任或附件时保留已有缴费配置。
- 缴费计划只作为摘要保存，不生成缴费期次、待缴状态、提醒或账务交易。

### 2.4 被保险人与责任项

- 保障概要、保障亮点、等待期、除外责任是用户维护的可选文本，空白内容表示未记录。概要与亮点描述保单的整体保障范围与特点，不替代合同或具体保障责任。
- 等待期和除外责任可以注明适用的被保险人与责任。除外责任统一承载既往症处理、承保限制、通用责任免除和特别除外约定，不记录成员的完整健康史，也不推导理赔结果。
- 一张商业保险必须关联至少一名被保险人；保存时被保险人不重复。
- 商业保险与被保险人为主用户多对多关系。一张保单可覆盖多人，一名成员也可关联多张保单。
- 保存编辑时不能移除最后一名被保险人。
- 保障责任项可维护零条或多条；每项包含责任类型、名称、可选责任说明、展示顺序和零条或多条责任要点。
- 医疗、疾病给付、身故、伤残、其他为受控责任类型，按保障内容分类，独立于保单险种。意外医疗、意外身故和意外伤残分别属于医疗、身故和伤残。
- 重疾医疗承担重大疾病治疗费用，属于医疗；重大疾病、中症和轻症达到合同约定条件后给付约定保险金，属于疾病给付；猝死属于身故。
- 责任名称由用户自由填写；责任说明用简短文本概括保障范围，空白内容不保存。
- 常用责任名称与要点名称按责任类型提供，点击后填入名称，用户可以继续修改。常用名称不自动创建责任或填入保障规则；同一责任内已使用的要点名称不作为候选。
- 住院医疗、特殊门诊、院外药械等可以作为独立责任或某责任下的范围要点，需要独立维护赔付规则时建立责任项。
- 责任要点的名称和内容均不能为空；同一责任项内名称不得重复；要点顺序按用户保存顺序保留。
- 保障责任项与责任要点均按用户保存的顺序展示，用户可以调整各自顺序。
- 保障责任项是用户摘要，合同附件是完整依据。
- 保障概要、保障亮点、等待期、除外责任和具体保障责任在保单详情进入保障责任管理后维护；新建或编辑保单资料时保留已有保障信息。

### 2.5 合同附件

- 一张商业保险可添加、查看和删除多份合同附件。
- 附件在商业保险保存后维护，不改变被保险人、保障期间或责任项。
- 删除单份附件只移除该附件的元数据与文件。
- 删除商业保险时，一并删除其保障责任项、责任要点、被保险人关联、附件元数据与附件文件。

## 3. 社保

### 3.1 记录身份

- 社保类型固定为医保、养老、工伤、生育和失业；同一被保险人可以持有多条社保记录。
- 每条社保记录必须且只能关联一名被保险人。
- 参保地区必填，以省、市选择结果表达；地区信息只用于记录参保地点，不决定社保政策或待遇。参保类型为职工或居民。
- 编辑社保记录时可以修改参保人和参保地区，记录及其缴费历史保持关联。
- 同一位被保险人可以为不同社保类型、参保地区或参保类型分别建立记录。
- 社保类型和参保类型是记录的历史身份。编辑既有记录时不得修改；需要变更时新建社保记录，并保留原记录及其缴费历史。
- 社保记录不保存保障期限、缴费计划、聚合级缴费基数、个人账户、参保凭证或保障责任项，也不派生保障状态。

### 3.2 缴费记录

- 缴费记录包含缴费年份、可选月份、可选缴费基数、缴费金额和可选缴费说明。年份为 1900 至 2100 年；月份存在时为 1 至 12。
- 月份为空表示年度记录。同一年度可以同时有年度记录和各月记录；相同年份与月份只能有一条记录。
- 新增或编辑缴费记录时，缴费金额必填；缴费金额与已填写的基数不得为负。未记录的金额保持缺失，不从基数推导。
- 缴费记录可以新增、修改或删除，允许暂时没有缴费记录。
- 缴费基数与说明随单条缴费记录保存，不在社保记录上维护“当前缴费基数”。
- 新增或编辑社保记录时只维护参保信息；缴费记录统一在社保详情页维护。

## 4. 删除与一致性

- 数据库不使用外键；跨表引用和引用完整性由应用层校验。
- 删除被保险人前检查商业保险关联和社保记录；存在任一引用时拒绝删除。
- 删除商业保险时，在同一业务操作中删除其关联成员、责任项、责任要点和附件元数据，并清理附件文件。
- 删除社保记录时，一并删除该记录的缴费记录。
- 删除共享商业保险或修改其被保险人，会影响所有关联成员的保障详情。

## 5. 成员读侧

- 被保险人成员管理页展示全部成员，包括尚未添加保险的成员，并只展示成员身份信息，不展示保险摘要。
- 保险总览的保单数量统计保障中及终身保单；保障成员统计这些保单覆盖的唯一被保险人数。
- 保险总览与成员详情的保额总计只累计保障中及终身保单，保额缺失按 0 计算；共享保单按每名被保险人各计算一次。
- 成员保障详情按商业保险和社保分组；社保列表展示每条记录的具体社保类型。
- 商业保险列表项以产品名称为主标题，展示保险公司、保额和派生状态；险种通过筛选区分。
- 保险总览指标、保额合计及保单列表中的金额不展示货币符号。保额达到一万元时统一用“xx 万”展示，小于一万元时展示原值，展示换算不改变保存的金额。
- 社保列表项展示社保类型、参保地区和参保类型。
- 成员保障详情是跨聚合只读投影；浏览不会修改保险事实，也不产生账务、提醒或 AI 结果。
