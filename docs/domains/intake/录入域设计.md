# 录入域设计

## 职责与边界

录入域将用户描述、外部来源资料和已授权周期规则整理为记账输入，负责输入解释、确认或规则执行以及录入结果管理。账户、交易、分项、复式分录、余额和过账规则由账务核心管理。

输入渠道不决定账务行为。截图、语音和文件提供原始信息；录入能力解释业务意图并补全输入，确定后通过账务核心完成记账。各能力使用自己的候选、计划或规则模型，不要求所有输入都具有导入来源、来源映射或导入批次。

## 来源导入

来源导入解释外部来源记录，维护账户与分类映射，组织导入交易组，提交导入批次并编排撤销。解析、映射和审阅状态仅属于当前录入会话；成功提交后保留来源映射、批次及批次详情。

来源导入的规则与模型见[导入业务设计](导入业务设计.md)。

## 识别规则

识别规则根据输入中的关键词建议结算账户或收支分类，配置包含关键词、已有目标、适用来源、启用状态与执行顺序。识别文本包含任一关键词时命中；匹配文本由输入能力准备。系统提供分类默认规则，账户规则由用户创建。目标分类的收支方向、账户的可用角色须与交易兼容。

账户与分类分别按列表顺序取第一个启用、目标可用且类型兼容的规则。截图记账只使用全部来源规则；来源导入使用全部来源与对应导入来源的规则，两者保持整体执行顺序。指定来源的规则保留用于账单导入。目标缺失的规则保留供用户重新配置，但不参与匹配。

目标按内部身份关联，改名后继续有效。删除、归档或角色不兼容时跳过规则，不自动降到父分类，也不改指后来创建的同名对象。首次无法确认的默认目标保持待配置。识别规则只建议已有目标，不创建或恢复账户与分类。

分类默认词库覆盖餐饮、交通、居家、购物、娱乐、教育、医疗、通讯、人情、慈善，以及工资、奖金、兼职、投资收益和现金返利。商品用途明确的细分类规则优先于通用商户规则。豆浆、油条可直接建议早餐；烤鱼、拉面、包子建议食品餐饮。午餐、晚餐只在文字明确表达时细分。“居家生活 / 理发”“居家生活 / 美容”分别承接对应服务。金融产品名称不单独作为收益依据，转账、退款与还款属于场景信息。

管理入口位于“我的 → 交易 → 识别规则”。用户可置顶、长按拖动调整顺序、启用、禁用、编辑或删除规则；新建规则默认置顶。规则配置、目标身份、执行顺序及删除状态随用户数据备份保存，删除内置规则后不会因启动或升级重新出现。每次识别或导入审阅读取当前配置和可用目标快照。

识别规则与来源映射分别维护。来源账户先采用有效来源映射，未命中后使用共享账户解析。来源明确提供的分类采用来源分类映射与精准名称或路径匹配；缺失分类使用共享分类解析。分类候选的修正只影响当前导入，不保存为来源映射。导入确认不改变识别规则配置。

## 截图识别录入

用户通过 Android 系统分享发送一张单笔支付或收款结果页、交易详情页截图，或从“我的 → 交易 → 截图记账”选择图片。识别在本地完成，以文字、位置和识别置信度为依据，按“识别场景 → 提取场景信息”通用解释截图，形成待用户确认的识别候选，保留能够提取的金额、时间、交易对方、商品说明与付款或收款方式。

系统分享在应用未启动、前台或后台运行时都可接收。运行中分享进入已有应用的截图识别流程，不另起应用会话；尚未完成的系统选图按取消处理。

选图过程中收到新分享时，以分享图片进入新的截图识别流程。旧选图的取消或迟到结果不会退出新页面、覆盖新图片；离开当前截图页面后，旧识别结果也不再改变当前流程。

截图统一使用通用解释，不识别外部产品来源，也不按来源选择解析规则。场景按普通收入、普通支出、转账、退款、还款等业务大类判断，再提取对应信息；不能确定的场景或字段保留为待核对信息。红包或他人转入明确已收款、已到账且金额方向一致时按普通收入处理，转账时间、说明或单号不改变收款场景；仅出现转账名称或未确认收款时不推断收入。支付失败或取消保持未成功场景；退款、还款和缺乏明确自有资金账户线索的转账保持各自场景，通过相应手动操作完成记账。

实际交易金额以截图中的显著收支金额或明确的实付、实收、扣款、到账、转出金额为依据，成功状态可与金额同行；金额没有正负号时结合明确的收付款状态或交易成功后的付款方式判断方向。原价、订单金额、优惠与账户余额不能代替实际交易金额。普通收支在场景、方向和实际金额明确时预填对应录入页；自有资金转出到银行卡在处理中或已到账时均可预填转账页，保留实际转出金额、时间和两侧账户线索。转出标题可提供来源资金账户与到账银行卡；仅有转出金额和到账银行卡时，来源账户留空。金额缺失、金额存在歧义或普通收支方向未知时提示手动处理。收款同时展示转账时间与收款时间时采用收款时间，资金转出采用实际转出时间；预计到账时间不作为交易时间，时间缺失时采用当前时间，不额外提示。

账户解析由截图记账与来源导入共用，按“标准化后的完整名称 → 用户账户关键词规则 → 常见银行与支付方式别名”依次查找已有目标。每阶段命中后停止，多个名称或别名命中时按账户列表顺序取第一个；名称匹配不推断尾号或卡类型，不使用模糊匹配。零钱通与零钱、余额宝与支付宝余额属于不同支付方式，完整产品名称优先于较短的平台或余额别名。自有资金转账分别用可靠的转出、转入账户文字在可用资金账户中匹配，两侧不借用对方线索；银行卡尾号可参与用户明确配置的关键词规则。

分类解析由截图记账与来源分类缺失的账单导入共用，按“分类关键词规则 → 同方向预置其他”依次建议。“其他”不存在时保持缺失，由用户选择。普通收支关键词规则优先使用可靠的分类名、商户与商品说明；账户规则优先使用可靠的付款或收款方式，全文只在对应语义区域缺失或不可靠时参与关键词匹配。交易对方只关联已有的同名对象，商品说明与未关联的交易对方保留在可编辑备注中。自有资金转账不推断收支分类或交易对方。

识别结果进入现有交易录入页，用户可以修正金额、时间、账户、分类、交易对方和备注，确认保存后才形成账务事实。账户解析未命中时保持空缺，由用户选择；普通收支与自有资金转账预填不额外显示识别完成、缺失字段或低置信度提示。用户补选分类时保留当前账户，不使用分类历史自动补填账户。已有同方向、同金额、同一秒交易时间的普通交易会显示简短的可能重复提示，提示不阻止用户确认，也不作为自动去重依据。

识别候选只存在于当前录入流程，不建立导入批次或来源映射。图片只作为当前识别输入，不成为交易附件或账务持久化数据。

其它录入能力的功能规划见[核心功能](../../02.%20核心功能.md)。

## 与账务核心的协作

录入能力拥有来源解释和录入流程，账务核心拥有账务事实与过账校验。录入能力在确认或授权执行后调用账务核心创建交易，撤销导入时调用账务核心删除对应交易组。

录入结果和账务写入处于同一用例事务中：任一账务创建、来源映射或批次写入失败时整体回滚。录入域不复制账户角色、分录平衡和余额计算规则。
