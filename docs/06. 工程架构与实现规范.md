# 工程架构与实现规范

本文档是 SmartFlow Flutter 工程治理入口，汇总目录组织、分层边界、页面动态渲染、业务行为分发、MVVM、测试与演进规则。详细规则拆分到 `docs/engineering/`。

业务模型见 `docs/domains/`，视觉规范见 [05. 设计系统](05.%20设计系统.md)，业务域划分与依赖边界的决策依据见 [ADR-0001](adr/0001-业务域划分与账务核心独立性.md)。

## 总体分层

SmartFlow 采用**顶层分层 + 层内按业务域组织**：

- `application/`：用例编排层，负责用户操作、事务边界、跨领域协调、查询投影。
- `domain/`：领域层，负责领域模型、领域服务、领域不变量与 ports。
- `infrastructure/`：基础设施实现层，负责 Drift / SQL / mapper / repository 实现 / RPC 等技术细节。
- `feature/`：UI 页面与用户工作流，不按 DDD 业务域强行归属。
- `design_system/`：项目级设计系统。
- `widget/business/`：跨 feature 复用的业务组件，可按视觉语义分组，例如 `finance/`、`transaction/`。
- `feature/shared/presentation/`：跨 feature 复用的页面展示适配与查询辅助，例如账户索引和交易列表 presentation builder。

写侧依赖方向：

```text
feature / widget / app
        ↓
application/<域或用例组>
        ↓
domain/<域>
        ↑
infrastructure/<域>  实现 domain ports
```

纯读侧可以绕过 domain：

```text
feature / widget / app
        ↓
application/<域>/<capability>/query
        ↓
infrastructure/<域> query implementation
        ↓
database
```

## 核心约束

- `domain/` 不依赖 Flutter、Riverpod、Drift、`application/`、`infrastructure/`、`feature/`、`app/`。
- `application/` 可以编排一个或多个 `domain/`，并拥有用例事务边界。
- `infrastructure/` 实现 domain ports 和 application query interfaces，不承载业务决策。
- `feature/` 通过 Riverpod provider 使用 application 用例和查询，不直接 new DAO / repository 实现。
- feature 层采用 MVVM，但不新增 `model/` 目录；MVVM 中的 Model 指既有 application / domain / read model 体系。
- 复杂页面优先建立页面级 ViewModel 和不可变 view state；已有页面按触达式迁移。
- 路由只提供页面身份和初始化信号；页面动态渲染与业务行为分发由页面级 ViewModel 控制。
